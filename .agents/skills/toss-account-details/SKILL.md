# 토스 개인계좌 상세 확인

사용자의 수동 요청으로 주문·체결 요약과 실제 배당 입금 상세를 확인한다.
스케줄·연결 감지·백그라운드 작업은 만들지 않는다. 기존 정본·채택값·과거 비교 종료
방침을 유지한다. 확인된 새 자료는 기존 비공개 R2와 장부 증분에 연결하되 기존 채택값을 바꾸지 않는다.

호출 예: `$toss-account-details 오늘 주문·체결과 실제 배당 입금 상세를 확인해줘`.
배당 기본 호출 예: `$toss-account-details 오늘 포함 최근 14일 배당 상세를 확인해줘`.

기본 호출은 수집부터 비공개 저장·장부 연결·재조회 검증까지 수행한다. 호출 예:
`$toss-account-details 오늘 주문과 실제 배당을 확인하고 비공개 R2에 저장한 뒤 장부에 연결해줘`.
이미 승인된 기존 private 저장소 범위에서 [저장·연결 계약](references/publication.md)을
반드시 이어서 수행한다. 사용자가 명시적으로 외부 저장을 금지한 호출은 그 제한을 우선한다.
조회·로컬 파일 생성만으로 전체 완료라고 보고하지 않는다. 새 자격증명 설정 권한을 뜻하지 않는다.

## 요청 범위

대상 계좌, 기간과 확인할 항목을 기존 대화에서 먼저 확인한다. 이미 지정된 범위는
재질문하지 않는다. 누락된 범위만 확인하며 과거 전체 수집을 기본값으로 삼지 않는다.
배당 기간을 별도로 지정하지 않으면 **Asia/Seoul 기준 오늘-13일~오늘(양끝 포함 14일)**을
사용한다. 주문 API의 `orderedAt` 날짜 범위와 배당 상세 탐색 기간은 별개로 기록한다.
API 주문 확인은 [API 범위와 실행](references/api.md), 실제 배당 입금 등 화면 상세는
[ego light 흐름](references/ego.md)을 해당 작업 전에 읽는다.

## API로 주문 확인

저장소의 [수동 읽기 명령](../../../scripts/toss/read-account-orders.mjs)을 사용한다.
이 명령은 기존 collector를 재사용하고 호출마다 새 run을 만든다. 완료된 collector
run의 재사용은 API를 다시 호출하지 않으므로 최신 조회로 보고하지 않는다.

기존 로컬 설정 파일을 경로로 참조한다. 키·토큰을 명령 인수에 넣거나 다른 PC/클라우드로
복사하지 않는다. 기존 토큰을 우선 사용하며, 필요한 OAuth 발급이 요청 범위에서
허용된 경우에만 `--issue-token`을 사용한다. 인증 실패를 자동 재발급으로 우회하지 않는다.

## ego light로 개인 입금 상세 확인

모든 브라우저 작업 전에 설치된 환경에서 `ego-browser skill`을 실행하고 현재 가이드를
끝까지 확인한다. 기본 흐름은 **ego light를 열어 제어하고 토스증권 공식 사이트로 이동**하는 것이다.
접근 가능한 기존 토스 탭이 있으면 재사용하고, 없으면 현재 가이드의 `taskSpace()`로 이 요청의
작업 공간 하나를 만들고 기본 `p1`에서 `https://www.tossinvest.com/`을 연다. 작업 공간 목록이
0개라는 이유만으로 사용자에게 탭 공유를 요구하지 않는다. 자세한 재사용·중단 규칙은
[ego light 흐름](references/ego.md)을 따른다. 다른 브라우저·새 Playwright·원격 디버깅 설정으로
대체하지 않는다. 실제 실행·연결 실패는 정확한 blocked 상태로 보고한다. 로그인/OTP나 사용자의 제어가
필요하면 가이드의 보안 handoff로 넘기고 사용자 확인 뒤 같은 공간에서 재개한다.

대상 계좌를 확인한 뒤 **내 계좌 → 예상 배당금 → 현재 월 → 오늘 이하 가장 가까운 날짜**를
선택한다. [14일 상세 탐색](references/ego.md#최근-14일-상세-탐색)에 따라 기간 내 날짜를
역순으로 열고 각 날짜의 **종목을 하나씩 선택한 뒤 오른쪽 상세 패널 전체**를 확인한다.
[패널 필수 확인표](references/ego.md#오른쪽-상세-패널-필수-확인)를 적용하고 선택 종목과
패널 제목·지급일이 일치하기 전에는 상세 완료로 보고하지 않는다. 월 경계는 이전 달까지 이어간다.
`예상 배당금`이라는 메뉴 이름만으로 모든 상세를 예상값으로 분류하지 않는다. 패널의
지급 상태와 표시 금액을 근거로 판정하며, 세금·세후 금액을 못 읽은 상태를 필드 부재로 단정하지 않는다.
일반 `거래내역` 메뉴로 임의 우회하지 않는다. 실제 입금 시각이 필요하면 패널의
`입금 내역 보기`를 별도 연결 근거로 구분한다. 공개 공시·예정 배당은
개인 입금의 대체 근거가 아니다. 페이지 끝 여부와 상세 범위를 확인하지 못하면
부분 확인으로 남긴다. 쿠키 추출·세션 복사·금융 화면 공개 첨부는 하지 않는다.

## 결과 판정

API와 브라우저의 성공·실패·미실행을 각각 보고한다. 0건, 미지원, 실패, 부분 조회,
응답 종료를 구분하고 한쪽 성공으로 전체 확인 완료라고 하지 않는다.
주문 ID·배당 고유 ID와 출처를 유지해 목록/상세·반복 관측을 중복 합산하지 않는다.
원화/달러, 세전/세금/실수령, 주문 생성/실제 체결/지급 시각을 구별한다. 모르는 값은
null로 남기고 누락 수수료·환율·초 단위 시각을 추정하지 않는다.

조회 시각, 대상 계좌의 마스킹 표시, 요청·실제 확보 기간, 확인 건수와 미확인 영역만
간결히 보고한다. 키·토큰·쿠키·전체 계좌번호는 채팅/로그/Git에 남기지 않는다.
원문은 Git 제외 로컬 폴더에 먼저 보존하고, 승인된 비공개 R2에 저장한 뒤 장부 증분을 연결한다.
수집/API 성공, R2 GET 검증, index 연결, 인증된 장부 표시를 각각 확인한다. 새 증분은
기존 채택값을 바꾸지 않으며 중복 여부 미확정은 합계에서 제외한다.
전체 완료는 원격 원문/manifest/receipt의 GET·해시 검증, append-only index 연결과
실제 서버 투영 또는 인증된 장부 화면에서 정확히 한 번 반영된 확인까지 충족해야 한다.
어느 단계든 실패하면 `partial`/`blocked`와 마지막 안전 checkpoint를 남기고 저장된 run에서
재개한다. 인증·도구 부족 때문에 금융 원문을 로그로 옮기거나 새 키를 만들지 않는다.
실제 확보하지 못한 자료나 예상·미확인 값을 확정 내역으로 꾸며 저장하지 않는다.
주문·취소·매매·환전·이체·push·배포는 이 스킬의 수집·저장 요청에 포함되지 않는다.
