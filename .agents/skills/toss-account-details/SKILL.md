# 토스 개인계좌 상세 확인

사용자의 수동 요청으로 주문·체결 요약과 실제 배당 입금 상세를 확인한다.
스케줄·연결 감지·백그라운드 작업은 만들지 않는다. 기존 정본·채택값·과거 비교 종료
방침을 유지하고 새 관측을 기존 장부에 자동 반영하지 않는다.

호출 예: `$toss-account-details 오늘 주문·체결과 실제 배당 입금 상세를 확인해줘`.

## 요청 범위

대상 계좌, 기간과 확인할 항목을 기존 대화에서 먼저 확인한다. 이미 지정된 범위는
재질문하지 않는다. 누락된 범위만 확인하며 과거 전체 수집을 기본값으로 삼지 않는다.
API 주문 확인은 [API 범위와 실행](references/api.md), 실제 배당 입금 등 화면 상세는
[ego light 흐름](references/ego.md)을 해당 작업 전에 읽는다.

## API로 주문 확인

저장소의 [수동 읽기 명령](../../../scripts/toss/read-account-orders.mjs)을 사용한다.
이 명령은 기존 collector를 재사용하고 호출마다 새 run을 만든다. 완료된 collector
run의 재사용은 API를 다시 호출하지 않으므로 최신 조회로 보고하지 않는다.

기존 로컬 설정 파일을 경로로 참조한다. 키·토큰을 명령 인수에 넣거나 다른 PC/클라우드로
복사하지 않는다. 기존 토큰을 우선 사용하며, 필요한 OAuth 발급이 요청 범위에서
허용된 경우에만 `--issue-token`을 사용한다. 인증 실패를 자동 재발급으로 우회하지 않는다.

## ego light로 개인 입금 상세 확인

모든 브라우저 작업 전에 설치된 환경에서 `ego-browser skill`을 실행하고 현재 가이드를
끝까지 확인한다. **이미 토스증권이 열린 ego light 세션**만 사용한다. 관측한 작업 공간과
탭을 재사용하며 다른 브라우저·새 Playwright·원격 디버깅 설정으로 대체하지 않는다.
세션·탭을 찾지 못하면 정확한 blocked 상태를 보고한다. 로그인/OTP나 사용자의 제어가
필요하면 가이드의 보안 handoff로 넘기고 사용자 확인 뒤 같은 공간에서 재개한다.

대상 계좌를 확인한 뒤 실제 배당 입금 목록과 상세를 읽는다. 공개 공시·예정 배당은
개인 입금의 대체 근거가 아니다. 페이지 끝 여부와 상세 범위를 확인하지 못하면
부분 확인으로 남긴다. 쿠키 추출·세션 복사·금융 화면 공개 첨부는 하지 않는다.

## 결과 판정

API와 브라우저의 성공·실패·미실행을 각각 보고한다. 0건, 미지원, 실패, 부분 조회,
응답 종료를 구분하고 한쪽 성공으로 전체 확인 완료라고 하지 않는다.
주문 ID·배당 고유 ID와 출처를 유지해 목록/상세·반복 관측을 중복 합산하지 않는다.
원화/달러, 세전/세금/실수령, 주문 생성/실제 체결/지급 시각을 구별한다. 모르는 값은
null로 남기고 누락 수수료·환율·초 단위 시각을 추정하지 않는다.

조회 시각, 대상 계좌의 마스킹 표시, 요청·실제 확보 기간, 확인 건수와 미확인 영역만
간결히 보고한다. 키·토큰·쿠키·전체 계좌번호는 채팅/로그/Git에 남기지 않는다.
원문은 Git 제외 로컬 폴더에만 보존한다. 주문·취소·매매·환전·이체·업로드·push·배포는
이 스킬의 읽기 요청에 포함되지 않는다.
