# ego light 실행과 개인 배당 입금 상세

## 현재 도구 계약 확인

1. 설치된 환경에서 `ego-browser skill`을 실행한다. 끝의
   `[ego-browser:skill] end of guide`까지 확인한다. 출력이 잘렸으면 임시 파일로 저장해
   나누어 읽는다. 업데이트했거나 도구가 요구하면 다시 읽는다.
2. 이 가이드에 나온 현재 명령·메서드만 사용한다. 저장소에 고정 tab ID, selector,
   task-space ID나 Playwright 명령을 박아 넣지 않는다.
3. 실행 파일이 없으면 현재 경로/설치 여부만 확인해 blocked로 보고한다. 무단 설치,
   다른 브라우저 대체, 쿠키 복사, 원격 디버깅 활성화는 하지 않는다.

기본 샌드박스의 bootstrap 연결 오류는 가이드가 지원하는 정상 승인 경로가 있을 때만
그 범위에서 재확인한다. 거절·제어 상실·권한 오류를 다른 경로로 우회하지 않는다.

## 기본 실행과 대상 선택

스킬 호출은 ego light를 열고 토스증권 공식 사이트로 이동하는 흐름을 포함한다.
현재 가이드의 `listTaskSpaces()`로 접근 가능한 공간을 확인하고 기존 토스 탭이 있으면
권한 범위 안에서 재사용한다. 사용자 소유 공간의 claim은 명시적인 사용자 요청이 있을 때만
한다. 관련 없는 개인/업무 탭은 열거나 제어하지 않는다.

재사용할 토스 탭이 없으면 `taskSpace()`로 이 요청의 작업 공간 하나를 생성한다.
이는 기존 ego light의 기본 프로필을 사용하며 별도 프로필 생성·선택이나 로그인 세션 복사를
하지 않는다. 기본 페이지 `p1`에서 `https://www.tossinvest.com/`으로 이동한다.
목록이 0개인 것은 생성 전 정상 상태일 수 있으므로 탭 공유를 필수 조건으로 삼지 않는다.
현재 설치 가이드가 다음 API를 제공하는지 확인한 뒤 실행한다.

```js
// 최초 실행 전 기존 공간을 확인한다. goalName은 이번 요청의 고유 이름이다.
const goalName = `toss-account-details-${Date.now()}`;
const task = await taskSpace(goalName);
console.log({ taskSpaceId: task.spaceId, page: "p1" });
await task.page("p1").goto("https://www.tossinvest.com/");
```

다음 라운드는 반환된 공간 ID와 페이지 label을 사용한다. 요청 하나당 공간 하나만 사용하고,
이미 진행 중인 공간에서 연결 실패·사용자 제어·시간 초과가 발생했을 때 새 공간을 만들어
우회하지 않는다. ego 실행·연결 자체가 실패하면 정확한 오류를 보고하며 무단 설치나
다른 브라우저로 대체하지 않는다. 공간·탭 부재만으로 로그아웃이라고 단정하지 않는다.

관측한 탭과 현재 화면의 의미 기반 요소를 사용한다. 접근할 때마다 로그인·계좌·기간을
확인한다. 새 로그인/OTP·기기 승인·브라우저 권한 또는 사용자 제어가 필요하면 가이드의
handoff 경로를 안내하고 사용자 완료 후 같은 공간에서 재개한다. 계좌가 바뀌면 중단한다.
이미 승인·확인된 계좌와 요청 범위를 반복 확인받을 필요는 없다.

## 최근 14일 상세 탐색

기본 경로는 **토스증권 사이트 → 내 계좌 → 예상 배당금 → 현재 월 → 오늘 이하 가장
가까운 표시 날짜 → 배당 상세**다. 계좌 일치를 먼저 확인하고 관측한 UI 요소로 이동한다.
실제 UI를 보기 전에 경로·버튼·페이지 수·계좌 정보를 추측하지 않는다.
기간이 별도 지정되지 않았으면 한국 날짜 `today`를 고정하고 `today-13일`부터 `today`까지
양끝을 포함한다. 예를 들어 2026-10-30이면 **2026-10-17~2026-10-30**이다.
시작·종료일은 배당 상세 탐색 범위이며 API 주문 생성일 필터를 이 값으로 임의 변경하지 않는다.

1. 현재 월의 표시 날짜를 읽고 `start <= date <= today`인 날짜만 고른다. 미래 예정 날짜는
   제외한다. 페이지의 선택 연도·월을 확인해 날짜를 구성하며 연도를 추측하지 않는다.
2. 오늘 이하 가장 가까운 날짜부터 역순으로 클릭한다. 같은 날짜의 모든 종목·지급 항목을
   확인하고 각 항목의 상세를 연다. 한 종목을 읽고 그 날짜를 완료로 표시하지 않는다.
3. 목록과 상세의 더 보기·스크롤·페이지 이동을 확인한다. 가상 목록이면 필요한 구간을
   읽고 끝 또는 범위 밖 경계를 확인한다. 원래 날짜 목록으로 돌아와 다음 과거 날짜로 이동한다.
4. 시작일이 이전 달이면 이전 달로 이동해 같은 방식으로 이어간다. 1월이면 이전 연도
   12월까지 포함한다. 기간 밖 전체 과거를 추가 수집하지 않는다.
5. 요청 범위, 실제 읽은 날짜·종목·상세, 원문 ID(없으면 null), 표시 상태, 페이지 범위와
   실패/미확인 항목을 Git 제외 로컬 근거에 남긴다. 목록만 스캔한 날짜와 상세까지 확인한
   날짜를 구분한다. 같은 목록/상세를 두 지급으로 중복 집계하지 않는다.

`success`는 범위 내 날짜와 그 안의 모든 표시 항목·상세를 확인하고 목록 범위 끝을 확인했을
때만 사용한다. 생략된 상세나 확인하지 못한 페이지는 `partial`, 로그인은 `login_required`,
접근 실패는 `blocked`다. 범위 전체의 빈 목록을 확인한 경우만 0건으로 보고한다.

### 날짜 계산 예시

브라우저의 현지 시간 설정과 무관하게 한국 날짜를 계산한다. 아래 코드는 달력 계산만 하며
브라우저 또는 금융 API를 호출하지 않는다.

```js
const parts = Object.fromEntries(new Intl.DateTimeFormat('en-US', {
  timeZone: 'Asia/Seoul', year: 'numeric', month: '2-digit', day: '2-digit',
}).formatToParts(new Date()).filter(p => p.type !== 'literal').map(p => [p.type, p.value]));
const today = `${parts.year}-${parts.month}-${parts.day}`;
const startDate = new Date(`${today}T00:00:00Z`);
startDate.setUTCDate(startDate.getUTCDate() - 13);
const start = startDate.toISOString().slice(0, 10);
// UI에서 연도·월을 확인해 만든 ISO 날짜를 start <= date && date <= today로 필터하고 역순 정렬한다.
```

### 검증 체크리스트

| 사례 | 기대 동작 |
| --- | --- |
| 2026-10-30 | 10/17~10/30, 양끝 포함 14일 |
| 2026-11-05 | 10/23~11/05, 현재 월 다음 이전 달 확인 |
| 2027-01-05 | 2026-12-23~2027-01-05, 이전 연도 확인 |
| 2028-03-01 | 02/17~03/01, 윤년 02/29 포함 |
| 오늘 10/30, 표시일 10/31·10/30·10/29·10/16 | 10/30→10/29만 확인 |
| 한 날짜에 두 종목, 두 번째 상세 실패 | 두 항목을 추적하고 날짜/전체 상태 partial |
| 예상/지급예정 금액만 있음 | 실제 입금 미확인, 확정 원장·합계로 승격하지 않음 |
| 지급 완료 표시가 있지만 세금 필드 없음 | 표시 상태와 근거만 보존, 세금 null |

## 실제 입금 증거 확인

날짜가 과거여도 지급 사실을 자동 확정하지 않는다. 화면에서 실제 입금·지급 완료와
개인 계좌의 상세 근거가 확인되는 항목만 확정 입금 관측으로 분류한다. 예상/지급예정은
별도 상태로 보존하고 [저장 계약](publication.md)의 확정 입금 입력으로 전달하지 않는다.
공개 종목의 배당 공시, 예상 배당, 권리 발생, 보유수량 계산은 개인 입금이 아니다.

가능한 필드만 확인하고 각 필드가 실제로 보였는지 구분한다.

- 원문 거래/지급 ID와 계좌, 종목, 실제 입금일·시각 및 표시 정밀도
- 통화별 세전액, 원천징수/세금, 실수령액; 없는 값은 null
- 확정 입금·예정·취소·정정·환수의 상태 및 관련 원문 ID
- 목록 기간, 필터, 더 보기/cursor/페이지네이션과 끝까지 읽었는지 여부

안정적인 고유 ID를 확인하지 못하면 목록 위치·같은 날짜/금액만으로 서로 다른 입금을
합치지 않는다. 목록과 상세를 별도 입금으로 중복 합산하지 않는다. 부분 페이지만 확인한
결과를 전체 기간 완료나 0건으로 보고하지 않는다. 통화 환산·누락 세금·초 단위 시각을 추정하지 않는다.

읽기 동작만 수행한다. 매수·매도·주문 정정/취소·환전·출금·송금 버튼은 누르지 않는다.
DOM/스냅샷 출력 전 전체 계좌번호·비밀값을 제외하고 요청과 무관한 개인 정보를 읽지 않는다.
쿠키·토큰·브라우저 저장소·네트워크 인증 헤더를 추출하지 않는다. 금융 화면 스크린샷은
공개 첨부하지 않는다. 필요한 원문은 허용된 Git 제외 로컬 폴더에만 보존한다.

마지막에는 확인한 입금 건수·기간·필드·페이지 범위와 미확인 항목을 보고한다.
API 성공 여부와 독립적으로 browser success/partial/blocked/login_required를 기록한다.
