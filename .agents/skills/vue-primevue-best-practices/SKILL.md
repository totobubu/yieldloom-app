# Vue + PrimeVue 프로젝트 공용 스킬

## 적용 순서

1. 루트 `AGENTS.md`와 `README.md`, 변경 대상 및 직접 연결되는 코드를 읽는다.
2. `package.json`·`package-lock.json`에서 현재 버전을 확인한다. 작성 시점 기준
   Vue 3.5, PrimeVue 4, Vite 7, Vue Router 4이며 JS와 TS가 공존한다.
3. 조회를 추가하거나 호출 시점을 바꾸는 작업은 루트 `AGENTS.md`의
   「API·데이터 조회 중복 방지」를 구현 전에 적용한다. 아래 기준 중 관련 항목을
   적용하고 작업 크기에 맞춰 검증한다.
4. 리뷰에서는 실제 결함·회귀를 우선하고, 취향이나 파일 크기만으로 추출을 요구하지 않는다.

프로젝트 패턴과 검증 대상 예시는 [references/project-patterns.md](references/project-patterns.md)를 참고한다.
문서의 저장소 경로는 저장소 루트를 기준으로 한다.

## Low-level composition

작고 명확한 기능 단위를 조합해 기능을 구성한다. 줄 수나 파일 수를 목표로 삼지 않는다.

| 계층             | 책임                                     | 배치 기준                                              |
| ---------------- | ---------------------------------------- | ------------------------------------------------------ |
| 순수 함수·서비스 | 계산, 정규화, 검증, 데이터 접근          | 기존 `src/services/`, `src/utils/`, `lib/` 경계를 확인 |
| Composable       | Vue 반응성과 수명주기가 필요한 상태·동작 | `src/composables/` 아래 기능에 맞춰 배치               |
| UI 컴포넌트      | 표현, 입력, 이벤트, slot 조합            | `src/components/`의 기존 기능별 디렉터리               |
| 페이지·레이아웃  | 라우트 입력, 기능 연결, 화면 단위 흐름   | `src/pages/`, `src/layouts/`                           |

- 순수 계산을 `useXxx`로 감싸지 않는다. 독립적인 책임, 재사용 또는 검증상 이점이
  있는 경우에 추출하고, 밀접한 상태와 동작은 함께 둔다.
- Composable은 `useXxx`로 이름 짓고 입력·반환값·부수 효과를 명확히 한다.
  내부에서 라우터, DOM, 인증 상태를 암묵적으로 찾기보다 필요한 의존성을 받는다.
  라우팅 전용 composable처럼 직접 의존하는 편이 자연스러우면 그 계약을 명시한다.
- 상태는 가장 가까운 공통 소유자에 둔다. 모듈 전역 상태는 테마처럼 의도적으로
  앱 전체에서 공유할 때만 사용하고 공유 범위를 드러낸다.
- 반환은 일반 객체에 refs·computed·동작을 담는 방식을 우선한다. 외부 변경이
  불필요한 상태는 readonly로 노출하고, 모든 composable에 획일적인 반환 구조를 강제하지 않는다.
- UI는 props로 받고 emits로 변경 의도를 전달한다. props나 그 중첩 데이터를
  암묵적으로 수정하지 않는다. `v-model`은 부모와 합의한 변경 계약으로 사용한다.
- 콘텐츠 차이는 slots로 조합한다. 거대한 설정 객체나 불리언 prop 조합으로
  서로 다른 모든 화면을 표현하는 범용 컴포넌트는 피한다.
- 파일 하나나 PrimeVue API를 그대로 전달하는 래퍼는 만들지 않는다. 반복되는
  제품 규칙·접근성·레이아웃 계약을 캡슐화할 때 공용 컴포넌트를 만든다.
- 기존 JS를 일괄 TS로 전환하거나 새 상태 관리·폼 라이브러리를 기본 도입하지 않는다.
  새 코드의 타입은 인접 코드와 공개 계약에 맞춰 선택한다.

## Vue 반응성과 수명주기

- SFC는 기존 `<script setup>` 패턴을 따른다. 템플릿에서 사용할 Vue API는
  명시적으로 import한다. 현재 Vite 설정은 컴포넌트 자동 import만 구성한다.
- 파생 값은 `computed`, 부수 효과는 `watch`·`watchEffect`로 표현한다.
  computed getter에서 네트워크 요청이나 상태 변경을 수행하지 않는다.
- `reactive` 객체를 일반 구조 분해해 반응성을 잃지 않는다. `toRefs`나 getter를
  사용한다. Vue 3.5의 반응형 props 구조 분해와 일반 객체 구조 분해를 구별한다.
- 반응형 입력을 지원하는 composable은 ref/getter 계약을 명시하고, `toValue`로
  읽을 때는 computed·watchEffect 또는 watch의 getter 안에서 의존성을 추적한다.
- deep watch는 실제 중첩 변경 감지가 필요할 때만 사용한다. props 전체보다
  필요한 필드를 관찰하고, 상태 복사와 양방향 watcher 루프를 피한다.
- 이벤트·타이머·observer·구독은 소유한 scope에서 정리한다. Composable은
  `onScopeDispose`, 컴포넌트는 적절한 수명주기 훅을 사용한다.
- 비동기 요청은 변경된 티커·계좌의 이전 응답이 최신 상태를 덮어쓰지 않도록
  취소 또는 요청 식별자로 보호한다. 취소 시 최신 요청의 loading 상태도 보호한다.
- `onWatcherCleanup`을 쓰면 첫 await 전에 등록한다. 클라이언트 API는 실행
  환경을 확인하고 필요 시 mount 이후에 접근한다.

## PrimeVue 4와 스타일

- UI 개발·퍼블리싱·테마·컴포넌트 재사용 작업에는
  [primevue4-ui](../primevue4-ui/SKILL.md)를 함께 적용한다.
  공식 문서는 https://v4.primevue.org/ 를 기준으로 하고 PrimeVue 5 전용 API는 도입하지 않는다.
- 설치 버전의 props·events·slots·Pass Through 타입을 확인한다. PrimeVue 3
  예제나 존재하지 않는 PT section 이름을 추측해 적용하지 않는다.
- `src/main.js`의 PrimeVue, ToastService, ConfirmationService, Tooltip 설정과
  `vite.config.js`의 `PrimeVueResolver`를 재사용한다. 중복 전역 등록을 피한다.
- DataTable 셀은 column slots, Dialog 콘텐츠는 작은 컴포넌트와 slots로
  구성한다. 서버 페이지네이션을 쓰면 정렬·필터·전체 행 수의 기준도 서버와 맞춘다.
- 우선순위는 공개 props·slots → 디자인 토큰 → 공개 Pass Through → 제한된
  스타일 보정이다. 토큰은 `src/config/theme.js`와 기존 SCSS·CSS 변수를 확인한다.
- 내부 DOM 선택자나 깊은 `:deep()`·`!important`에 의존하는 변경은 최소화하고,
  불가피할 때 적용 범위와 버전 의존 이유를 남긴다.
- 앱의 다크 모드 선택자는 `.p-dark`다. `useLayout.ts`의 테마 설정 흐름과
  라이트·다크 대비를 확인한다. PNG 출력용 카드의 별도 스타일은 제품 목적을 확인한다.
- `components.d.ts`는 컴포넌트 자동 import의 생성 결과이므로 수동으로 API를 추가하지 않는다.

### 개인 장부 데이터 계약

장부의 정본·이행 기준은 [장부 정책](../../../docs/SHEET_TRIAL_LEDGER.md#정본과-이행-방향)을
따른다. 토스 원문/파싱/정규화 사건/후보/관리자 확정과 시트 참고값을 UI 계약에서 구분하고,
시트 행 구조에 맞춰 별도 주문을 병합하거나 토스 값으로 승인값을 자동 덮어쓰지 않는다.
실제 데이터 전환이 없는 분석·후보 표시를 운영 장부 전환 완료로 표현하지 않는다.

## 데이터·폼·접근성

- loading, error, empty, success를 구분한다. 실패를 빈 결과나 금액 0으로
  숨기지 않고 재시도·확인이 가능한 UI를 제공한다.
- 금액·통화·기준일·환율·확정/추정의 의미는 기존 서비스 계약을 유지한다.
  화면에서 별도 계산식을 복제하거나 결측값의 의미를 임의로 바꾸지 않는다.
- 폼은 field label, inputId 연결, 오류 설명, 제출 중 상태를 제공한다.
  Enter 제출과 중복 클릭을 처리하고 서버 검증 오류를 사용자에게 전달한다.
- 아이콘 버튼에 접근 가능한 이름을 제공한다. Dialog는 키보드 조작, 포커스
  진입·복귀, 닫기 동작을 확인한다. PrimeVue의 기본 접근성 속성을 덮어쓰지 않는다.
- 색상만으로 손익·오류·상태를 구별하지 않고 텍스트나 다른 식별 수단을 제공한다.
- URL의 티커·필터 입력은 검증하고, 개인 포트폴리오·인증 정보는 URL이나 로그에 넣지 않는다.

## 성능

- API 호출을 추가하기 전에 mount·watch·탭 재진입·공유 컴포넌트에서 같은 자료를
  조회하는지 확인하고, 기존 공용 조회 서비스를 우선 사용한다. 가족 원장 조회는
  `src/services/familyPortfolio.js`의 `familyRequest`·`loadFamilyLedger`를 확인한다.
- 진행 중 요청 합치기와 버전 기반 재사용을 적용할 때 로그인 세션·권한·조회 조건을
  분리하고, 취소·저장·로그아웃 시 무효화도 함께 구현한다. 캐시로 권한 검증을 생략하지 않는다.
- 조회 변경은 최초/재진입/동시 조회의 API 요청 수와 서버 문서 읽기를 구분해 검증한다.
  기존 원장 경합·재사용 테스트는 `tests/portfolio_ledger_client.test.mjs`,
  로컬 API 통합 검증은 `tests/portfolio-ledger.integration.mjs`를 참고한다.
- 렌더링 중 반복되는 큰 계산·필터는 computed나 서비스로 이동하고 데이터 크기를 확인한다.
- `v-for`에는 안정적인 고유 key를 사용한다. 목록의 identity를 배열 index로 대신하지 않는다.
- 대량 목록은 데이터 규모에 따라 페이지네이션·가상화를 검토한다. 실제 필요 없이 도입하지 않는다.
- 큰 불변 데이터는 필요할 때 shallowRef 등을 검토하되 중첩 변경 계약을 함께 확인한다.
- PDF·이미지 등 무거운 기능의 지연 로딩은 기존 코드와 번들 영향을 확인해 판단한다.

## 변경별 검증

| 변경                              | 기본 검증                                              |
| --------------------------------- | ------------------------------------------------------ |
| 문서·스킬만                       | 상대 경로·명령·예시 확인, `git diff --check`           |
| Vue·TS·프런트엔드 JS              | `npm run type-check`; 관련 동작 확인                   |
| 계산·서비스                       | 관련 `node --test tests/<관련파일>.test.mjs` 실행      |
| 컴포넌트·스타일·폼                | 브라우저에서 관련 화면·입력·오류·키보드·모바일 폭 확인 |
| 테마                              | 관련 화면 라이트·다크 및 새로고침 후 설정 유지 확인    |
| 카드 출력                         | 관련 카드 미리보기와 PNG의 글꼴·크기·잘림 확인         |
| 빌드 설정·의존성·라우팅·통합 변경 | `npm run build`; 관련 직접 접속·새로고침 확인          |

- 공통 서비스 변경은 필요에 따라 `node --test tests/*.test.mjs`로 범위를 넓힌다.
- 현재 `package.json`에 `test` 스크립트는 없다. 검증 명령을 추측하지 않는다.
- `npm run lint`, `lint:eslint`, `lint:oxlint`, `format`은 파일을 수정한다.
  스타일 검사만 필요하면 `npx --no-install prettier --check <변경파일>`처럼 범위를 지정한다.
- 새 테스트는 계산 경계, 응답 경합, 입력 검증 등 의미 있는 동작을 검증할 때 추가한다.
  단순 텍스트·스타일 변경이나 구현을 그대로 복제하는 테스트는 만들지 않는다.
- 실행 환경이나 외부 데이터가 없으면 검증하지 못한 범위를 보고하고 통과했다고 쓰지 않는다.
  목 응답으로 확인한 동작과 실제 데이터·인증 연동 검증을 구분한다.

## 유지보수

팀 공통 기준 변경은 이 스킬과 필요한 참조 문서를 같은 변경에서 수정한다.
적용 시점이 달라지면 루트 `AGENTS.md`도 갱신한다. 버전·경로·명령은 실제 저장소를
기준으로 유지하고, 예시 코드를 모든 면에서 따라야 할 표준으로 취급하지 않는다.
