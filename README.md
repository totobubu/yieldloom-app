# 토또부부 배당 썸네일 스튜디오

종목별 배당 콘텐츠 카드 제작에 집중한 Vue 앱입니다.

## 화면

- `/`: 티커·종목명·운용사 검색 및 종목 선택.
- `/login`: 일반 사용자의 직접 접근을 홈으로 돌려보냅니다. 관리자는 공개 UI에 노출되지 않는 `/admin/login`에서 로그인하며, 허용 목록에 없는 계정은 즉시 로그아웃됩니다.
- `/mypage`: 인증된 관리자만 접근하는 전체 계좌 포트폴리오입니다. 한눈에 보기는 `view=summary|holdings|capital`로 요약·보유 종목·원금/자금 서브탭을 직접 열 수 있습니다.
- `/mypage?tab=calendar`: 권한 있는 계좌의 월간 배당 캘린더·연간 타임라인. 공시/잔고 기준 세전 예상과 저장된 배당 거래를 구분합니다.
- `/mypage?tab=insights`: 배당 투자 설계실(배당 효과·FIRE·회수/재투자·안정성·성향 모의고사·블로그 5종), 계정 결산 보관·콘텐츠 연결, 기록 품질·청산 손익과 자산 집중도.
- `/simulator`: 관리자 전용 최초 투자·납입·배당·재투자 A/B 및 원천징수율 가정 비교.
- `/mypage/legacy`: 이전 단일 계좌 자료 조회.
- `/stock/:ticker`: 종목 상세·시세·배당 정보와 배당 카드 PNG·게시 패키지 다운로드, 게시 문구 복사. `/thumbnail/:ticker`는 이 경로로 이동합니다.
- `/legal`: 데이터 출처·갱신·투자 면책 및 개인정보 안내.
- `/admin/feedback`: 공개 종목 상세에서 익명으로 접수한 요청·질문을 관리자만 검토하고 처리합니다.
- `?rivals=CRSH,TSII`: 라이벌 선택 공유. 최대 3종.
- 그 외 주소는 `/`로 이동합니다. `VITE_APP_MODE`에 따른 화면 전환은 제거했습니다.

## 인증 화면과 공유 카드

관리자 로그인·재설정 화면은 Stitch 인증 시안의 웹·모바일 배치를 반영합니다. Firebase 재설정 링크(`/admin/login?mode=resetPassword&oobCode=…`)의 검증·만료·재시도·변경 완료를 처리하며 작업 코드는 URL에서 제거하고 메모리에만 보관합니다. 메일에서 이 화면을 열려면 Firebase Console → Authentication → Templates의 비밀번호 재설정 작업 URL을 `https://yieldloom-app.vercel.app/admin/login`으로 설정해야 합니다. 이메일 템플릿 설정을 바꾸지 않으면 기존 Firebase 호스팅 재설정 화면을 이용합니다.

공유정보 탭에서 1:1(720×720), 16:9(1280×720), 9:16(720×1280)과 기본·페이퍼·네이비 디자인을 선택합니다. 선택은 카드 5종의 미리보기·PNG·ZIP manifest·로컬 프리셋에 함께 반영됩니다. 기존 프리셋과 기본 PNG 파일명은 유지하며 앱 다크 모드와 출력 디자인은 독립적입니다. 디자인 원본 63개의 기능별 반영 현황은 [시안 대조표](docs/design/stitch-screen-mapping.json)와 [분석 문서](docs/design/STITCH_FEATURE_GAPS_KO.txt)에 기록합니다.

```sh
# 개발 서버(5173)에서 실행. 인증은 테스트 응답으로 대체하며 실제 메일·계정을 만들지 않습니다.
node tests/auth-flows.browser.mjs
node tests/share-presentation.browser.mjs
```

## 데이터 공급

공개 시세·검색 목록·공시·분류 자료는 `src/services/publicJson.js`에서 URL별 동시 요청을
합치고 제한된 메모리 캐시를 공유합니다. 시세와 릴리스 포인터는 1분, 공시 이력·분류 자료는
최대 3분 재사용하며, 시세·공시의 전용 새로고침 버튼은 캐시를 우회합니다. 계좌 수량·원장·인증
정보는 이 공개 캐시에 넣지 않습니다. 시세 조회는 차트와 포트폴리오 평가가 같은 응답을
공유하고, 거래 CSV는 분석·캘린더와 같은 권한·버전 검증 원장을 사용합니다.

앱과 서버 및 공통 배치 경로의 조회 조사 결과·유지한 호출·검증 한계는
[조회 전수 조사 기록](docs/data-management/request-audit.json)에 기록했습니다. 여기에 적힌
감소 수치는 합성 데이터의 특정 시나리오 결과이며 운영 전체 호출량·Firestore 청구 감소율이
아닙니다. `publicJsonFor().metrics()`로 공개 데이터의 요청·재사용·동시 합치기 횟수를 확인할 수 있습니다.

```sh
node --test tests/public_json.test.mjs tests/public_release.test.mjs tests/request_cache.test.mjs tests/scoped_refresh.test.mjs
# Vite 개발 서버(5173)가 실행 중일 때, 합성 응답으로 브라우저 요청 수와 권한 오류를 검사합니다.
node tests/request-dedup.browser.mjs
```

검색 목록은 기본적으로 작은 `ticker-index.json`을 사용합니다. `VITE_DIVGROW_RELEASE_BASE_URL`을 설정하면 DivGrow의 버전 고정 `releases/v1/current.json`과 manifest·catalog를 검증해 목록을 읽습니다. 카드 페이지는 썸네일 API로 필요한 시세 보조 데이터를 요청하며, `DIVGROW_DATA_BASE_URL`은 DivGrow R2의 `data/` 경로를 가리킵니다. 검증된 공식 배당 원장은 data v2의 승인 릴리스로 분리합니다.

종목 데이터가 체크아웃에 없다면 기존 데이터 저장소에서 복원하거나 `VITE_R2_PUBLIC_URL`을 설정해야 합니다. `VITE_USE_R2=true`로 종목 데이터를 R2에서 우선 읽을 수 있습니다. 환경변수를 바꾸면 개발 서버 재시작 또는 재빌드가 필요합니다.

GitHub Pages 배포는 `VITE_API_BASE_URL` 설정이 없으면 정식 웹앱 API인 `https://yieldloom-app.vercel.app`을 사용합니다. 인증·계좌용 Node·Python API는 기본 프런트엔드 origin `https://totobubu.github.io`와 로컬 개발 주소를 허용하며, 추가 사이트는 서버의 `PUBLIC_APP_ORIGINS`에 명시합니다. 익명 시장 데이터만 반환하는 `/api/thumbnail-data`·`/api/stock-prices`는 CDN에 저장된 응답도 같은 방식으로 읽을 수 있도록 공개 CORS를 사용하며, 브라우저 자격증명은 허용하지 않습니다. `FIRESTORE_SA_KEY`·Toss 자격증명은 서버 전용으로 유지합니다. Pages에 Firebase 웹 설정이 없는 경우 로그인 화면에서 정식 웹앱으로 이동해 계좌 기능을 이용할 수 있습니다.

익명 종목 의견함은 `/api/stock-feedback`을 통해 Firestore에 저장합니다. Vercel의 Production·Preview 환경에 기존 `FIRESTORE_SA_KEY`와 충분히 긴 임의 문자열인 `FEEDBACK_IP_SALT`를 설정해야 합니다. 원본 IP는 저장하지 않고 이 비밀값으로 해시한 제한 키만 10분 동안 사용합니다. 공개 제출을 허용할 별도 프런트엔드 origin은 `PUBLIC_APP_ORIGINS`에 추가합니다.

## 광고 배치

공개 종목 검색 화면만 광고 슬롯을 지원합니다. `VITE_ADSENSE_CLIENT`과 `VITE_ADSENSE_HOME_SLOT`이 모두 유효할 때만 Google AdSense 스크립트를 지연 로드합니다. 개인 포트폴리오·로그인·PDF 업로드 화면에서는 광고를 로드하지 않습니다. 실제 활성화 전에는 AdSense 사이트 심사와 이용 지역에 맞는 개인정보·동의 고지를 별도로 완료해야 합니다.

일정 카드는 `public/content-studio/distribution-index.json`과 티커별 공식 배당 이력, 또는 `VITE_DATA_RELEASE_BASE_URL`로 지정한 data v2 릴리스를 사용합니다. 가격 이력과 공식 배당 원장의 업데이트·정합성 검사는 계속 필요합니다.

공식 운용사 수집기 15종, SQLite 원장, 데이터 대조 및 릴리스·배포 도구는 유지합니다.

ETF 기초자산 연결은 `data-v2/security-underlyings.json`에 공식 상품명·출처 URL·원문
SHA-256·확인 시각·전략·방향·명시된 배수를 함께 보관합니다. 검색 인덱스, 원격
core/DivGrow 목록의 검색 화면, 상세 API 및 포트폴리오 분류가 이 정보를 사용합니다.
라이벌 비교 대상은 별도의 기존 검토 목록을 유지합니다.

```sh
npm run audit:underlyings
npm run collect:underlyings
# 저장된 원문으로 재현: 네트워크 요청 없음
python scripts/metadata/underlyings.py --offline --apply
python -m unittest discover -s tests/metadata -v
node --test tests/security_underlyings.test.mjs
# 개발 서버 5173에서 실제 검색·모바일·이전 목록 호환 검증
node tests/underlying-search.browser.mjs
```

전체 ETF 조사 결과는 `docs/data-management/underlying-audit.json`에 종목별로 남깁니다.
운용사가 없더라도 이름에 ETF가 있으면 조사에 포함합니다. `verified`는 공식 근거가
확인된 연결, `legacy-unverified`는 재검증되지 않은 기존 연결, `needs-review`는 이름에서
발견된 후보입니다. `no-single-underlying-detected`는 단일 연결을 발견하지 못했다는
뜻이며, 단일 기초자산이 없다고 확정한 결과가 아닙니다.

수집기는 Direxion·Kurv·GraniteShares·Roundhill·YieldMax·Defiance·REX·ProShares의
공식 목록을 시도합니다. ProShares처럼 목록을 해석하지 못한 경우와 HTTP 오류,
상품 목록/상세 페이지 충돌은 보고서에 기록합니다. 부분 실패 시 종료 코드 2를 반환하고
검증된 추가분만 등록하며 기존 연결은 삭제하지 않습니다. 이름 추정이나 거래소·통화가
확인되지 않은 신규 ETF는 자동으로 종목 목록에 만들지 않습니다. 신규 발견 상품의
근거는 보고서의 `unregisteredOfficialProducts`에 보관합니다.

`Refresh verified ETF underlyings` 워크플로는 main에서 평일 08:20 UTC에 실행되며,
검증된 연결·포트폴리오 분류·조사 결과를 커밋하고 Pages 재빌드를 요청합니다.
원문 캐시는 워크플로 아티팩트로 30일 보관합니다. 브랜치 보호 정책이 봇의 main
푸시를 막는 저장소에서는 아티팩트를 검토해 정상적인 PR 절차로 반영해야 합니다.
이 워크플로는 Vercel 운영 배포를 별도로 실행하지 않습니다.

```sh
npm run content:run
npm run content:refresh -- --scope provider --provider yieldmax
```

수집 파이프라인은 기본적으로 카드용 데이터 작업을 수행합니다. 기존 블로그 Bundle·편집 캘린더·주간 대본 생성은 `--include-editorial`을 명시한 경우에만 실행합니다. 호환 도구와 기존 저장 데이터는 보존합니다.

```

## 개인 배당 캘린더와 가정 시뮬레이터

마이페이지의 **배당 캘린더**는 현재 조회 가능한 계좌의 잔고 종목과 공식 배당 이력을 연결합니다. 월간/연간, 계좌·통화 필터, 지급일/배당락일 전환, 원문·수량 기준일 상세 보기를 제공합니다. 과거 배당락일의 수량은 현재 잔고에서 이후 매수·매도를 되돌려 계산하고, 지급일 근처에 같은 종목의 실제 배당 입금액이 있으면 그 금액과 공시 주당 배당금으로 수량을 역산합니다. 미래 공시 일정도 수량 기준일·배당금·배당 통화를 확인한 경우에만 세전 참고액을 표시합니다. 공시 확인 필요·주기 추정·지급일 미확인·지원하지 않는 종목은 따로 안내합니다. 통화를 임의 환산하지 않습니다.

**저장된 배당 거래**는 기존 인증 API로 모든 페이지를 읽으며 전체 10,000행까지 지원합니다. 배당 취소를 차감하고 원장 금액을 표시하되 실제 세후 수령액이나 기록의 완전성을 확정하지 않습니다. 조회 전후 계좌 권한·원장 버전과 로그인 상태를 확인해 변경 중 응답을 폐기합니다. 개인 거래·수량은 브라우저 저장소나 공유 URL에 저장하지 않으며, 공시 이력만 3분간 메모리에 캐시합니다. 여러 종목 조회는 동시 4개·최대 100종목으로 제한하고 누락을 안내합니다.

분석·캘린더의 거래 조회는 로그인 세션 메모리에서 검증이 끝난 페이지를 공유합니다. `entriesRevision`과 계좌 접근 권한이 같으면 탭 재진입·계좌 필터 변경 때 거래 페이지를 다시 읽지 않습니다. 권한·버전은 매 조회 전후 서버에서 확인하며, 전용 `view=ledger` 응답은 잔고·가족 프로필을 제외합니다. 같은 GET의 동시 요청은 하나로 합치고, 한 소비자의 취소가 다른 소비자의 조회를 취소하지 않습니다. 로그아웃·사용자 변경·변경 요청·접근 오류 때 캐시를 폐기하고, 수동 새로고침은 거래 페이지를 다시 읽습니다. 캐시는 최대 10,000행·100페이지이며 버전이 없는 자료는 재사용하지 않습니다. 첫 조회·변경 후 조회는 전체 거래 페이지를 읽습니다. 기간별 서버 집계와 거래 필터는 아직 적용하지 않았습니다.

원금 회수·자금 상세를 펼치면 **내 돈 · 재투자 · 현금 회수**에서 통화별 자금 흐름과 종목별 출처를 확인할 수 있습니다. 확정한 외부 입금과 사용자가 설정한 기초 취득원가·현금만 새 원금으로 보고, 배당·기타 수익·원금 순으로 자동 매수 배분하며 저장한 매수 자금 구성을 우선합니다. 배당 100을 다시 투자해도 누적 투자 원금은 늘지 않고 재투자 기반 자산만 100 늘어납니다. 매도는 가장 오래된 보유 로트부터 차감하고 초과 수익을 분리합니다. 다른 종목으로 이동해도 최초 원금의 출처를 유지해 중복 투입을 막습니다.

원금 회수율은 **원금으로 귀속된 외부 출금 ÷ 누적 투자 원금**입니다. 배당·수익 출금은 총 현금 회수에는 포함하지만 원금 회수율에는 포함하지 않습니다. 출금 분류를 확정하지 않은 경우 현금 로트 비율로 추정한 원금 회수를 확정값과 분리해 표시합니다. 전체는 같은 통화의 원금과 회수액 합계로 계산하며 계좌 회수율을 평균하지 않습니다. 계좌별 표의 ‘자금 추적’에서 해당 계좌의 차트·종목별 출처 배분으로 이동합니다.

차트는 누적 투자 원금, 취득원가와 현금을 합친 추적 자산, 누적 원금 회수입니다. 현재 시세 평가액·총수익률로 표시하지 않습니다. 종목 표에는 원금·재투자 출처의 보유 취득원가, 재투자분 수량, 누적 재투자, FIFO 매도로 배분한 재투자분 실현손익을 표시합니다. 같은 날은 입금→배당→매도→매수→출금 순의 규칙상 추정이며, 기초 잔액·세후 배당 정산액·매매 수량·환전/계좌 이동 연결이 없으면 확인 필요로 표시합니다. 배당 취소가 있으면 추적을 보류합니다. 개인 거래 원장은 변경하지 않습니다.

`배당 분석`은 조회 권한이 있는 계좌의 모든 거래 페이지를 읽고 조회 전후 계좌 권한·원장 변경 번호를 확인합니다. 계좌·가족 범위·로그인 상태가 바뀌면 이전 조회를 취소하고 기록을 지웁니다. 선택 연도의 1월부터 분석 월까지 배당과 배당 취소를 통화별로 합산하며, 날짜 미확인·미래 날짜는 제외 건수를 안내합니다. 기록이 없는 달과 관측된 0원을 구분하고, 금액 누락이 있는 경우 확인된 금액만 표시합니다. 전년 동월 비교는 완료된 달에 양쪽 기록·금액이 확인되고 전년 금액이 양수인 경우만 제공합니다. 실제 지급 내역의 완전성이나 세전·세후 금액을 확정하는 지표는 아닙니다.

누적 배당 기여도는 취소 차감 후 양수인 종목별 금액 합계를 분모로 사용합니다. 음수 순배당은 표에 남기고 비중에서는 제외하며, 상위 3종목 의존도를 표시합니다. 월 목표 달성률과 종목별 배당 감소 가정은 선택 월의 금액·통화가 확인될 때만 계산합니다. 입력은 화면에서만 유지하고 계좌·통화·월을 바꾸면 목표를 초기화합니다. 감소 가정은 과거 기록에 적용한 비교이며 미래 배당 예측이 아닙니다.

자산 집중도는 최신 시세 평가와 별도로 **업로드한 잔고의 확인된 평가액**을 사용하고 현금·미확인·음수 평가액을 제외합니다. 종목·운용사·연결 기초자산별 비중을 제공하며 서로 다른 잔고 기준일과 누락 계좌를 안내합니다. 운용사·기초자산 미분류는 종목별로 남기고, 연결 기초자산 분류는 롱·인버스·레버리지 방향과 배수를 반영한 실질 노출도가 아닙니다. 분류 파일 조회가 실패해도 저장 배당과 종목별 분석은 유지합니다.

`data-v2/catalog-seed.json`의 운용사 또는 `public/thumbnail-catalog.json`의 연결 관계를 바꿀 때 아래 명령으로 작은 공개 분류 파일을 함께 갱신합니다. 분류 파일에는 개인 자료가 없습니다.

```

원금 회수·자금 상세는 패널을 펼칠 때만 조회합니다. 같은 로그인 세션의 계좌별 요청을 합치고 5초 동안 메모리에서 공유하며, 이후에는 매번 계좌·가족 권한을 확인하고 변경 번호가 같으면 원장을 다시 읽지 않습니다. 현금 분류·자금 구성 변경은 별도 변경 번호로 확인해 거래 원장을 재사용하고, 거래 업로드는 기존 `entriesRevision`으로 갱신을 감지합니다. 개인 원장을 브라우저 저장소나 공용 CDN에 캐시하지 않습니다. 요청 제한(429)은 일일 한도 소진으로 단정하지 않고, `Retry-After`에 따라 기본 60초 동안 재요청을 막습니다. 이미 소진된 서버 사용량은 이 변경으로 초기화되지 않습니다.

계좌 목록의 요청 제한 화면에는 권장 재시도까지 남은 초와 현지 시각을 표시하고, 대기 중 계좌 목록 재시도와 새로고침을 비활성화합니다. 시간이 지나도 자동으로 재요청하지 않으며 고객이 다시 조회할 수 있습니다. 다시 429가 오면 새 대기 시간을 적용합니다. 서버의 `ResourceExhausted`만으로 일일 한도 소진 여부나 복구 시각을 확정하지 않으며, 현재 60초는 `retryTiming: recommended`로 표시하는 재시도 간격입니다. Pages에서도 `Retry-After`를 읽을 수 있도록 허용된 origin에 해당 응답 헤더를 노출합니다.

마이페이지의 `CSV 내보내기`에서 읽기 권한이 있는 한 계좌의 최신 기준일 잔고 또는 저장된 전체 거래를 UTF-8 BOM CSV로 내려받을 수 있습니다. 통화·자료 기준일(`asOf`)·출처(`source`)를 보존하며 미확인 금액은 빈칸으로 둡니다. 거래는 200행씩 모두 읽되 한 번에 10,000행까지 지원하며, 조회 중 권한·로그인 계정·거래 원장이 바뀌면 부분 파일을 만들지 않습니다. 계좌번호·권한·PDF 비밀번호 같은 계좌 내부 필드는 출력하지 않습니다. XLSX 형식과 이전 단일 계좌 자료의 내보내기는 지원하지 않습니다.

수식으로 해석될 수 있는 텍스트는 작은따옴표로 보호하고 `csvEscaped` 열에 처리한 열 이름을 기록합니다. 다시 올릴 때 이 열을 유지하면 원래 거래 고유번호를 복원해 중복 검사를 유지합니다. 기존 CSV 업로드의 한 계좌·200행·2MB 제한과 잔고 전체 스냅샷 정책은 그대로 적용됩니다. 등록 완료 화면에서는 새로 저장한 행과 중복을 구분하고, 과거 기준일 잔고는 최신 잔고를 덮지 않았음을 안내합니다.

구조·제품 기본값·지원 형식·보존 이전·Firestore 규칙/TTL 적용·검증 방법은 [가족 포트폴리오 v2 안내](docs/architecture/FAMILY_PORTFOLIO_V2.md)를 참조하세요. 실제 증권사 API는 새 가족 기능에 연동하지 않았습니다.

테마 전환·로컬 설정 저장, 오류 경계·Sentry, Android 구성도 유지합니다. Vercel Analytics는 기존 패키지 상태를 유지하며 새로 활성화하지 않았습니다.

## XLSX·증권사 자료, 계정 결산과 알림

계좌의 `자료 업로드`에서 표준 CSV와 같은 열의 XLSX(첫 시트·첫 행 제목)를 선택하거나,
`증권사 CSV·XLSX 열 연결`에서 파일의 제목 행·시트·인코딩과 열을 직접 지정합니다.
토스·키움·한국투자·미래에셋·삼성·기타를 구분하지만, 실제 발급 양식을 검증한
전용 자동 인식기는 아닙니다. 종목명 대신 코드를 연결하고, 거래에는 발급 기간이
달라져도 유지되는 고유번호가 필요합니다. CP949는 직접 선택하며 통화도 연결하거나
USD/KRW로 명시합니다. 숫자만 있는 종목 코드의 Excel 0 채움 표시를 보존합니다.

CSV/XLSX는 2MB·자료 200행·50열까지이며 XLSX는 최대 20시트, 제목 행은 1~20행입니다.
암호·수식·오류 셀·매크로·XLS는 거부하고 압축 해제 총량은 20MiB로 제한합니다.
15자리 이상 숫자 셀은 정밀도 손실 방지를 위해 거부하므로 고유번호는 원본에서
텍스트로 내보내세요. 파일 열 확인은 제목·행 수만 반환하며, 연결 후 기존 검토·수정·
권한 확인·중복 방지 저장을 거칩니다. 거래 금액과 원화/달러 정산액은 별도 항목입니다.

`배당 분석 → 월간 결산 저장·비교 → 계정 보관함 열기`에서 로그인 사용자별 결산을
선택 계좌 범위·통화당 최대 24개 보관합니다. 저장은 금액 포함 확인과 원장 버전 일치가
필요하며 같은 월 대체·삭제는 확인 후 수행합니다. 저장 후 원장이 변경되면 당시 요약임을
표시합니다. 공유 계좌도 현재 권한을 재확인하며 가족 구성원끼리 보관함을 공유하지 않습니다.
결산은 사용자가 검토한 화면 집계이며 서버가 재계산한 공식 수령 증명은 아닙니다.

`마이페이지 → 설정 → 자동 배당 알림`은 기본 꺼짐이며 설정은 계정에 저장합니다.
앱을 열거나 자료를 갱신할 때 선택 계좌·통화의 1/3/7일 이내 확정 공시 일정을 표시합니다.
브라우저 알림은 별도로 권한을 허용하고 설정을 저장한 경우에만 표시하며 종목명이 포함됩니다.
앱이 닫힌 동안의 푸시·메일은 제공하지 않습니다. 설정 조회는 세션 메모리에서 5분간
공유하며 새로고침은 직접 요청합니다. 주기적 서버 폴링·추가 원장 조회는 없습니다.
브라우저 알림 중복 방지는 로그인 세션·하루·일정 기준이며 다시 로그인하면 재표시될 수 있습니다.

추가 분석은 이미 받은 원장으로 거래 유형별 금액·미확인 수, 입출고·환전 후보,
6개월 배당 변동성을 보여 줍니다. 6개월 모두 기록·금액이 있고 마감된 경우에만
최근 3개월/이전 3개월 비교를 계산합니다. 기록 없는 달을 0원으로 채우지 않습니다.
완전한 거래 기록을 확인한 뒤 기준일 잔고가 없고 매수·매도 수량과 정산액이 확인된
종목만 청산 손익을 계산합니다. 입출고·분할은 원가 확인이 필요해 계산하지 않습니다.
이 수익률은 단순 누적 수익률이며 연환산·시간가중 수익률은 아닙니다.

결산의 `결산 카드·블로그 만들기`는 현재 월과 연결한 이전 결산을 TXT·SVG·1080px PNG로
만듭니다. 금액은 기본 비공개이고 계좌·명의·종목·개별 거래를 내보내지 않습니다.
공개 메모는 직접 검토하며 외부 자동 게시를 하지 않습니다.

서버 보관 경로는 `portfolioPrivateUsers/{사용자해시}/statementScopes/{범위해시}`이고
클라이언트 Firestore 접근은 거부합니다. 기존 규칙의 기본 거부에도 해당하며 직접 SDK로
열지 않습니다. 계정 결산 1개 계좌의 조회·저장은 테스트에서 문서 읽기 3개(범위·가족·계좌),
알림 설정 조회·저장은 1개를 관측했습니다. 동일한 결산·설정 재저장은 쓰기를 생략합니다.
거래 원장 조회와 Firebase Auth 토큰 강제 갱신은 추가하지 않습니다.

## 포트폴리오 고도화: 대조·입력 설정·정정·XIRR

- **배당 캘린더 → 예상·기록 대조**: 기존 공시와 권한 검증된 원장을 사용합니다.
  같은 계좌·종목·통화의 지급일과 같은 날짜 기록을 우선 연결하며 전후 7일도 후보로
  확인합니다. 겹치는 지급 일정의 후보는 자동 합산하지 않습니다. 지급일이 지났어도
  거래 미확인은 미수령을 뜻하지 않습니다. 배당 취소는 차감하며 공시와 기록을 합산하지
  않습니다. 현재 보유 종목의 공시만 연결하므로 매도한 종목의 과거 일정은 누락될 수
  있습니다. 배당락일 수량과 세전 금액 기준을 직접 확인한 경우에만 `주당 공시액 × 수량`
  대비 차이를 계산합니다. 계좌·통화·기간·자료가 바뀌면 확인을 초기화합니다.
- **자산관리 → 계좌의 자료 업로드 → 증권사 CSV·XLSX 열 연결**: 증권사·자료 종류별로 인코딩·제목 행·
  시트 순번·기본 통화·열 위치를 이 브라우저에 명시적으로 저장/불러오기/삭제합니다.
  파일·행 데이터·시트 이름·계좌 정보는 저장하지 않으며 헤더는 SHA-256 지문만
  보관합니다. 새 파일의 헤더 순서가 달라지면 저장된 연결을 적용하지 않습니다.
  다른 시트는 사용자가 선택한 뒤 다시 검사하며, 불러온 열 연결은 확인란을 선택해야
  미리보기로 진행됩니다. 자동 저장·서버 저장은 하지 않습니다.
- **자산관리 → 계좌의 자료 업로드 → 수동 잔고 입력**: 현재 잔고와 같은 기준일의 오류 정정을 선택하고
  1~200자 사유와 전체 잔고를 확인할 수 있습니다. 저장 전 종목·통화별 추가/제외와
  수량·평가액 변경을 표시합니다. 검토와 저장 시 권한·원본 해시를 재확인하며 동시 수정은
  거절합니다. 변경 없는 정정은 거절하고 같은 검토의 재전송은 기존 영수증으로 중복
  저장을 막습니다. 새 이력에는 버전·수정자·시각과 변경 전후 자료를 보관합니다.
  `잔고 변경 이력 조회`는 명시적 조회로 20개씩 불러오고 상세는 선택할 때만 읽습니다.
  과거 이력은 소급 생성하지 않으며 원장 거래를 수정하거나 자동 되돌리지는 않습니다.
- **배당 분석 → 원장 품질·청산 수익 분석 → 계좌 XIRR**: 계좌 개설 시 기초 자산 0,
  전체 입출금과 현금 포함 전체 잔고를 확인한 경우에만 계산합니다. 선택 월의 성과가
  아닌 개설부터 업로드 잔고 기준일까지의 ACT/365 연환산 수익률입니다. 표준 원장의
  `cashKind=external_deposit`(입금), `external_withdrawal`(출금)만 외부 흐름으로 쓰며,
  내부 배당·매매는 별도 현금흐름으로 중복 반영하지 않습니다. 마지막 전체 평가액을
  회수액으로 넣고 환산·현재 시세 조회는 하지 않습니다. 현금 미분류·환전·계좌 이동·
  증권 입출고·통화 혼재·누락 금액은 계산을 보류합니다. 현금흐름 부호가 여러 번 바뀌면
  복수 해 가능성 때문에 값을 선택하지 않습니다. 수익률 탐색 범위는 -99.9999%부터
  99,999,900%이며 그 안의 해가 없는 경우 확인 사유를 표시합니다.

프리셋·XIRR·배당 대조 계산·필터 변경은 API/Firestore/Auth 작업을 추가하지 않습니다.
거래 화면에서 대조 화면으로 이동하면 기존 세션 원장을 재사용하되 기존 전후 권한 검증은
유지합니다. 합성 브라우저 검증에서 재진입 HTTP 요청은 2회 이내이며, 같은 기준일 정정은
미리보기 문서 읽기 2개, 저장 5개를 관측했습니다. 이력 조회는 선택할 때 별도로 읽으며
필드 제한은 문서 읽기 과금 감소를 뜻하지 않습니다. 실제 청구량·실제 계좌는 검증하지 않았습니다.

## 배당 투자 설계실

`내 포트폴리오 → 배당 분석 → 월간 결산 저장·비교`에서 선택 월·통화·계좌 범위의
배당 합계와 기록 수를 JSON 파일로 보관할 수 있습니다. 금액 포함 확인 후 다운로드하며
계좌번호·명의·종목·개별 거래는 포함하지 않습니다. 같은 로그인 사용자·가족·계좌
범위는 SHA-256 해시로 구분합니다. 파일은 계정에 자동 저장하거나 서버로 업로드하지
않으며, 사용자가 직접 안전하게 보관하고 다시 선택합니다. 최대 32KB·버전 1 파일을
지원하고 다른 통화·계좌 범위·같거나 이후 월의 비교는 거부합니다.

이전 결산을 불러오면 현재 분석 월과 기록 금액의 차이를 표시합니다. 두 결산 모두
마감된 월이고 기록·금액이 확인되며 날짜 제외가 없는 경우에만 증감을 계산합니다.
이전 금액이 0 이하이면 증감률을 표시하지 않습니다. 기록 없음·금액 미확인·관측된
0원을 구분하고 배당 취소는 기존 분석과 같이 차감합니다. 저장 후 원장이 정정되어도
이미 내려받은 파일은 바뀌지 않으며, 파일 진위나 실제 수령 기록의 완전성을 보장하지
않습니다. 월·계좌·사용자 변경과 로그아웃 시 불러온 자료와 다운로드 확인을 지웁니다.
JSON 저장·불러오기·비교는 이미 검증된 화면의 원장·집계를 사용하므로 추가 API/DB 조회가 없습니다. 아래 계정 보관함은 사용자가 열거나 저장·삭제할 때 별도로 권한을 확인합니다.

```sh
node --test tests/monthly_statement.test.mjs tests/portfolio_insights.test.mjs
# Vite 5173. 합성 인증/API로 결산 다운로드·재불러오기·계좌 범위·오류를 확인합니다.
node tests/portfolio-insights.browser.mjs
```

`내 포트폴리오 → 배당 분석`의 설계실은 조회 중인 개인/가족·계좌·통화·분석 월을 따릅니다. 원장 조회 실패 시 계산 화면을 숨기고, 계좌·월·통화 변경과 로그아웃 시 입력·설문·초안을 초기화합니다. 개인 입력을 로컬 저장소·URL·분석 로그에 남기지 않습니다. 기존 배당 캘린더·집중도·시뮬레이터는 계속 사용할 수 있습니다.

- **배당 효과**: 선택 월까지 최근 12개월 저장 배당과 자료상 증권 평가액을 통화별로 표시합니다. 배당 취소를 차감하고 기록 없는 달과 금액 미확인을 구분합니다. 짧은 기록을 자동 연환산하지 않으며, 거래 기록의 세후 금액·완전성을 확인한 경우에만 시작 배당률 가정으로 가져옵니다. 평가액은 현재 시세가 아닌 업로드 자료 기준입니다.
- **FIRE**: 시작 평가액·월 납입·세전 배당률·원천징수율·주당 배당/주가 변화·물가·재투자 비율·생활비·최대 60년을 입력합니다. USD 포트폴리오는 KRW 목표와 환율 변화도 지원합니다. 보수적(배당 20% 삭감, 배당/주가 변화 -2%p), 기준, 낙관적(+2%p)의 최초 목표 충족 월과 연도별 표·추이 차트를 표시합니다. 월 납입 증액·생활비 축소 및 배당 현금 보유 대비 재투자 효과도 비교합니다. 최초 충족이 이후 유지나 실제 FIRE를 보장하지 않습니다.
- **회수·재투자**: 버튼을 누르면 조회 권한을 전후 확인한 계좌별 기존 원금 API와 자금 추적 계산으로 외부 납입/인출을 가져옵니다. 원장 변경·일부 계좌 실패 시 합산을 적용하지 않습니다. 기초 자료 누락과 분류 경고는 그대로 표시합니다. 확인 입력한 누적 세후 배당과 실제 외부 인출을 구분하고, 일정 배당·인출 비율에서 남은 회수액/개월을 계산합니다. 동일 종목·다른 종목 신규 투자·매도 후 교체를 같은 금액/기간으로 비교하며 교체에만 입력 비용을 차감합니다. 입력 전체 자산+외부 인출-외부 납입은 금액 손익이며 시점 반영 수익률은 아닙니다.
- **안정성**: 전체 배당 10/20/30% 삭감, 최대 배당 기여 종목 중단, 환율·배당 동시 충격에 따른 생활비 충당률과 부족액을 계산합니다. 주가 하락으로 높아진 배당률과 실제 배당 증가를 구분합니다. 기존 집중도에 업종/국가 분류도 추가했으며 공개 분류 파일에 없는 값은 종목별 미분류로 남깁니다. 기업 지급 여력과 ETF 분배 재원 등은 공식 자료로 직접 확인해야 합니다.
- **성향 모의고사**: 10문항으로 위험 선호·투자 여력·학습 이해도를 구분합니다. 집중도 경고·해설·투자 원칙 초안을 제공하며, 전문 적합성 진단이나 개인별 매수 추천을 뜻하지 않습니다.
- **블로그 5종**: 월간 결산/FIRE 보고/종목 점검/재투자 비교/성향 회고를 네이버 편집기용 TXT로 복사·다운로드하고, 5종+배당 차트 PNG/SVG를 ZIP으로 내보냅니다. 금액·비율·예상 시점·종목은 기본 비공개입니다. 자유 메모는 자동 익명화하지 않으므로 공개 전 직접 검토합니다. 자동 게시는 수행하지 않습니다.

FIRE·재투자 모델은 월초 납입·균등 월 배당·월말 세후 재투자·소수주 매수 가정입니다. 재투자 배당은 자산에 이중 가산하지 않고 비재투자 배당은 현금으로 보유합니다. 원천징수율 외 종합과세·건강보험료·계좌 세제·매매수수료·배당락 조정은 계산하지 않습니다. 주가와 주당 배당을 독립적으로 변화시켜 미래 배당률을 계산하며, 과도한 입력의 수치 발산은 오류로 처리합니다. 월별 실제 지급 공백은 배당 캘린더에서 별도로 확인합니다.
