# 구글시트 시험 거래 목록

관리자 메뉴의 **부부 거래 목록 · 시험** (`/admin/sheet-ledger`)에서 사용한다.
기존 포트폴리오 장부와 분리된 `sheetTrialLedgers/{uid}` 아래에 남편/아내
계좌와 100행 단위 페이지를 저장한다. 최대 4,000행이며 비용 미상은 null이다.
Firestore 클라이언트 직접 접근은 금지하고 API가 기존 관리자 허용 목록을 검증한다.

## 운영 준비

- 기존 Firebase Google 로그인 제공자를 활성화한다. 관리자 계정과 같은 계정으로
  Google 재인증 팝업을 연다. Google OAuth 동의 화면에 Sheets/Drive 읽기 전용
  범위를 등록하고 필요한 경우 테스트 사용자에 관리자 계정을 추가한다.
- Firebase 프로젝트와 연결된 Google Cloud 프로젝트에서 Google Sheets API와
  Google Drive API를 활성화한다. 비공개 앱은 OAuth 게시/검증 정책을 확인한다.
- 서버의 기존 `FIRESTORE_SA_KEY`와 프런트 Firebase 설정을 사용한다.
  별도 서비스 계정 공유나 OAuth 클라이언트 비밀키는 필요하지 않다.
- 읽기 토큰은 화면 메모리에만 유지하고 저장 완료·로그아웃·화면 이탈 때 폐기한다.
  토큰이나 개인 거래 원본은 로그·공개 정적 파일에 기록하지 않는다.

## 이전 절차와 데이터 의미

현재 거래 목록 화면에서는 최초 1회용 Google 시트 가져오기 영역을 제거했다.
페이지 진입·필터·수동 추가에서 시트를 다시 호출하지 않는다. 아래 이전 API 절차는
기존 기능의 계약 설명이며, 이미 저장된 장부와 원본은 그대로 보존한다.

거래 목록은 페이지네이션·표 내부 고정 높이 없이 문서 스크롤 위치에 맞춰 최대
100행의 DOM 창을 표시한다. 검색·정렬은 전체 등록 자료를 기준으로 계산한다.
키보드의 `처음/마지막 거래로 이동`과 브라우저 PageDown/End로 접근하며 전체/필터/표시 범위를 구분한다.
목록 확장은 추가 API/DB 조회를 발생시키지 않는다.

`거래 행 추가`는 계좌·유형·거래일과 선택적인 실제 일시/시간대·통화별 금액을 입력해
`source.kind=manual`, 검토 필요로 저장한다. 빈 값은 null이며 표시되지 않은 초/시간대를
추정하지 않는다. POST `add-manual`은 `requestId` UUID, `data`, `version`을 요구한다.
같은 요청 ID·내용의 재시도는 중복 쓰기 없이 원래 거래를 반환한다. 취소는 쓰기 0회다.
수동 추가 후 현재 필터를 유지하며 `추가한 거래 보기`로 새 행만 찾아볼 수 있다.

URL → 미리보기 분석(필요할 때 Google 읽기 권한 연결) → 제외/보류와 추정 근거 확인 → 저장.
연결된 화면에서는 재연결 없이 분석하며, 토큰 만료 안내가 나오면 분석 버튼을 다시 눌러
연결한다. 동일 관리자 재인증으로 장부를 재조회하거나 분석 결과를 초기화하지 않는다.
읽기/저장 요청에는 45초 제한이 있으며, 분석 중 상태와 오류를 화면에 표시한다.
저장 직전 원본을 다시 분석하고 미리보기 지문과 버전을 비교한다. 변경되었으면
409로 거절하고 다시 분석한다. 동일 원본 행은 중복 저장하지 않고 기존 수정도 보존한다.
시트 행 삽입/이동은 원본 ID를 바꾸므로 최초 이전 이후 구조 변경된 시트의 재이전은 피한다.

현재 원본 구조에 맞춰 夫 A1:V570, 妻 A1:AK566, 夫배당 A1:K652,
妻배당 A1:K2000을 읽는다. 시트 구조/범위가 변경되면 어댑터도 함께 갱신한다.
종목별 집계 탭은 읽지 않는다. 한국 날짜 기준 미래 행은 제외한다.
수량/세후 지급액이 직접 입력되거나 숫자 덧셈/뺄셈인 행을 실제 거래 근거로 사용한다.
셀 참조 수량/지급액만 있는 행은 보류한다. 원본 수식은 실행하지 않는다.
날짜가 비어 있는 배당 행은 직전 날짜 묶음을 추정 적용하며 연도 구분에서 초기화한다.
과거 계산행에 직접 입력한 숫자가 섞여 있으면 자동 판별에 한계가 있으므로 미리보기를 확인한다.

매수단가는 금액/수량으로 계산한다. 매수 원화금액/환율은 원본에 거래별 근거가 없어
자동 환산하지 않는다. 배당의 세전/세후 차액은 세금 추정이며 수수료와 환전비용은
미확인이다. USD/KRW는 같은 거래의 별도 통화 표기로 서로 합산하지 않는다.
재투자는 같은 계좌의 7일 이내 배당 잔액을 같은 티커 우선으로 소진하여 연결한다.
90% 이상이면 재투자 추정, 일부이면 혼합, 재원 근거가 없으면 미확인이다.
거래 수정은 시스템 장부에만 적용한다. 원본 시트에는 쓰지 않는다.

## API와 호출량

- `GET /api/sheet-ledger`: 현재 관리자 시험 장부와 버전 조회.
- `POST`: `action=preview|commit`, `url`, `googleToken`.
  commit은 미리보기의 `fingerprint`, `version`을 요구한다. 클라이언트 거래 배열은 무시한다.
- `PATCH`: `id`, `version`, `patch`로 수정. 버전 충돌은 409.

화면 진입/명시적 새로고침마다 장부를 페이지 조회하며, 필터·정렬은 0회다.
동시 조회는 클라이언트에서 합친다. 장부를 세션 밖이나 영구 브라우저 캐시에 저장하지 않는다.
서버 조회는 페이지별 메타 문서와 필요한 거래 페이지만 일관된 읽기 트랜잭션으로 읽는다.
최초 페이지는 계좌별 관측 체크포인트 2개도 확인한다. 페이지 계약은
[관측 배치 계약](SHEET_OBSERVATION_BATCHES.md)을 따른다.
가져오기 분석/저장마다 Google Sheets 요청 1회, 저장은 메타 문서로 충돌을 확인하고
변경된 페이지만 쓴다. 완전 중복 가져오기는 쓰기 0회다.
이는 코드상 예상 횟수이며 실제 Firestore 청구량을 뜻하지 않는다.

검증: `node --test tests/sheet_ledger.test.mjs`,
`node tests/sheet-ledger.browser.mjs` (Vite 5173, 합성 인증/API),
`npm run type-check`, `npm run lint:check`, `npm run build`.
실제 OAuth 동의와 운영 DB 저장은 관리자 브라우저에서 별도로 확인한다.

## 시험 장부 출처 대조와 원금 검증

원금은 매수액과 다르다. 확인된 외부 순입금(외부 입금−외부 출금)과 자금 출처별
원금을 별도로 표시한다. 외부 출금 중 `DIVIDEND_PROFIT`로 관리자가 확인한 배당
활용 출금은 원금을 차감하지 않는다. `UNKNOWN`·`MIXED`는 원금 잔여분에 임의
반영하지 않고 검토 필요로 남긴다. FIFO·비례 배분 및 신규 배당 재투자 계산은 하지 않는다.
`ACCOUNT_TRANSFER`는 상대 계좌와 근거를 보존하고 부부 합산 외부 원금에서 제외한다.
계좌별 이체 순액은 별도 표시한다. 금액 수정 시 이전 자금 분류는 무효화된다.
합계는 등록된 근거의 부분 합계이며 전체 계좌 원금의 완전성을 보증하지 않는다.

대조 관측 자료는 `PDF`, `TOSS_TRANSACTION`, `TOSS_ORDER`,
`TOSS_EXPECTED_DIVIDEND`로 구분한다. 출처 고유 ID·계좌·원본 위치·관측값·선택적
원문을 제출하고 미리보기 후 **대조 자료만** 저장한다. 이 JSON 제출 경로는 확보된
관측 자료의 검증/연결용이다. 토스 웹 자동수집이나 기존 PDF 장부의 자동 조회가
구현·실행됐다는 의미가 아니며, 실제 자료 수집·소유 계좌 확인은 별도 단계다.
누락값은 null이다. 관측되지 않은 시분초·시간대·수수료를 채우지 않는다.
환전금액과 주문금액−체결금액 차이는 새 원금 또는 수수료로 자동 간주하지 않는다.
환전 수수료가 사용 원화에 포함된 경우 `fxFeeIncluded=true`로 보존한다.
예정 결제일은 실제 결제 일시와 다르다. '예상 배당금' 메뉴에도 과거 지급 상세가 있으므로
출처명과 지급 상태를 분리한다. 확정·지급·실제 지급일 원문이 확인된 배당만 기존 입금에
근거로 연결하며 새 현금유입을 만들지 않는다. 미지급·미확정·상태 불명은 보수적으로 남긴다.
[배당 상태 계약](SHEET_DIVIDEND_STATUS.md)에 정규화 필드와 원문 보존 규칙을 정리했다.

같은 출처/계좌/고유 ID는 중복 등록하지 않는다. 같은 ID의 다른 값은 거절하며 별도
개정 ID가 필요하다. 동일 계좌·유형·티커·날짜·확인 가능한 수량으로 연결 후보를
제안하지만 값은 바꾸지 않는다. 여러 후보는 미매칭으로 남긴다. 기존 후보가 있는데
신규 사건으로 저장하려면 별도 사건이라는 관리자 확인도 필요하다.
출처별 값을 병렬 표시하고, 관리자가 관측 필드와 근거를 선택해 채택해야 시험 거래만
수정한다. 원본 등록값·출처 관측값·필드별 채택 이력은 유지한다. 다른 계좌/유형으로의
채택과 예상 배당의 실제 입금 확정은 금지한다.

시트 가져오기 확정 시 네 탭의 원본 셀(수식/오류/미래/보류 행 포함)을
`sheetTrialLedgers/{uid}/sourceArchives/{sha256}`에 불변 스냅샷으로 보존한다.
실제 거래에 제외 행을 섞지 않으며 기존 Google 원본·PDF Firebase 자료에는 쓰지 않는다.
원본+제외 내역은 4MB, 보존 버전은 8개로 제한한다. 원본은 소유 관리자 인증 후 명시적
다운로드만 가능하다. 새 대조 자료는 계좌별 독립 관측/원문/완료 배치로 저장하며
누적 2,000건/전체 응답 4MB 한도를 제거했다. 기존 자료는 이전/삭제하지 않는다.
요청당 100건/3MB 이하로 원문을 나누며, 조회는 커서 페이지를 사용한다.

추가 API는 기존 관리자 인증을 유지한다. 거래 수정은 장부 버전을 검증하며,
불변 관측 배치 저장은 별도 fingerprint/중복 검증으로 병렬 수집을 허용한다.

- POST `batch-preview|batch-commit`: `accountId`, `batchId`, `checkpoint`, `observations`; [전체 계약](SHEET_OBSERVATION_BATCHES.md).
  구형 `evidence-preview|evidence-commit` 쓰기는 410이며 기존 관측 읽기는 유지한다.
- POST `accept-evidence`: `accountId`, `observationId`, `reviewVersion`, `targetId`, `fields`, `note`, `version`; 신규 사건은 거래일 필수.
- POST `classify-cash`: `id`, `scope`, `origin`, `peerAccountId`, `evidenceIds`, `note`, `version`.
- GET `?sourceArchive={id}`: 현재 관리자에게 연결된 보존 원본만 다운로드.

추가 조회량: 거래 페이지와 관측 요약 페이지를 분리하며 페이지마다 인증/버전 검증을 유지한다.
전체 검색/정렬/필터는 받은 요약에서 계산하여 추가 HTTP/DB 조회 0회다.
관측 선택 시 해당 원문의 완료 영수증·청크를 필요한 때만 조회한다.
원본 다운로드는 메타 1개+원본 메타 1개+원본 청크 N개이며 거래/대조 페이지는 읽지 않는다.
최초 원본 보존은 원본 메타 1회 읽기 후 청크 N개+메타 1개 쓰기이며 동일 지문의 재가져오기는
원본을 다시 쓰지 않는다. 동일 배치 재전송은 쓰기 0회다. 다른 배치의 중복 원본 제출은
관측은 중복 생성하지 않지만 별도 배치 원문/영수증은 보존한다.
이 수치는 코드상 예상이며 실제 운영 과금 측정값이 아니다.

추가 검증: `node tests/sheet_reconciliation.test.mjs`,
`node tests/sheet-reconciliation.browser.mjs` (로컬 5181, 합성 인증+메모리 DB).
합성 성공을 실제 계좌 수집·운영 저장 성공으로 보고하지 않는다.

### 후속 브라우저 수집 설계 기준 (아직 구현/실행하지 않음)

- 계좌+유형+날짜 의미+정규화 티커+매매수량으로 후보를 찾고 실제 상세 화면에서 확인한다.
  체결일/결제일/지급일과 배당 보유수량/매매수량을 혼동하지 않는다. 같은 키 다건은
  거래번호·시각·금액으로 구분하며 unique/ambiguous/unmatched 건수·비율을 실제 측정한다.
  검증 없이 99%를 주장하거나 미확정 후보에 상세값을 자동 확정하지 않는다.
- 토스 원화/달러 탭은 별도 원통화 현금 원장으로 보존한다. 환전 양쪽 기록을 연결하되
  외부 입출금 또는 신규 원금으로 이중 계산하지 않는다. 브라우저 수집을 API로 몰래 대체하지 않는다.
- 원천 배당과 여러 매수·환전·출금은 독립 event와 다대다 allocation link로 분리한다.
  link는 원통화 배정액·근거·proposed/confirmed를 보존하고 잔액/중복 배정을 검증해야 한다.
  단일 parentId에 제한하거나 통화 액면을 합산하지 않는다. 현재 행별 출처 분류는 이러한
  금액별 배정 그래프를 구현한 것이 아니며, 재투자 UX와 함께 후속 범위다. 사용자 가정 예시는 저장하지 않는다.
  원천별 미사용 현금은 통화별 lot로 남고 FX 후에도 lineage를 유지해야 한다.
  배당보다 매수가 많다는 사실만으로 신규 원금 납입을 추정하지 않는다. 실제 외부입금
  근거가 필요하며 원금·배당·매도대금·미확인 잔액의 혼합 배정과 잔액 보존을 허용해야 한다.
