# Dividend evidence verification

Run `npm run content:verify-dividends` from the application directory. For a targeted audit:

```sh
python scripts/content_pipeline/enrich_dividends.py --ticker JEPI --limit 1
```

The provider-refresh workflow runs the same audit even after an official refresh fails. A ticker refresh audits only that ticker, including ETFs; a provider refresh stays within that provider. A registered ETF can be selected before its first official event exists. Raw evidence, source documents, observations, audit results and rotation state are retained in the existing content database and raw directory. The JSON summary is written to `var/content-studio/dividend-verification.json` and uploaded as a workflow artifact. This process never overwrites canonical dividends or promotes external observations to official confirmation.

Third-party requests require a reviewed grant in `data-v2/dividend-reference-access.json` (`--access` selects an alternative registry). The shipped registry is empty: no new free provider has been verified for automated storage **and public redistribution**. Missing grants produce `referenceStatus: supplier_connection_required`, not an empty or zero-dividend claim. Existing observations are retained. HTTP failures record the observed status code without inferring the cause or changing URLs, credentials or proxy settings.

The empty registry intentionally pauses the existing Yahoo/Investing/Seeking Alpha **enrichment requests**, including rotating audits. It does not provide a working SCHD substitute and must not be described as SCHD recovery. Official collection/export remains separate. Each audit reports `canonicalEventCount`, `previouslyStoredReferenceCount`, and the workflow's `officialRefreshStepOutcome`; a failed official step remains a failure even when older evidence exists. The preservation regression test confirms that official rows, stored observations, source documents and exported dividend JSON remain unchanged during this disabled audit.

Only add a grant after confirming the actual supplier agreement. Each provider entry must explicitly set `enabled`, `automatedCollection`, `storage`, and `publicRedistribution` to true, `feeRequired` to false, and include `evidenceUrl` (HTTPS agreement/review evidence), `reviewedAt`, `validUntil` (ISO dates), exact `tickers`, `allowedHosts`, and `datasets: ["dividends"]`. A URL mapping alone grants no permission. Expired grants, other hosts/tickers, and paid access remain disabled. The synthetic grants in tests apply only to injected fixtures.

Sources:

- Official provider adapters remain the primary source. Optional `BRAVE_SEARCH_API_KEY` enables discovery of additional documents on their approved official domains. Search snippets are not parsed as dividends. Discovered PDFs are retained for further parsing, with `parser_required` recorded.
- The retained Yahoo parser can compare ex-date and amount, with symbol, currency, exchange timezone and stock-split checks, if a qualifying grant is registered.
- The retained Investing.com parser uses security URLs in `data-v2/verification-sources.json`; JEPI is mapped, but that mapping is not a license.
- The retained Seeking Alpha parser uses `https://seekingalpha.com/symbol/{TICKER}/dividends/history` for registered USD securities on supported US exchanges, subject to a qualifying grant. Public HTML dividend tables supply ex-date, amount and available record/payment dates. By default at most five authorized Seeking Alpha requests are made per batch (`--reference-limit`).

Seeking Alpha can require JavaScript, cookies or a subscription. A page without a readable public table is recorded as an error and supplies no observations. The adapter does not bypass access restrictions or infer amounts from page headings. Adding a reference does not guarantee live collection from that site.

Comparisons require the exact ex-date and currency, use bounded decimal tolerance, and flag ambiguous rows and unresolved split basis. Missing fields remain unavailable. Existing Toss ingestion is unchanged; this command does not add a new Toss API collector. Securities without a supported official adapter can accumulate auxiliary evidence, but official discovery requires an adapter first.

The thumbnail API keeps already collected reference rows when the official ledger is unavailable, marks them `needs_review`, and reports `sourceStatus.officialDividends: unavailable` alongside the existing unavailable/partial status. This preserves evidence without presenting reference amounts as official. This fix does not add an ETF reference publication pipeline or activate any supplier. The standalone stock collector now omits Yahoo dividend events and raw response storage unless the same reviewed grant permits them; existing observations remain in its prior snapshot. Its Yahoo price and split collection remains a separate data-rights review.

Supplier review (2026-11-04): [Alpha Vantage terms](https://www.alphavantage.co/terms_of_service/) grant personal non-commercial access unless otherwise agreed in writing, so a free key does not establish public-service rights. [Investing.com terms](https://www.investing.com/about-us/terms-and-conditions) restrict redistribution; a mapped public page is insufficient. Yahoo/Seeking Alpha permission for this service was not established, so neither is enabled here. [SEC APIs](https://www.sec.gov/search-filings/edgar-application-programming-interfaces) provide submissions and XBRL without API keys, subject to [Fair Access](https://www.sec.gov/about/developer-resources) (identified client, at most 10 requests/second). They are a possible official filing evidence source, not a verified complete SCHD ex-date/amount/payment-date feed. No SEC adapter was added on the assumption that aggregate financial-statement dividends are individual ETF events.

Additional review: [Nasdaq website terms](https://www.nasdaq.com/legal) prohibit capturing site data, so a public SCHD dividend page does not establish an allowed fallback. [EODHD terms](https://eodhd.com/financial-apis/terms-conditions) prohibit personal-license redistribution/display; its documented dividends API therefore needs a suitable agreement before this service can use it. [Financial Datasets pricing](https://www.financialdatasets.ai/pricing) includes redistribution on a paid commercial plan; neither a purchase nor SCHD coverage was validated. [StockAnalysis terms](https://stockanalysis.com/terms-of-use/) allow limited attributed snippets and distinguish compliant crawlers from automated platform use, but do not establish rights to build this service's dividend database. [Slickcharts terms](https://www.slickcharts.com/terms) provide disclaimers without an explicit automated storage/redistribution grant. These candidates remain disabled; no accounts, paid plans, scrapers or private credentials were activated. The remaining next step is a documented source grant plus identity, event-field and historical-coverage validation, followed by a separate publication review.
