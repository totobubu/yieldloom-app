# Roundhill 공시 수집 일정과 휴장 복구

예약 실행은 `.github/workflows/observe-roundhill.yml` 하나로 관리한다.
TOPW·MAGY와 화·수·금 wrapper 및 reusable workflow를 이 파일로 통합했다.
티커·요일·한국시간 기준 시각·조회 범위·복구 한도는
`scripts/content_pipeline/roundhill_schedule.json`에 둔다.
복구 실행기는 YieldMax와 `scheduled_observation.py`를 공유한다. 기존 Roundhill CLI와
상태 파일 경로는 유지하고, 공급자 표식이 없던 기존 상태도 읽을 수 있다.

| 그룹 | 기준 요일·시각 (KST) | 티커 |
| --- | --- | --- |
| topw | 월 22:00 | TOPW |
| crypto | 화 20:00 | YBTC, YETH |
| zero-dte | 수 20:00 | XDTE, QDTE, RDTE |
| magy | 목 20:00 | MAGY |
| weeklypay | 금 20:00 | AAPW, AMDW, AMZW, ARMW, AVGW, BABW, BRKW, COIW, COSW, GOOW, HOOW, METW, MSFW, NFLW, NVDW, PLTW, TSLW, UBEW, UNHW, GDXW, GLDW, TSYW |

## 예약 선택과 DST

- 기준 시각 15분 전부터 30분 후까지 5분 간격으로 해당 그룹만 확인한다.
- 기존 KST 구간을 연중 유지한다. `America/New_York`가 표준시이면 한 시간 늦은
  구간도 추가한다. 이메일 관측만으로 모든 발표가 미국 시각을 따른다고 단정하지 않는다.
- 기준 시각 한 시간 후 재확인하고, 표준시에는 두 시간 후에도 확인한다.
- 별도 복구 실행은 **매일 09:17·12:17·18:17·23:17 KST**에 한다.
  토·일요일과 미국·한국 휴장일에도 실행한다. 긴 대기 작업을 두지 않는다.
- 여름철에 불필요한 겨울 슬롯은 plan 단계에서 끝내며 원장 잠금을 잡거나 외부 자료를 조회하지 않는다.
- 그룹은 `github.event.schedule`과 GitHub 실행의 최초 `created_at`으로 계산한다.
  실행 대기나 재실행으로 실제 시작 시각·날짜가 달라져도 다른 그룹으로 바뀌지 않는다.
  GitHub cron 자체의 지연·누락은 가능하므로 매일 복구 작업이 누락된 주기를 보완한다.
  플랫폼에서 매 실행 시각을 보장하는 구조는 아니다.

## 조기·지연 발표와 공식 날짜

복구 시 기준 발표일 **이전 3일~이후 3일(달력일)** 중 현재까지의 날짜를 조회한다.
미국 영업일을 우선 탐색하되 휴장일·주말도 조회 후보에서 제외하지 않는다.
휴일 달력으로 발표 시각·날짜를 자동 변경하는 방식은 아니다.
이를 통해 월요일 휴장에 따른 전 금요일 발표, 목요일 휴장 전 수요일 MAGY 발표,
발표가 다음 날로 옮겨진 경우를 수집한다. 조기 폐장일에도 수집을 계속한다.

공식 소스의 발표일·배당락일·기준일·지급일·금액을 그대로 저장한다.
한국 휴장은 수집 중단이나 미국 공식 날짜 변경의 근거로 사용하지 않는다.
입금 예상일을 계산하는 한국 영업일 달력과도 분리한다. 금액 없는 예정 캘린더 행은
확정 분배금으로 저장하지 않는다.

날짜 구간은 다음 주 구간과 겹치지 않는다. 다음 주의 새 분배금을 찾았다고 이전 주
미확인 건을 완료 처리하지 않는다. **4일 이상 실제 발표일이 이동하는 예외**는 조회
범위를 벗어난 날짜를 원래 주기에 자동 연결하지 않는다. 미확인 상태를 유지하고 아래 수동 입력으로
실제 공식 발표일과 기준 주기를 지정한다. 같은 공식 발표일이 늦게 게시되는 경우에는
기한이 지나도 원래 날짜 구간을 재조회한다.

이전 주가 미확인인데 다음 주 기준일보다 이른 날짜에서 공시가 발견되면 두 주기 중
어디에 속하는지 단정하지 않고 `needs_review`로 남긴다. 공식 금액·날짜는 공개하되
주기 완료는 보류한다. 수동으로 특정 주기에 연결한 발표일은 인접 주기가 재사용해
완료될 수 없다.

여러 날짜는 하나의 수집 배치로 전달한다. Cboe를 날짜별로 조회한 후 누락 티커만
운용사 공식 JSON으로 확인한다. 같은 티커의 운용사 이력을 날짜마다 다시 받지 않는다.
정상 발표일 한 번에 Cboe에서 그룹 전체가 확인되면 기존처럼 HTTP 1회로 끝난다.
SQLite 공식 원장과 공개 스냅샷의 날짜·금액 등이 모두 일치해야 수집 완료로 판단한다.
일부만 확인되면 그 티커는 공개하고, 이후에는 누락 티커만 조회한다.

## 미확인 건 이월·동시성

`var/content-studio/generated/roundhill-observations.json`에 그룹·기준 주기·실제 확인된
발표일·미확인 티커·마지막 조회 시각을 저장한다. 기존 R2 원장 아카이브에
`generated` 디렉터리가 포함되므로 다음 실행과 다음 주에도 이어서 처리한다.
초기 상태가 없으면 그룹별 직전 기준 주기와 3일 이내의 다음 기준 주기를 만든다.
그보다 오래된 중단 기간은 수동으로 주기를 지정해 복구한다.

일반 복구 한 번에 최대 5개 주기를 마지막 조회가 오래된 순서로 처리한다.
새 주기·미시도 주기도 순환에 포함되어 과거 누락이 최신 수집을 계속 막지 않는다.
2개 미국 영업일이 끝난 후에도 미확인이면 `overdue`로 기록하고 복구 실행을 실패로
표시한다. **실패 표시 후에도 미확인 건을 삭제하거나 완료로 바꾸지 않는다.**
완료된 주기만 28일 이후 정리한다.

NYSE 정기 휴장 규칙과 설정의 `extraUsClosures`를 영업일 계산에 사용한다.
예외적인 임시 휴장은 설정 갱신이 필요하다. 달력이 틀려도 조회를 중단하지 않으며
영향은 지연 경고 시점에 한정된다. 한국시간 아침에 아직 시작하지 않은 미국 영업일을
경과 일수에 포함하지 않는다. 조기 폐장일의 경고 기준은 보수적으로 미국 16시를 쓴다.

원장 복원→조회→저장→공개 커밋 전체는 기존 `content-studio-state-write` 잠금으로
다른 수집기와 직렬화한다. 취소 우선 설정을 쓰지 않는다. GitHub concurrency는
대기 작업을 모두 보장하는 큐가 아니므로 별도 복구 실행이 필요하다.
수집 제한 시간 초과 시 하위 수집 프로세스도 종료하고 미확인 상태를 보존한다.
원장 저장과 스냅샷 검증이 모두 성공해야 공개 데이터를 커밋한다.

## 수동 복구

GitHub Actions의 **Observe Roundhill announcements**에서:

- `group=auto`: 저장된 미확인 건과 현재 확인할 주기를 복구한다.
- `group=crypto` 등 특정 그룹: 해당 그룹만 복구한다.
- `declarationDate`: 공식 자료에 적힌 실제 발표일을 지정한다. 특정 그룹이 필요하다.
- `cycleDate`: 예외적인 장기 이동을 해소할 때 원래 기준 주기를 함께 지정한다.
  예: TOPW의 월요일 주기 `2026-10-26` 공시가 실제로 금요일에 발표되었다면
  `group=topw`, `declarationDate=2026-10-30`, `cycleDate=2026-10-26`.
  이 입력은 저장된 공식 날짜를 월요일로 바꾸지 않는다.

로컬에서 외부 요청 없이 예약 선택만 확인할 수 있다:

```sh
python scripts/content_pipeline/schedule_roundhill.py --plan-only \
  --event-schedule '0,5,10,15,20,25,30 11 * * 2-5' \
  --scheduled-at '2026-10-20T11:05:00+00:00'
python -m unittest discover -s tests/content_pipeline -p 'test_*observation.py'
```

원장·R2 자격 증명은 공개 출력에 포함하지 않는다. 실행별 공시 확인 보고서는
`roundhill-<run_id>` 아티팩트에서 30일 동안 확인한다.
