# 검토·수집·비교 운영

## 관리자 검토

`/admin/metadata`에서 공식 연결, 기존 미검증 연결, 이름 기반 후보와 신규 상품을 확인한다.
Firebase 인증과 서버 관리자 허용 목록을 모두 통과해야 조회·저장할 수 있다.
승인은 공식 근거와 동일한 기초자산만 허용한다. 새 종목은 종목명·거래소·USD 통화 확인도 필요하다.
수정 의견은 재검증 대기로 남는다. 보류·거절·수정 의견은 기존 운영 연결을 삭제하지 않는다.
동시 수정은 revision 충돌로 거절하고, 같은 요청의 재전송은 중복 이력을 만들지 않는다.
검토 근거와 검토자 정보는 공개 내보내기에서 제외한다.

승인은 즉시 검색 자료를 바꾸지 않는다. 평일 08:20 UTC 수집 워크플로 또는 수동 실행에서
`api/security-metadata?action=export`의 승인 자료를 검증하고 등록한다.
`python scripts/metadata/apply_reviews.py --input export.json`으로 파일을 먼저 검증하고,
`--apply`를 추가하면 registry와 catalog에 반영한다. 기존 legacy nav에 없는 승인 종목도
catalog 재생성 시 보존한다. 비교 그룹은 별도 편집 기준을 유지한다.

## 수집 상태와 배포

같은 관리자 화면에서 운용사별 마지막 시도·일부 성공·완전 성공 시점, 오류 건수와 연속 실패를 본다.
이전 정상 연결 수보다 30% 넘게 감소하면 일부 확인 필요 상태가 된다. 성공이 72시간 이상 지연되어도 표시한다.
실패한 수집은 이전 성공 시점과 연결을 지우지 않는다. 초기 상태는 미관측이며 다음 실제 수집부터 기록한다.
오프라인 재감사는 성공 관측 시각을 갱신하지 않는다. 재시도는 화면의 GitHub 워크플로 링크에서 실행한다.

수집 결과가 변경되면 정확한 커밋을 Pages에 전달한다. Vercel은 기존 Git 연동 또는 선택적으로 설정한
`VERCEL_DEPLOY_HOOK` 저장소 secret을 사용한다. 두 사이트의 `app-release.json`에서
40자리 커밋과 catalog·연결·수집 상태의 SHA-256이 모두 일치해야 동기화 검사가 성공한다.
한 사이트가 배포되지 않거나 오래된 자료를 제공하면 워크플로가 실패한다. 자동 롤백은 수행하지 않는다.

## 기초자산 비교와 보유 종목 가정

`/underlying/AAPL`처럼 기초자산 페이지에서 전략·방향·배당주기로 필터링한다.
공식 검증과 기존 미검증 연결을 구분한다. 상세 조회 시에만 총수익률·수수료·가격 하락 자료를 가져온다.
공용 JSON 캐시를 공유하고 최대 4개 네트워크 요청을 동시에 실행한다. 자료가 없으면 미확인으로 남긴다.
총수익률은 제공처 조정 종가 추정 여부와 기간을 표시한다. 가격 하락률은 배당을 제외하며,
분할 검토가 필요한 가격 자료는 계산하지 않는다. 종목별 기준일과 실제 기간을 함께 확인해야 한다.

포트폴리오 인사이트의 보유 종목 가정 비교는 이미 받은 계좌·원장을 사용한다.
같은 통화의 현재 보유 평가액을 시작점으로, 배당 현금 보유·재투자·배당 감소를 비교한다.
월 추가 납입은 선택 종목의 시작 평가액 비중으로 한 번 배분한다. 기존 보유분에는 신규 매수 수수료를 부과하지 않는다.
주간 배당은 연 52회로 계산한다. 배당 지급액·주기·성장률은 사용자가 확인하는 미래 가정이다.
과거 원장의 세후 여부·완전성을 확인한 경우에만 연간 배당금 가정 추정을 허용한다.
기록이 없다는 이유로 배당 0을 가정하지 않는다. 입력 변경·범위 변경·로그아웃 시 결과를 폐기하며,
개인 시뮬레이션 자료는 URL이나 로컬 저장소에 저장하지 않는다.

## 검증

서버 검토 권한·동시 수정·중복 저장·공개 자료 정제, 수집 실패 보존, 신규 종목 보존,
두 사이트 배포 버전 판정, 주간 배당·세금·수수료·통화 격리 및 브라우저 흐름을 자동 검사한다.
브라우저의 관리자·원장 자료는 합성 fixture다. 이 검사는 실제 Firestore 쓰기나 운영 배포 성공을 입증하지 않는다.
