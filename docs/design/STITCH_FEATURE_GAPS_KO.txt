판단 요약
초기 56개에 추가된 인증 전용 시안 7개를 포함해 총 63개를 현재 라우트·서비스·API에 대조했다. 기존 기능과 연결되는 기본 화면은 11개, 공유 작업실에 부분 연결되는 화면은 3개다. 나머지 42개는 신규 기능 42개를 뜻하지 않는다. 공유 카드의 색상·템플릿·출력 비율 대안 17개, 상태 화면, 모바일/데스크톱 쌍이 포함돼 있다.

전체 screen ID별 판정은 같은 폴더 stitch-screen-mapping.json에 기록했다. 키·다운로드 서명 URL·개인 계좌 데이터는 포함하지 않는다.

1. 개인 배당 캘린더·연간 타임라인 — 적용 추천 / P1 / 난도 중간
해당 시안: 08 기본 캘린더 웹·모바일, 연간 타임라인 웹·모바일, 엑셀 등록 반영 캘린더.
현재: /mypage?tab=calendar 에 월간 캘린더·연간 타임라인을 구현했다. 권한 있는 계좌/통화와 지급일/배당락일 필터, 공시 원문·기준일 상세, 공식/검토 필요/주기 추정 구분, 저장된 배당 거래의 별도 조회를 제공한다. 업로드 완료 안내에서 연결한다. 지급일 미확인·일정 미지원 종목은 따로 안내한다.
연결 근거: src/services/thumbnail/dividendSchedule.ts, scheduleVerification.js, src/services/familyPortfolio.js, FamilyPortfolioView.vue의 summary.positions.
구현: 권한 있는 계좌의 보유 티커→티커별 일정 조회→월/연간 이벤트 묶음. 배당락일/지급일을 분리하고 공시 확정·주기 추정을 구별한다. 통화별 예상액을 분리하고 전체 합계로 임의 환산하지 않는다. PrimeVue DatePicker/SelectButton/DataTable/Drawer를 조합할 수 있다.
필요 데이터: ticker, accountId, quantity, quantityAsOf, exDate, payableDate, amount, currency, verificationStatus, sourceUrl. 여러 종목 요청은 동시성 제한·캐시·부분 오류 처리가 필요하다.
핵심 제약: 현재 잔고 수량은 과거 배당락일의 지급 자격을 증명하지 않는다. 잔고 기준일이 다르면 ‘현재 자료 기준 예상’으로 표시하고 실제 수령 기록은 배당 거래 원장에서만 보여 준다. 이력이 없는 달은 0원 지급으로 확정하지 않는다.
완료 기준: 월/연간 전환, 계좌·통화 필터, 부분 누락/추정 이벤트, 서로 다른 자료 기준일, 조회 전용 공유 계좌의 권한, 모바일 리스트를 검증한다.

2. CSV/엑셀 내보내기·엑셀 등록 — 단계적 적용 추천 / P1 / 난도 낮음~중간
해당 시안: 엑셀 일괄 등록·다운로드 모달 3개, 등록 후 대시보드 상태 2개.
현재: 표준 UTF-8 CSV·토스 PDF 업로드, 추출 결과 검토·수정, 중복 검사, 잔고 기준일 대체가 있다. 초기 분석 후 계좌별 CSV 내보내기와 신규 저장·중복·과거 잔고를 구분하는 완료 안내를 추가했다. 표준 및 열 연결 XLSX 업로드를 지원하며 XLSX 다운로드는 제공하지 않는다. 열 연결·인코딩·시트 순번은 브라우저 프리셋으로 재사용하고 헤더 지문 변경 시 재연결한다. CSV는 기존 인증 조회 API를 사용하며, PNG/ZIP은 이미지 공유용으로 구분한다.
연결 근거: FamilyPortfolioView.vue의 preview/commit, api/family-portfolio.py, api/family_portfolio_service.py.
1단계: 현재 접근 가능한 잔고·거래를 표준 CSV로 내보내고 양식/자료 기준일/통화·출처를 포함한다. 전체 계좌번호나 원본 PDF·비밀번호는 내보내지 않는다. 셀 값이 수식으로 해석될 수 있는 입력은 안전하게 처리한다.
2단계: 실제 xlsx 지원 시 라이브러리·라이선스·유지보수 검토 후 파일 크기·시트·행 수·헤더·날짜·소수점·통화를 검증한다. CSV와 같은 검토·중복·권한 검사 경로로 정규화하며 직접 DB에 기록하지 않는다.
핵심 제약: 현행 CSV 200행, PDF 10,000행/200행 배치, 파일 2MB 제한을 xlsx에 자동 적용한 척하지 않는다. xlsx 제한은 압축 해제 크기와 메모리까지 고려해 별도 확정한다. 현재 잔고 등록은 해당 계좌의 전체 잔고 스냅샷 대체 방식이다.
완료 기준: 한글 인코딩, 수식 주입 방지, 재가져오기 정합성, 재업로드 중복, 권한 제한, 대용량·잘못된 헤더 처리. ‘반영 완료’ 상태 UI는 이 확장 없이도 기존 CSV/PDF 성공 상태에 재사용할 수 있다.

3. 공유 카드 템플릿·1:1/16:9/스토리 비율 — 적용 추천 / P1 / 난도 중간
해당 시안: 18 영수증·글래스·월스트리트 다크·골드, 무공백 달성/퍼센트 모드, 피드/와이드 등 17개.
현재: 요약·비교·라이벌·일정·과거 진입 배당률 카드에 1:1(720×720), 16:9(1280×720), 9:16(720×1280) 비율과 기본·페이퍼·네이비 디자인을 적용했다. PNG/ZIP의 파일명·manifest와 프리셋에도 선택이 저장된다. 기존 프리셋은 기본 정사각형으로 호환한다. 공개 링크, 문구 톤도 유지한다. 앱 다크 모드와 출력용 카드 테마는 구별돼 있다.
연결 근거: TickerThumbnailView.vue, components/thumbnail/ThumbnailCardShell.vue, ThumbnailPreview.vue, src/services/thumbnail/publishPackage.js, contentPresets.js.
구현: 동일한 금융 데이터 모델 위에 cardTemplate과 aspectRatio를 추가한다. 1:1/16:9/9:16 출력 치수, 프리뷰 배율, 출력 파일명·manifest, 프리셋 버전을 함께 관리한다. 기존 720×720 기본 출력은 호환 유지한다.
핵심 제약: 스타일 17개는 서로 독립된 금융 기능이 아니다. ‘12개월 무공백’은 실제 검증된 월별 지급 기록이 있을 때만, ‘절세 성공’·달성률은 명시된 목표·계산 근거가 있을 때만 표시한다. 근거 없이 성과를 만들어 내지 않는다. 개인 가족명·계좌·보유액은 기본 공유물에 넣지 않는다.
완료 기준: 각 비율의 잘림/폰트, PNG 치수, ZIP manifest, 다크 앱에서 출력 색상 독립성, 긴 종목명, 데이터 누락, 과장된 성과 문구 방지.

4. 인스타그램 공유 후 안내 — 제한적 적용 가능 / P1 / 난도 낮음~중간
해당 시안: 인스타그램 스토리 공유 완료 팝업·바텀시트 2개.
현재: Web Share가 있는 기기에서 공유 창, 플랫폼 링크, 링크/문구 복사와 파일 다운로드를 제공한다. 인스타그램 게시 API 연동이나 게시 완료 콜백은 없다.
구현: Web Share 파일 지원 여부를 확인한 뒤 이미지 공유, 미지원 기기에서는 이미지 저장·문구 복사·직접 게시 안내를 제공한다. Android/브라우저별 파일 공유 동작을 검증한다.
핵심 제약: OS 공유 창을 닫았거나 파일 다운로드를 시작했다고 ‘인스타그램 게시 완료’라고 표시하면 안 된다. ‘공유 창을 열었습니다’, ‘이미지를 저장한 뒤 게시해 주세요’처럼 실제 확인 가능한 단계만 표시한다. 자동 게시를 원하면 별도의 플랫폼 인증·계정 조건·권한·API 검토가 필요하다.

5. 포트폴리오 종목 직접 추가·수정 — 조건부 적용 / P2 / 난도 중간
해당 시안: 09 종목 추가/수정 모달 웹·모바일 2개.
현재: 자료 업로드 탭에 수동 잔고 입력을 추가했다. 기존 잔고를 입력 표에 채우고 종목·수량·평가액·통화와 새로운 기준일을 받아 기존 검토·검증·저장 경로로 전체 잔고를 저장한다. 출처는 manual-holdings-v1이며 소수 수량·평가액 공란을 지원한다.
범위: 최대 200행, 전체 잔고 확인, 새로운 기준일 입력 또는 사유를 명시한 현재 기준일 정정을 지원한다. 입력·검토 중 잔고 변경은 서버에서 거절한다. 변경 전후 비교와 버전 이력을 제공하며 빈 잔고·한 종목 증분 편집·자동 되돌리기는 제공하지 않는다. 종목은 표준 코드로 입력하며 자동 매핑을 새로 추가하지 않았다.
핵심 제약: 한 종목만 입력했는데 전체 계좌 잔고를 대체해 다른 종목을 지우지 않도록 한다. 거래 추가와 잔고 수정을 구분하고, 기초 보유/입출고가 불명인 상태에서 손익·원금을 자동 확정하지 않는다. 권한·수정 충돌·기록 출처와 되돌리기 정책을 먼저 정한다.
완료 기준: 증분 수정/전체 대체의 구분, 기존 종목 보존, 조회자 수정 차단, 소수 수량, 종목 매핑, 기준일 역행과 동시 수정 충돌.

6. 배당 시뮬레이터·A/B 비교·복리 재투자 — 신규 기능으로 적용 가능 / P2 / 난도 높음
해당 시안: 10 기본·A/B·12개월 재투자 웹/모바일 6개.
현재: 기존 과거 이력 비교에 더해 /simulator 의 순수 계산 엔진·A/B·로컬 가정 저장 UI를 구현했다. 최초 투자, 월 초 납입, 0~360개월, 고정 연간 주당 배당, 월/분기/반기/연 지급, 수수료·원천징수·소수주·주가 변화와 월말 세후 재투자를 지원한다. 단일 통화 명목 모델이며 매도/환율/물가/배당락 가격 조정/ROC/배당 변화는 제외한다.
구현: 순수 계산 모듈에서 최초 투자액, 추가 납입, 기간, 배당 가정, 주가/환율 가정, 세금·수수료, 지급 주기, 재투자 시점을 명시적으로 받는다. A/B는 같은 기준일·통화·세금 가정으로 비교한다. PrimeVue InputNumber/Select/ToggleSwitch/DataTable로 입력·결과를 구성한다.
핵심 제약: 과거 고배당률이 미래에도 유지된다고 기본 확정하지 않는다. 배당락에 따른 가격 변화·분할·ROC·현금·소수주·환전·재투자 시차를 반영하지 않는 경우 그 가정을 표시한다. 회수율과 총수익률을 혼합하지 않는다.
완료 기준: 배당 0, 납입 0, 기간 0, 소수주 미허용, 세금 변화, 수수료, 주기 차이, 손실 시나리오, 재투자 타이밍에 대한 계산 테스트. 결과에 ‘가정 시뮬레이션’을 명시한다.

7. 배당 세무·절세 계산기 및 시뮬레이터 결합 — 제한된 범위부터 / P3 / 난도 높음
해당 시안: 12 계산기 웹·모바일 2개, 10&12 실수령액 비교 1개.
현재: 시뮬레이터의 ‘원천징수율만 비교’에서 A와 B의 투자 조건을 같게 두고 세전·세후 배당·징수 가정액·재투자 자산 차이를 비교한다. 실제 연간 세무·절세 계산 엔진은 없다. 원장에 tax 필드가 있다고 신고 계산이 가능한 것은 아니다.
초기 가능 범위: 사용자가 지정한 주당 배당·수량·원천징수율에 따른 단순 세전/세후 예상 비교. 국가·거주자·통화·적용 시점과 계산 가정을 고정한다.
별도 설계 범위: 조세조약/적용 문서, 외국납부세액, 종합과세, 계좌 유형, 취득·지급·환전 기준, 연도별 ROC 확정/정정, 이월·공제 규칙 등 실제 법규·데이터가 필요한 부분. 미국 개별 주식에 적용할 수 없는 계좌 혜택을 ISA/연금처럼 이름만 붙여 가정하지 않는다.
핵심 제약: ‘절세 성공’, ‘신고 금액 확정’ 대신 예상 비교로 표시한다. 시뮬레이터와 결합은 동일한 세금 모델·버전·가정이 확정된 후 진행한다.
완료 기준: 계산 범위/제외 조건·세율 버전·근거·경계값·반올림·통화·실제 지급 세금과 가정의 구분. 단순 안내를 넘어 실제 세무 계산을 제공하려면 별도 검토가 필요하다.

8. 마이데이터 증권사 계좌 연동 — 선행 조건 충족 후 / P3 / 난도 매우 높음
해당 시안: 11 계좌 연동 관리 웹·모바일 2개.
현재: api/toss-connection.py와 getTossConnectionStatus는 준비 상태를 조회한다. readiness_payload의 enabled는 False이며 실제 고객 OAuth·잔고 동기화 완료를 제공하지 않는다. 현행 개인화 입력은 PDF/CSV다.
필요 조건: 실제 공급자/API 권한과 계약, 고객별 인증·동의, OAuth 상태·PKCE/redirect 검증, 서버 토큰 암호화·만료/갱신, 동의 철회와 삭제, 읽기 전용 권한, 동기화 작업·중복 처리·원본 기준일·오류 재시도·감사 기록.
연결 방안: 공급자 데이터를 기존 계좌·원장·검토 모델로 정규화하되 파일 업로드 출처와 자동 수집 출처를 구분한다. 자동 수집과 수동 잔고가 서로 덮어쓰지 않는 정책이 필요하다.
결론: 디자인만 적용해 증권사 연결 버튼을 활성화할 수는 없다. 공급자 준비 전에는 현재 PDF/CSV 업로드를 진입점으로 유지한다. 연결 준비 상태를 ‘연동 완료’로 표현하지 않는다.

추천 순서
1차: CSV 내보내기 + 저장 완료 상태 보강 + 공유 카드 비율/템플릿.
2차 완료: 권한 있는 계좌 기반 개인 배당 캘린더와 연간 타임라인.
3차 부분 완료: 가정 기반 시뮬레이터와 세전/세후 원천징수율 비교. 수동 잔고 입력은 기존 종목을 불러온 전체 스냅샷 방식으로 구현했다.
별도 프로젝트: 실제 세무 계산·마이데이터 자동 연동. 요구 계약·데이터·운영 범위를 먼저 확정한다.

인증 전용 시안 추가 반영
Stitch MCP에서 추가 인증 시안 7개를 확인해 중앙 카드형 로그인·회원가입, 모바일 안내·비회원 탐색, 비밀번호 재설정 요청·메일 확인·링크 검증·만료·재시도·변경 완료 상태를 연결했다. 로그인 유지 선택은 Firebase LOCAL/SESSION 저장 방식에 반영하며, 회원가입·새 비밀번호에는 확인 입력을 제공한다. 비밀번호 정책은 기존 Firebase 6자 이상 기준을 유지한다. 시안의 동의/마케팅 선택은 저장 계약이 없어 추가하지 않았으며, 실제 서비스·개인정보 안내로 연결한다. 증권사 자동 연동 등 미구현 기능을 홍보하지 않는다.
새 비밀번호 입력 화면은 /login?mode=resetPassword&oobCode=… 링크를 처리하며, 작업 코드는 URL에서 제거하고 컴포넌트 메모리에서만 관리한다. 메일 링크를 이 화면으로 연결하려면 Firebase Console 인증 이메일 템플릿의 작업 URL을 https://yieldloom-app.vercel.app/login 으로 설정해야 한다. 기존 Firebase 호스팅 재설정 링크는 계속 동작한다. 실제 메일 발송·계정 생성 없이 공급자 응답을 대체한 브라우저 테스트로 흐름을 검증했다.

추가 상태 시안이 필요한 기존 기능
가족 권한·파일 추출 검토·수정 충돌/오류·세션 만료 등 실제 제품 상태도 전용 시안이 충분하지 않아 공통 UI와 실제 데이터 계약으로 보완해야 한다.

범위
분류 수와 screen ID 목록은 초기 분석 시점의 대조 결과다. 후속 구현에서 CSV 내보내기, 등록 완료 안내, 공유 카드 비율·디자인과 인증 시안 7개의 상태 흐름을 추가했으며, 매칭 JSON의 implementationStatus/implementationNotes에 해당 시안의 진행 상태를 기록했다. 가정 시뮬레이터·개인 배당 캘린더를 구현했고, 세무는 원천징수율 가정 비교만 제공한다. 수동 잔고는 새 기준일의 전체 스냅샷 입력과 현재 기준일의 사유 있는 정정·변경 이력을 지원한다. XLSX 업로드·열 연결 프리셋·배당 공시/원장 후보 대조와 조건부 계좌 XIRR을 추가했다. XLSX 내보내기·실제 세무 판정·증권사 자동 연동은 미구현이다. 인증 키나 실제 개인 자료를 공유/배포 파일에 포함하지 않는다.
