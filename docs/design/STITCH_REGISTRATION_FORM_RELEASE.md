# 기존 Dialog 등록 폼의 부분 적용

기준 main은 `ebc2ea8de2fbbb0272eb8e417955688b305c69cd`다. 전체 리디자인 #236에서 확인한 등록 폼의 표현만 분리한다. 기존 운영 Dialog, 직접입력 기본값과 방법 순서, 명의자 표시, 계좌/검토/업로드 경로를 유지한다. 새20개 초안과 미완료 전체 화면은 포함하지 않는다.

애플리케이션 변경은 `src/components/portfolio/AssetAccountRegistration.vue` 한 파일이다. 원본은 Stitch 콘텐츠 프로젝트7356929996797649648 / d04aa5557c114ec3a4b4895adc3eb724. 기존 입력·문서 선택·추출 결과·중복 안내·동의·제출을 카드와 반응형 필드로 정리하고, 입력44px·제출180×44px·필수 표시·문서 아이콘과 실제 선택 파일명/크기를 반영한다. 중복 안내 다음에 동의를 배치해 안내를 읽고 확인하도록 한다. 파일 선택에는 이름과 도움말을 갖춘 실제 버튼을 사용한다. 등록/추출 중 비활성 조건과 실제 file input의 change 경로는 유지한다.

기존 script의 AST를 비교했다. 파일 선택용 DOM ref와 방법 표시 문구만 제외하면 원본과 동일하다. 직접입력 기본값·옵션 값/순서·검증·추출 요청·취소/늦은 응답 보호·등록 emit·파일/암호 변경 시 동의 초기화·원문 비밀번호 폐기·중복 판정과 권한 조건은 그대로다. API/서버/계산/권한/데이터는 수정하지 않는다. 새 공개 경로도 없다.

시안은 선택·식별 예시가 채워진 전체 페이지이고 운영은 기존 Dialog다. 전체 페이지 조립·본문 폭이나 예시 금융 값/파일을 복제하지 않는다. 기존 Dialog의 명의자 표시와 직접입력 기본값을 유지하므로 화면 전체 동일함을 주장하지 않는다. 배지는 실제 추출 결과를 뜻하는 `문서 추출 결과`이며 선택 명의자와의 일치나 사용자 동의 완료를 뜻하지 않는다. 누락 항목을 임의 값으로 채우지 않는다.

## 검증 범위

- 기존 운영 Dialog에서 직접입력→등록, 합성 PDF 암호 오류→추출→명의/기관/마스킹 확인→사용자 동의→검토·저장, 중복·재시도/조회전용 권한을 메모리 API로 검증한다. PDF opt-in은 정해진 합성 바이트만 사용하며 실제 고객 문서/DB에 쓰지 않는다.
- 1280/768/390/320 × 실제 테마 토글의 밝음/어두움에서 긴 파일명, 실제 파일 선택 버튼의 Enter/Space, 추출 전 등록 차단, 선택/입력만으로 API 요청 없음, 가로 넘침 없음, Dialog 종료 후 초점 복귀를 확인한다. 유한 애니메이션 종료를 기다린 뒤 캡처한다.
- 브라우저 실패를 조사했다. 일반 HTML에서도 빠른 키 입력 직전의 일회성 filechooser 구독이 간헐적으로 누락됐다. Playwright1.57의 구독 갱신은 비동기다. 페이지 진입 전에 감지를 계속 등록한 동일 대조군은 기본 입력24회와 앱 버튼18회 모두 통과했다. 시간 지연/금융 assertion 완화 대신 감지 설정을 바로잡는다. 취소된 CSS 애니메이션의 finished Promise도 정상 종료와 함께 기다리고 실제 Dialog 표시를 확인한다.
- 설치된 시스템 Chromium154와 프로젝트 Playwright1.57의 Chromium143을 구별하고, CI와 같은 Playwright143도 로컬 검증에 사용한다. 패키지 버전을 올리거나 TLS/프록시/보호 설정을 바꾸지 않는다. [Playwright 브라우저 지침](https://playwright.dev/docs/browsers)을 따른다.
- build/type, lint와 Node 전체 단위 검사를 실행한다. `registration-browser` CI 작업은 기존 suite와 별도 메모리 API/합성 PDF opt-in으로 같은 흐름을 검증한다. 기존 기본 브라우저 작업의 parser 조건은 바꾸지 않는다.

로컬 근거는 `/workspace/stitch-v2-evidence/checks/phase29/`의 partial-script-contract.json, partial-browser-ready.log, partial-*-ready.log와 실제 최신 결과 파일을 따른다. 정확한 원격 CI·Preview·운영 SHA 및 실계좌 미검증은28차 운영과 구별해 최종 체크포인트에 기록한다. 코드 푸시를 운영 배포라고 표현하지 않는다.
