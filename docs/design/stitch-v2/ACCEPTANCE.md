# 원본 대비 검증 기준 및 미통과 목록

현재 판정: **증거 무결성 통과 / 기록된 시각 검토 미승인 / 운영 반영 불가**.

18차 감사에서 이전 `pixelParity: fail`이 상수였음을 확인했다. 현재는 `not-scored`와 기록된 시각 검토를 분리한다. 0/14를 측정된 불량률·개선량으로 해석하지 않는다. [우선순위와 완료 계획](AUDIT_AND_COMPLETION_PLAN.md)을 먼저 참조한다.

## 판정 기준

모든 선택 화면은 다음 기준을 각각 통과해야 한다. 캡처 성공이나 작은 픽셀 차이 비율로 디자인 완료를 대신하지 않는다.

1. 원본: MCP ID·HTML·PNG SHA-256이 대조표와 일치해야 한다. 30개 원본의 무결성을 검사한다.
2. 기기: 콘텐츠14종 각각 PC1280/Tablet768/Mobile390, DPR2를 독립 캡처한다. 이미지 확대/축소를 하지 않으며 콘텐츠 캡처 폭은 정확히 viewport×2다. 셸은 지정된12상태를 별도로 검사한다.
3. 화면 건강: JS 오류·가로 넘침·정적 자산 실패가 없어야 하고 글꼴 로딩 후 캡처해야 한다.
4. 시각: 모든 필요한 요소·위치·간격·글꼴·카드·차트·프리뷰가 검토되어야 한다. 남은 차이가 있으면 미통과다. 픽셀 채널차32 비율은 진단값이며 합격 기준이 아니다.
5. 상태: loading/empty/error/disabled/readonly/중복/검토 상태 등 원본 상태와 전이를 빠짐없이 대조해야 한다. 현재의 화면당 고정 fixture 하나는 상태 전수 검증이 아니다. 원본에서 추출한 상태 문구는 mapping.json의 observedStateLabels에 보관했고 전체 매핑은 아직 미완료다.
6. 기능·자료: 기존 조회·필터·정렬·권한·내보내기·입력 검토를 보존하고 실제 금융 의미·완전성·통화·기간·결측 판정을 바꾸지 않아야 한다. 예시 값을 실제 계산에 넣을 수 없다.
7. 실제 계좌: 합성 로그인/메모리 API와 별도로 실제 인증·권한·개인 이력의 읽기 검증이 필요하다. 이번 테스트는 실제 사용자 세션·운영 DB를 사용하지 않는다.

실행:

```sh
STITCH_EVIDENCE_DIR=/workspace/stitch-v2-evidence node scripts/design/validate-stitch-evidence.mjs
STITCH_EVIDENCE_DIR=/workspace/stitch-v2-evidence node scripts/design/validate-stitch-evidence.mjs --require-parity
```

기본 명령은 증거 무결성만 검사한다. 두 번째 명령은 시각 수용 게이트이며 **현재 의도대로 exit1**이다. 결과는 `/workspace/stitch-v2-evidence/verification.json`에 화면14종·셸12상태별로 기록한다. 원격 CI에는 화면 기능 검증을 추가했지만 로컬의 원본 이미지 비교가 원격 CI에서 실행됐다고 주장하지 않는다.

## 8차 정정 및 구조 복원

이전 원본 렌더링과 PC 비교 폭의 오류를 REFERENCE_CORRECTION.md에 공개했다.54개 정상 원본 렌더링과 같은viewport/DPR의42쌍을 새 기준으로 사용하고 건강/폭 검사를 강화했다. 과거 진단값은 현재 개선률로 사용하지 않는다. 8차의 실제 복원 영역과 화면별 구체적인 미적용 구조는 CURRENT_MATRIX.md 및 REVIEW.md에 기록한다. 캡처 건강 통과와 시각 수용 실패를 계속 구분한다.

Vercel 용량 초과는 통합 채팅에서 보고된 제약이며 이번 작업에서 저장소/할당량을 변경하거나 배포를 시도하지 않았다. 구현/검증이 준비되기 전 배포하지 않는다.29개 미생성 디자인도 생성하지 않았다.

## 10차 현재 판정

전체 명의자/분석2열/비교 조건/캘린더 분할 필터를 반영하고14종42개를 같은viewport와DPR2에서 재비교했다. 소스 예시와 실제 데이터 계약을 섞지 않았다.13개 우선 상태×3폭과 개인 페이지 여백 수정 뒤 등록/요약 상태를 갱신했다. 시각 수용은14종 모두 실패 상태를 유지하며 CURRENT_MATRIX.md의 구체적 잔여 차이를 따른다. 명확히 수정 가능한 선택UI/간격 차이를 금융 의미 충돌로 분류하지 않는다.
