# 21차: 공유 지표 정의와 선택 문구의 실제 동작

공유 원본 `2b8b6a95d49a43a6b0ab02e71556ed0e`의 기존 버튼 전환 상태와 구현을 대조했다. 최근 1건과 12개월 요약은 사용자 선택대로 모두 유지했다. 금융 계산, 공급 이력, 계좌 데이터와 권한은 변경하지 않았다. 운영 배포하지 않았다.

## 발견한 문제와 수정

카드 선택기의 ‘배당 비교’ 설명은 ‘비교군 배당 수익률 대조’였지만 실제 카드는 **같은 종목의 직전·최신 배당 1건**을 비교했다. ‘과거 매수 시점별 배당률’도 설명은 단순 YOC였지만 실제 계산은 표본별 기간의 **세후 배당금/당시 매수가**이며, 출시 초기에는 누적 기간을 별도로 다룬다. 설명과 비교 카드의 맥락 제목을 실제 정의로 바로잡았다.

기능 문제도 있었다. TTM을 제외한 카드에서는 오른쪽 문구가 항상 최근 배당 1건용 `TossCommunityCopy`였다. 배당 비교나 일정을 미리 보면서 다른 의미의 문구를 복사할 수 있었다. 이제 해당 카드의 화면·복사 버튼·개별 PNG 후속 문구·ZIP의 `.txt`가 기존 `cardShareText(kind)` 경로를 공유한다. 원본의 카드 전환에 따라 문구도 바뀌는 동작을 연결했고, 일반 카드 문구 영역에는 원본과 같은 옅은 배경·글자 수·44px 복사 버튼을 적용했다.

최근 1건의 상세 문구와 TTM 전용 문구는 기존 경로를 유지했다. 선택 카드 전체 보기에서는 어느 카드의 문구인지 표시한다. 새로운 비주력 카드 문구에는 지표 기준을 명시하고 날짜를 분리했다. 배당 비교의 두 배당락일, 일정 화면 기준일, 진입 표본의 분석 기준일/집계기간, 라이벌의 공통 비교기간을 구분하며 가격 자료 기준일을 따로 표시한다. 가격 스냅샷 날짜를 모든 지표의 집계기간처럼 쓰지 않는다.

고정 합성 fixture에서는 최근 배당 0.16/기준가격 50에 따른 1회 배당률 0.32%와, 12개월 합계 1.04/가격 50에 따른 연 배당률 2.08%를 그대로 유지했다. 이것은 실제 시장이나 사용자 계좌의 수치가 아니다. 원본의 가상 TTM $2.00·4.00%를 대입하지 않았다.

## 일정과 비교 카드의 시각·상태

일정 카드의 기존 네 라이프사이클 필드, 주간 이동, 연간/월별 이력은 보존하면서 원본 계열의 Hanken 글꼴·12px 모서리·옅은 본문 표면·청록 도구 색을 적용했다. 비교 카드에도 같은 글꼴/표면 계열을 적용했고 이전/현재 수치와 증감 방향은 유지했다. 원본의 단순 세 행을 맞추려고 실제 기준일·국내 입금 예상·추가 이력을 삭제하지 않았다. 이 확장 영역은 여전히 전체 시각 승인 대상이다.

실제 미래 공시 배당락일에도 ‘매수 마감 완료’라고 표시하던 정적 문구를 발견했다. 기존 날짜를 사용해 **공시 배당락 예정 / 배당락일 당일 / 배당락일 경과**로 구분하고, 과거 일정의 제목도 ‘최근 확인 배당 일정’으로 바로잡았다. 날짜나 확정 상태를 만들어 넣지 않았고 매수 가능 마감 시각을 추정하지 않았다. 세 기기에서 예정·당일·경과를 각각 확인했다.

이번 수정에는 사용자 결정이 필요하지 않았다. 이미 승인된 두 요약과 기존 계산을 유지하며 혼동되는 설명·복사 동작을 고치는 범위다. **추가 결정이 필요한 것은 원본과 동일한 새 금융 기능도 별도로 추가할지 여부다.** 원한다면 기존 카드들을 보존한 채 피어 TTM, 현재 세전 TTM 기반 YOC, 지수 추적오차/배당수익률을 별도 기능으로 추가해야 하며, 각 종목·기간·지수의 검증된 자료/완전성 계약이 필요하다. 현재 수치의 이름만 바꾸는 선택지는 없다. 이 범위 결정을 일반 CSS·배치 작업의 차단 사유로 사용하지 않는다.

## 검사와 이력

새 `stitch-share-metrics.browser.mjs`는 세 기기에서 선택한 비교·일정·진입 카드의 화면 문구와 실제 클립보드를 대조하고 ZIP의 비교 카드 `.txt`가 동일한지 확인한다. 톤 변경, 계산 가능한 진입 표본과 자료 부족 표본, 최근 1건·TTM의 원래 문구, 추가 데이터 조회 없음도 검사한다. 날짜/기간의 구분과 일정의 세 날짜 상태도 검증한다. 6개 구현 상태×3폭의18개 캡처는 `checks/phase21/metric-states/`에 있다. 당일·경과 상태는 추가 동작 검사이며 그18개 이미지에 포함된 것으로 세지 않는다.

관련 브라우저10개: 위 새 스위트, 보조 도구, 단일/ZIP 프리뷰, TTM12출력, 기존5종 출력·프리셋/톤, 개별 카드 동작, 종목 상세/일정, 분할 이력의 배당 비교20사례, 진입 카드, 월별 공유 이력. 관련 단위44개, build/type, lint를 실행했다. 마지막 결과는 `focused-results.json`과 로그를 따른다. 원격 CI에는 새 스위트를 추가했지만 실행하지 않았다. 기본 CI 구성46개(별도3+보강7 포함 총56개)의 전수 재실행이나 실계좌 검증으로 표현하지 않는다.

처음 새 검사에서 기존 합성 fixture를 ‘진입 지표 자료 부족’이라고 가정했으나, 해당 fixture는 완전한24개월 자료가 있어 계산 가능한 상태였다. 계산 코드를 바꾸지 않고 계산 가능한 표본과 별도의 짧은 이력 표본을 나눠 검사했다. 최초 실패는 `metric-fixture-first-attempt.log`에 보존했다. 기존 분할 검사의 텍스트 기반 체크박스 탐색은19차 이후 DOM과 맞지 않아 실제 접근성 이름으로 수정했으며, 분할/누락/0/일반·다크/추가 조회 기대값은 유지했다.

전체 화면 시각 수용, 다른 카드의 세부 배치, 실제 인증/계좌/PDF 등록·운영 DB·원격 CI·배포는 미완료다. 추가 팝업 원본 부재와 미생성29종의 범위도 그대로다. 부분 검증을 전체 디자인 완료로 올리지 않는다.

선택 카드의 실제 화면 대조에서 추가 표시 결함을 확인했다. PrimeVue 텍스트 버튼의 hover 배경이 선택 타일의 청록색을 가려 흰 글자가 거의 보이지 않았다. 선택 버튼의 배경을 투명하게 유지했고, 선택 순간 글자색의200ms 전환에서도 대비가 낮아지는 것을 확인해 해당 상태의 색 전환만 즉시 적용했다. 원래 실패3.07 대비값은 `hover-color-transition-first-attempt.log`에 남겼으며, 수정 후 실제 버튼/부모 배경을 합성한 글자 대비가hover와키보드포커스에서각각4.5이상인지3폭검사한다. 선택 배경만 보고 정상으로 판정하지 않는다.

최종 관련10개 통과 후 마지막 선택 표시 수정에 대해 공유 지표/클립보드/ZIP 스위트와 프리뷰/PNG 스위트를 다시 통과했다. 단위44개 통과, build/type 통과, lint오류0·경고54개다. 경고 수가 이전67개에서 줄어든 것은 수정한 비교 컴포넌트의 포맷 정리를 포함하며 금융 알고리즘 변경이 아니다. 구현18상태의 전체/콘텐츠 캡처와3개 비교문구의 화면/실제클립보드/ZIP텍스트JSON을 보존했다. 기존원본onclick15상태는20차카드crop에대응하는동일상태의전체문구화면을추가했으며새15상태로중복계수하지않는다.
