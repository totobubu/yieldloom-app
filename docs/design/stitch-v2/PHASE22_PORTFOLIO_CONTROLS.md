# 22차: 분석 필터와 배당 캘린더 도구

미정인 공유 금융 지표와 독립적인 UI만 수정했다. 분석 원본 `2e3c6628d6c74eafa277d9f07d60fc57`, 캘린더 원본 `fc276eb9388a48909296fb018f60771b`의 실제 HTML/PNG를 사용했다. 최근 1건과 12개월 카드, 금융 계산과 API 계약·권한은 보존했다. 새 지표를 기존 수치로 대체하지 않았다. 사용자 선택 범위와 필요한 자료는 [지표 결정 요약](METRIC_DECISION_SUMMARY.md)에 분리했다.

## 수정한 차이

분석 제목은 원본의 h1·20px/30px로 맞추고 부제는 실제 선택 월을 표시한다. 필터의 PC/Tablet `2fr 1.2fr 1.2fr auto`, 6px 라벨 간격·13px/600 라벨·44px 입력/새로고침을 복원했다. 변경 전 Tablet은 두 열이었고 Select는 약53px, 새로고침은50px였다. Mobile은 원본대로 한 열이다.

Tablet 실측에서 기본 브라우저 월 입력의 영어 연도가 잘렸다. 설치된 PrimeVue 4의 월 선택기를 사용해 `2026년 11월`로 표시한다. 컴포넌트 경계에서 로컬 연·월을 기존 `YYYY-MM`으로 변환하며 UTC 변환을 거치지 않는다. 기존 현재월 이하 제한·1900년 최솟값을 유지한다. 월 변경은 기존 메모리의 장부를 재투영하며 별도 조회를 추가하지 않는다. 실제 장부를 변경하지 않는다.

캘린더 제목은 원본의 ‘배당 캘린더’·20px/30px로 맞췄다. 원본의40px 모드 버튼,38px 기간 도구·8px 간격과 안쪽 여백을 복원했다. ‘이전/다음’ 문구와 실제 ‘오늘’ 이동을 연결했다. 임의 월 직접 입력과 기존 월/연간 이동은 그대로 유지한다. 오늘은 기존 calendarToday 기준의 현재 월을 선택하며 새 데이터·상태를 만들지 않는다.

## 비교 범위와 남은 차이

`checks/phase22/{before,after,localized,verified}`에 실제 측정과 캡처를 보존한다. 최종 `verified`는1280/768/390·DPR2이며 원본과 구현의 동일 viewport/font-ready 상태를 사용한다. 기본6개 콘텐츠 캡처를 갱신하고 기존42개 진단 비교를 다시 만든다. 차이 픽셀 비율은 합격률이 아니다.

초기 측정기는 원본 캘린더의 안쪽 `.mode-row`를 구현의 외곽 `.calendar-navigation`과 비교했다. 최종 측정은 원본 `.card:has(> .mode-row)` 외곽을 사용한다. 이전 원시 기록은 삭제하지 않는다. 분석 필터도 원본 `.filter-grid`는 안쪽이고 구현 `.insights-filters`는 패딩/테두리를 포함한다. 최종 JSON의 `contentHeight`로 동일 내용 영역을 비교한다. 라벨 노드의 높이는 원본 텍스트 단독과 구현 입력 포함 label이므로 직접 비교하지 않는다.

외곽 슬롯 폭, 안내 문구, 실제 계좌 선택지와 KPI/표의 데이터가 원본 가상 예시와 다르다. 캘린더 Mobile 기간 도구는 임의 월 입력을 보존하므로 원본의 한국어 읽기 전용 날짜 문구와 달리 브라우저 기본 영어 월 표시·구조·높이가 남는다. 원본 오늘 버튼의 날짜는 접근성 이름에 표시하고 좁은 화면의 가시 문구는 ‘오늘’이다. 전체 화면 시각 승인을 주장하지 않는다. 원본이 없는 팝업이나 미생성29종을 생성하지 않았다.

## 검증의 해석

새 브라우저 검사는 세 폭과 UTC/서울/로스앤젤레스에서 월 표시·기존 KPI·현재월 제한·오늘/이전/다음·추가 읽기/쓰기0·오류/넘침0을 확인한다. 기존 분석 회귀의 월 입력 조작만 한국어 표시와 실제 키보드 Tab 방식으로 변경했으며 계산/격리/취소 차감의 기대값은 유지한다.

최초 새 검사에서는 DatePicker 팝업의 modal 접근성 상태 때문에 region 역할을 다시 찾는 Tab 조작이 실패했다. 물리 키보드 Tab으로 바꿨다. 이후 미래월 제한을 라이브러리에 없는 aria-disabled 속성으로 검사해 실패했다. 설치된4버전의 실제 data-p-disabled 속성을 검사한다. 두 실패는 로그로 보존하며 금융 제품 결함으로 둔갑시키지 않는다. 기존 분석/캘린더 회귀는 잘못된5173 실행 주소로 접속 실패한 첫 로그를 보존하고 올바른5175로 재실행한다.

최종 테스트 수와 측정값은 아래 결과 및 phase22 manifest를 따른다. 전체 브라우저 재실행·원격CI·실제 계좌 인증/PDF/DB·전체 시각 승인·배포는 수행하지 않았다. 마지막 전체 회귀 기준은17차다.


최종 실측: 분석 필터의 내용 높이는 원본/구현 모두 PC69.5px·Tablet89px·Mobile300.5px다. Select·월 입력·새로고침은44px이며 제목은30px다. 캘린더 도구 외곽은 PC76px·Tablet126px로 원본과 같고 Mobile은 원본229px/구현224px로5px 차이가 남는다. 전체 높이를 가짜로 맞추려고 실제 입력을 삭제하지 않았다.

최종 관련 브라우저7개(새3폭/3시간대, 기존 분석, 기존 캘린더, 우선 패널, 데이터 계약, 콘텐츠 폭, 셸)와 단위26개가 통과했다. 우선 패널39상태와 셸12상태를 다시 기록했다. build/type 통과, lint오류0·경고54개다. 기본CI47개·별도3개/보강7개를 포함한 총57개는 구성 수이며 이번 전수 실행 수가 아니다. 증거 무결성은 통과하되 엄격 수용 게이트는 exit1로 유지한다.
