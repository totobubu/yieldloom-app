# 25차: 포트폴리오 요약의 평가 카드와 반응형 명세

원본 `008f9456b8c643d0b9f41957447b9afc`의 실제 HTML/PNG를1280/768/390·DPR2로 대조했다. P1-C의 요약 영역을 수정했다. KRW/USD 독립 합계·시세 제외/기간/추정·조회 범위·권한은 보존하고 금융 계산 서비스는 변경하지 않았다. 미정 공유 지표나 새 화면은 구현하지 않았다.

## 원본에 근거한 변경

원본은 md768px부터 두 평가 카드를 나란히 놓지만 구현은1024px 이하부터 한 열이었다. 경계를767/768로 맞췄다. 카드padding24px·gap24px를 모든 폭에서 복원했고 제목16px/24px/600과 저장 금액JetBrains Mono24px/32px/600, 참고 금액Mono24px/32px을 적용했다. 기존 저장 금액 줄 높이는40.8px였다. Tablet의348px×2열, Mobile358px×1열은 원본과 같다. PC는 공통 셸의984px 슬롯 때문에480px×2열이고 원본 단독 콘텐츠는596px×2열이다. 이 기존 조립 제약은 원본을 축소하거나 셸 폭을 임의로 바꿔 숨기지 않았다.

기존 자산 화면에서 사용하는 formatStoredAmount를 재사용해 ₩190,000/$1,430.00 형태로 표시한다. ISO 통화/통화별 독립성·최대8자리 소수와 미확인 처리는 기존 유틸리티를 따른다. 환산이나 금액 계산 변경이 아니다. 기존 자료/종가 기준일·차이·부분 집계와 주의문은 유지한다. 최근 종가 카드의 수치가 원본처럼 설명보다 먼저 보이도록 주의문의 위치를 옮겼으며 로딩/오류 때의 설명도 유지한다.

명세는 기존 데이터의10열 PC표와1024px 미만의 레이블 카드로 조립했다. ‘종가’와 ‘시세 기준일/출처’를 분리하고 원본 순서인 계좌→종목→통화→수량→저장값→잔고일→종가→시세일→참고값→상태를 사용한다. 실제 명의자 이름은 상위 화면의 기존 ownerName과 허용된 계좌/마스킹 정보만 재사용한다. 원본의 가상 ‘편집 가능/소유자/조회 전용’ 권한 문구를 임의로 복사하지 않는다. 실제 평가 제외 사유·수량 유지 가정·추정 표시는 보존한다.

좁은 화면의 카드에는 저장 자료 평가액/잔고일과 참고 평가액/종가·기준일을 두 열로 표시하며 출처·30일 초과·추정과 제외 사유도 남긴다. 통화/수량/기준액0은0으로 보존하고 미확인 값은—/미확인으로 구분한다. 기존10행 페이징을 PC와 Mobile에서 공유해 화면 폭 전환으로 선택 페이지가 바뀌지 않는다. 계좌 범위나 원본 positions 변경 때만 첫 페이지로 초기화한다. 새 fetch나 사용자 데이터 쓰기를 추가하지 않았다.

## 검증과 증거의 범위

`checks/phase25/{before,before-corrected,after,verified}`에 원본/구현3쌍의 실측과 캡처를 보존한다. 최초 원본 selector는 main 바로 아래로 잘못 한정해 일부 null이었으므로 실제 래퍼를 포함한 before-corrected를 기준으로 한다. 금액 폰트 등의 확인된 속성은 초기 기록에도 유효하지만 null을 차이 측정으로 취급하지 않는다.

새 명세 검사는3폭에서10열 또는3개의 레이블 카드·독립 합계·시세 미확인 제외·계좌 범위·추가 조회/쓰기0·오류/넘침0을 확인한다. 별도12행 합성 자료에서0인 저장액/0수량의 실제0평가액/미확인 시세—, PC/Mobile 페이지 공유를 검사한다. 첫 페이지 버튼 조작은 PrimeVue의 실제 한국어 접근성 이름이 ‘페이지 2’인데 ‘2’로 찾아 실패했으며 라이브러리/제품 기능을 바꾸지 않고 검사 이름을 수정했다. 최초 실패는 보존한다. 통화 표시를 검사하는 기존 데이터 계약의 기대 문자열도 같은 금액의 새 표시 형식으로만 변경했다.

실제 개인 계좌가 아닌 기존 고정 합성 fixture와 격리 메모리 API 검사다. 시각 비교는 원본 수치를 실제 수치로 바꿔 맞추거나 미확인 시세를0/예시값으로 채우지 않는다. 전체 브라우저/원격CI·실계좌 인증/DB/PDF·시각 수용과 배포는 미완료다. 최종 검사 수와 차이는 아래 기록 및 checkpoint manifest를 따른다.

## 남은 차이

원본 카드의 정적 예시에는 없는 실제 기준일 범위/추정 경고·통화 독립 설명·비교 가능한 항목수·자료 평가액 대비 차이를 유지하므로 전체 카드 높이가 다르다. 제목 옆 가상 배지와 원본의 가상 편집권한도 그대로 복제하지 않았다. 선택/빈 상태/오류/12행 페이징의 별도 원본 프레임은 검증된 원본 목록에 없어 구현 합성 상태 검증으로 구분한다. PC 셸의984px 조립 폭과 단독 원본1216px 차이도 남는다. 필터는 실제 기존 계좌 범위 선택을 보존하며 원본의 다중 명의자 체크박스를 새로운 기능으로 위장하지 않았다. 미생성29종·원본 없는 팝업은 만들지 않았다.


Tablet 이미지 검수에서 참고 금액이 부모의 overflow-wrap:anywhere를 상속해 끝자리가 다음 줄로 밀리는 문제를 확인했다. 원본의 실제 computed 스타일은 저장/참고 모두Mono이며 저장600, 참고 완전집계700/부분600이다. 처음 Hanken으로 해석한 설명을 정정한다. 참고 금액도Mono로 유지하고 원본의 줄바꿈 없는 표현처럼 오른쪽 내부 여백을 활용한다. 긴 실제 값은 값 영역 안에서 가로로 읽을 수 있다. 부분 합계는 중립색으로 표시했다. 기본 자료의 실제 글자 폭+letter-spacing이 사용 가능한 폭에 들어가는지3폭 검사에 추가했다. 부분 상태 binding의 누락도 새 검사가 잡아 실제 DOM에 연결했다. 최초 실패 로그는 partial-binding-first-attempt.log에 보존한다.

기존 메모리 API 고도화 검사는22/23차에 바뀐 월 입력의 옛 이름/형식을 사용해 분석·캘린더 단계에서 각각 실패했다. 현재 한국어 이름/형식과 실제 키보드 Tab으로 조작만 수정했다. 원장 수정/이력·XIRR 초기 가정 해제·배당 대조/기간·추가 조회 수·로그아웃 기대값은 유지했다. 실제 사용자 자료를 변경하지 않고 격리 메모리 API의 합성 계정으로만 수행한다. 실패 로그 두 개를 보존한다.


원본의 누락·추정·제외 자료 경고는 평가 카드 안이 아닌 명세 아래 별도 검토 영역이다. 기존 두 경고를 그 위치로 옮기고 실제 문구/항목 수는 그대로 보존했다. 원본의 ‘확인 필요2건’을 실제 확인 없이 복제하지 않고 ‘확인 필요’로 표시한다. ‘자료 검토 상세 진입’은 연결할 별도 원본/기능이 확인되지 않아 비활성 더미 버튼으로 두고 ‘별도 검토 화면 미구현’ 및 위 명세에서 사유를 확인할 수 있음을 표시했다. 팝업이나 검토 결과를 만들지 않았다. 시세 재조회/계좌 범위/페이지 입력은 계속 작동한다.
