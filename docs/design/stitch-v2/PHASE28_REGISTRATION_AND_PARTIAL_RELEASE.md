## 계좌 등록: 원본이 있는 제어만 수정

원본은 콘텐츠 프로젝트 `7356929996797649648`의 `d04aa5557c114ec3a4b4895adc3eb724.html`이다. 원본은 PDF 선택·식별·중복 예시가 이미 채워진 상태이고, 앱의 초기 상태는 빈 파일·미식별이다. 합성 선택 상태와 빈 상태를 각각 남기고 식별 완료나 계좌 값을 강제로 채우지 않는다.

- 비밀번호·공통 입력: 실제 높이50→44px, 글꼴16/400→14/500, padding0/14px. Select 루트44px·8px 모서리와 라벨 높이도 한정 보정한다. 처음 측정한 `#registration-type`은 내부 라벨이었으므로 이를 Select 루트 치수로 보고하지 않는다. 최종 측정은 `.registration-field .p-select`다.
- 제출: 약97.4×50px(모바일 가로 확장)에서 원본180×44px·14/600·8px 모서리·오른쪽 정렬로 복원했다. 추출 버튼도44px다. 각 필드 라벨은13/19.5px·600으로 맞췄다.
- 업로드:28/42px 문서 아이콘과 실제 선택 파일명·크기, 실제 지원 한도2MB 안내를 표시한다. 기본 file input은 영역 안에 유지하고 키보드/클릭을 모두 지원하며 포커스를 표시한다. 드래그 기능을 표시하거나 추가하지 않았다. PC/Tablet 선택 영역152px, 동일 합성 파일명/크기의 Mobile 선택 영역194px로 원본과 일치한다. Mobile 빈 상태171.5px는 파일명 한 줄과 두 줄의 차이다. 선택 검증용 바이트는 합성0바이트 버퍼이며 실제 PDF 추출 증명이 아니다.
- 원본의 필수 표시를 복원하되 원래 라벨명과 native required 계약은 유지한다. 처음 텍스트 별표가 정확한 라벨 선택을 깨뜨려 기존 상태 검사가 실패했다. aria-hidden 빈 span의 표시로 수정한 뒤 기존 정확한 라벨과 동작 검사를 통과했다. 테스트의 기대 라벨을 느슨하게 바꾸지 않았다.
- Mobile 문서에 겹친16px 안쪽 패딩을 제거하고 등록 카드24px 패딩은 세 폭에서 원본대로 유지한다. 실제 Mobile 본문 슬롯 때문에 필드308px 대 독립 원본316px 차이는 남는다. 원본 전체와 동일하다고 판정하지 않는다.

동작의 script, 서버 API, 금융 계산, 권한, 계좌 생성 계약은 변경하지 않았다. 파일/암호 변경 시 식별·동의 초기화, 추출 대기 중 비활성, 중복·조회전용 권한과 기존 업로드 진입을 보존한다.

## 검증과 범위

`/workspace/stitch-v2-evidence/checks/phase28/registration-final/`에 원본3장, 초기3장, 합성 선택3장과 속성 측정을 보존한다. 측정과 상태 검사는 원본을 수정하지 않고 같은1280/768/390, DPR2에서 수행한다. 오류·정적 자산 실패·가로 넘침0이다. 상태 브라우저는 세 폭×10상태를 확인하고 합성 식별 요청만 사용한다. 파일 선택은 실제 native chooser를 키보드 Enter와 영역 클릭으로 열어 확인하고 대기 중 disabled를 검사한다. 등록/원장 저장은 하지 않는다.

상태 검사의 정적 자산 핸들러를 fixture 차단기 뒤에 등록해 실제 승인된 글꼴 경로가 가려지지 않도록 했다. fixture API 격리는 유지한다. focused 상태 검사, build/type, lint를 실행하며27차 전체 회귀 및 해당 최종 원격 CI와 구분한다. 원격 CI는 이 변경의 푸시 후 별도 결과를 기록한다.

미해결: 등록 상태 배너/중복·동의/제출 전후 간격, 선택 영역의 다른 실제 파일명 줄바꿈, 기존 관리 화면 조립 및 전체 셸/14종 수용. 실제 관리자 계좌와 고객 PDF의 추출·등록은 검증하지 않았다. 등록 변경은 이번 공개 부분 운영 범위에 포함하지 않는다.
