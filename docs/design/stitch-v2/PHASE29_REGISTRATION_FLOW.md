원본 d04aa5557c114ec3a4b4895adc3eb724에서 입력→중복 안내→동의→제출의 순서와 실제 간격을 측정했다. 구현은 동의가 안내보다 먼저 나오고 Message 아래 여백이12px 추가돼 있었다. 문서/공통 입력/안내/동의/제출을 별도 영역으로 조립해 임의의 고정 y위치나 음수 내부 간격으로 맞추지 않았다.

같은 파일명/크기와 합성 반환 식별 정보를 사용한 제한된 구조 대조다. 다섯 간격은 세 폭 모두 방법→업로드20px, 추출 영역→입력24px, 입력→안내20px, 안내→동의10px, 동의→제출24px다. Mobile 등록 페이지의 본문 여백을16→12px로 맞춰8px 폭 차이를 없앴다. 원본의 기본24px 카드 패딩은 유지한다. 실제 계좌/문서 값을 가짜로 바꾸지 않았다.

문서 방법 표시 문구를 원본대로 보완했고, 실제 추출 요약에 기관·명의·마스킹을 분리해 표시한다. 배지는 `문서 추출 결과`로 표시해 원본의 식별완료 예시를 선택 명의자 일치·사용자 동의로 오해하지 않게 한다. 비어 있는 식별 항목은 확인 필요로 남긴다. 동의는 계속 명시적 체크가 필요하며 파일/암호/방법 변경 시 기존 규칙대로 초기화한다. 중복 경고는 실제 입력 기관/끝자리와 기존 권한 있는 계좌만 사용하고 조회전용 업로드 버튼은 비활성이다. 긴 이름/파일명은 잘라내거나 가짜 짧은 이름으로 바꾸지 않는다.

파일 선택 영역은 명시적인 버튼과 기존 file input으로 연결했다. 키보드 초점, 실제 파일명/지원 안내의 접근 가능한 설명, Enter/Space·클릭, 추출/등록 중 비활성은 검증한다. UI용 DOM ref와 방법 문구 외의 script와 API/계산/권한은 바꾸지 않는다.

검사 과정의 두 문제를 구분한다. 첫 배너 측정은 Message enter transition 중 높이0을 읽었으므로 폐기하지 않고 별도 unsettled 폴더에 남겼다. 최종 측정은 전환 종료를 기다린다. 파일 선택창은 일반 HTML 대조군에서도 간헐 누락됐고, Playwright의 비동기 구독을 페이지 진입 전에 등록한 동일 대조군은24회 및 앱 버튼18회 통과했다. 금융 검증을 줄이거나 임의 sleep/자동 재시도로 넘기지 않는다. 시스템 Chromium154와 CI용 Chromium143도 구별한다. 취소된 CSS animation.finished는 allSettled로 기다리며 실제 Dialog의 표시/종료 확인은 유지한다.

최종 기능 상태30개, 메모리 API의 합성 PDF 검토/저장, build/type/lint 및 원격 전체 CI는 체크포인트의 정확한 커밋에 연결한다. 원본·구현3쌍과 최초 실패/후속 결과는 `/workspace/stitch-v2-evidence/checks/phase29/`에 보존한다.
