# 8차 원본 비교 기준 정정

이전 비교에는 두 결함이 있었다. 원본 HTML/PNG 파일 자체의 SHA는 유효하지만, 이전 렌더링 및 차이 진단값을 정밀 비교 근거로 사용하지 않는다.

1. `https://cdn.tailwindcss.com/`은 이 환경에서 HTTP200·본문0byte로 관측됐다. 기존 자산 도구는 이를 성공으로 취급했다. Tailwind 원본의 `tailwind is not defined` 오류와 reset만 적용된 캡처를 재현했다. `https://cdn.tailwindcss.com/3.4.17`의407279byte 공개 런타임으로 렌더링하고 빈 자산 응답은 실패로 처리한다. MCP 원본 HTML에는 손대지 않았다. 각 화면·viewport에 새 브라우저 페이지를 사용한다.
2. PC 비교는 수신한 원본 PNG를1280CSSpx·DPR2의 구현 PNG와 직접 대조해 실제 픽셀 폭이 달랐다. 수신 PNG는 원본 증거로 보존하고, 이제14종의 세 기기 모두 원본 HTML을1280/768/390CSSpx·DPR2로 재렌더링한 기준과 비교한다. 원본/구현 폭이 각각 viewport×2가 아니면 비교를 실패시킨다.

`capture-stitch-originals.mjs` 결과54개(콘텐츠18레코드×3기기)는 스타일·JS 오류·자산·fonts.ready 상태를 검사한다. `rendered-originals/results.json`을 검증기에 연결했고, 적용 대상42개에 각각 유효한 원본 렌더링이 하나씩 있어야 한다.

원본 공유 화면390px는399px, 이전 분석 대안390px는401px 가로 넘침이 있다. 원본 CSS를 고치거나 축소하지 않고 viewport 폭으로 캡처하며 원래 scrollWidth/overflow를 기록한다. 수신 원본 PNG와 HTML 자체는 그대로 보존한다. 이 가로 넘침을 구현에 복제하지 않는다.

각 비교는 같은viewport·DPR이지만 독립 콘텐츠 원본과 공통 셸에 조립한 구현이다. 개인 화면의224px 메뉴와 셸 본문 오프셋은 별도 조립 검토 대상이다. 그 차이를 이미지 스케일링으로 숨기지 않는다. 원본의 예시 수치와 미리 선택된 식별·일정 상태 역시 실제 서비스의 빈 상태·실제 값으로 대체할 수 없으므로 구별한다.

현재 차이 비율은 전체 진단값이며 유사도/합격률이 아니다. 이전 단계와 수치가 직접 비교되지 않으며, 새 기준으로 화면별 남은 요소·간격·상태를 검토한다. 모든14종의 시각 수용은 여전히 미통과다.
