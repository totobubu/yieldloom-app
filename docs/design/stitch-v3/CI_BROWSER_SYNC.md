# 환전 메모 저장 브라우저 검증 동기화

영수증 계약 수정 work `e35a2d4`의 CI 41996599869 최초 실행은 cash-fx-links.browser.mjs의 메모 저장 직후 f.read에서 일반 오류로 실패했다. 재실행은 같은 단계 뒤 Mobile K2 환전 짝 선택을 찾지 못해 실패했다. 원래 로그에 상태 코드가 없으므로 최초 응답이 503이었다고 단정하지 않는다. 같은 tree의 feature CI41994691239는 네 작업이 통과했고, 수정 전 로컬 PC/Mobile 흐름은 3회 연속 통과했다. 합성 fixture에 GET 두 개를 동시에 보낸 별도 실험에서는 200과503 CAPITAL_READ_MODEL_BUSY가 나왔다.

기존 테스트의 메모 버튼 click→main aria-busy=false 대기는 저장 POST가 끝나 refresh를 emit하기 **전의 false**도 통과시킬 수 있었다. 실제 브라우저 후속 조회와 f.read 직접 검증이 경쟁하거나 다음 요소를 조회 중에 찾는 순서를 허용했다. 제품·금융 저장·조회 모델·권한은 고치지 않는다.

테스트를 저장 POST200→후속 GET 시작/aria-busy=true→GET200→aria-busy=false 순서로 기다리게 고쳤다. 후속 GET을 명시적 Promise로 잠시 보류해 로딩 중 상태를 결정적으로 검사한 뒤 해제한다. 임의 sleep/실패 무시/재시도로 통과시키지 않는다. fixture 실패는 상태 코드와 안전한 오류 코드만 포함해 다음 실패를 진단할 수 있게 했다. 본 테스트는 모든 계좌·원장·권한을 기존 합성 메모리 fixture 안에서만 다루며 원격 쓰기는 없다.

수정 후 PC1440/Mobile390 전체 환전 시나리오(선택/양쪽 승인·메모·재시도·분리·읽기 권한·늦은 계좌 응답·다크) 각3회 통과. 두 변경 테스트 파일 eslint 통과. 앱/서버 구현 변경이 없으므로 별도 앱 빌드를 반복하지 않았다. 원격 CI 결과는 이 수정의 정확한 head로 확인한다. 운영 승격 #254는 실패를 해결하기 전 닫았고 최종 CI가 통과한 work로 새 승격을 준비한다.
