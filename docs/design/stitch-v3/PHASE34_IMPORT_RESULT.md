# 저장 결과 영수증 후속 구현

기준은 열 연결 수정 head `f252746`이다. 열 연결의 운영 승격 #249와 분리한 후속 작업이며 **이 화면의 최종 시각 승인·운영 배포는 아직 하지 않았다.** 최종 원본은 Tablet `cf7686fbb620465f93418fde1572a6cc`, Mobile `f5a2132c4e234e648269220f0e889387`이다. 새 PC 원본은 없다.

## 실제 데이터와 동작

- 기존 commit의 검증·권한·중복 판정·저장·계산을 유지하고, 이미 판정한 행에 `rowResults`를 추가한다. 정규화된 저장 값의 날짜·종목·유형·수량·금액·통화·고유번호만 반환하며 추가 조회·쓰기·고객 정보 저장은 없다.
- 과거 영수증 재처리는 행별 원문을 보관하지 않는다. 이 경우 제출된 값을 저장 사실로 표시하지 않고 기존 건수만 반환한다. 어느 배치라도 행별 응답이 없거나 건수와 다르면 클라이언트는 전체 상세를 미제공으로 안내한다.
- 계좌 목록 갱신 실패·로딩·준비 상태를 구분하고 기존 refresh를 명시적 재시도로 재사용한다. 목록이 준비되기 전에는 기존대로 계좌/캘린더/CSV를 잠근다. 추가 등록은 유지한다.
- CSV는 기존 계좌 전체 내역 내보내기다. 시안의 영수증 전용 CSV라고 잘못 표시하지 않는다. 실제 입력 파일명은 검토 상태에서 영수증까지 세션 메모리로만 전달하며 없으면 미제공으로 표시한다.
- 행별 필터·50행 단위 로컬 페이지 이동은 추가 API 요청이 없다. 신규 저장은 현재 잔고 채택이나 금융사 확인이라는 뜻이 아니며, 과거 잔고의 보관 의미도 기존 설명대로 유지한다.
- 통화별 신규 건수와 해당 거래 유형만 실제 서버 결과에서 표시한다. 매수/매도 합계·입출금 순액·배당 입금액은 정의/산출 계약이 없으므로 **미제공**이다. 가상 합계·0·환율·세전/세후를 임의로 만들지 않는다.

## 검증

- API 6개 모음 63개 통과: 권한, 검토/저장, 중복/재처리, 정정, CSV, CORS. 섞인 신규/중복의 각 결과를 실제 저장 행과 대조한다.
- 변경 전/후 동일 합성 요청을 비교해 저장 행·잔고 버전·건수·문서 읽기 횟수가 동일했다. 신규 11회, 부분 중복 8회, 영수증 재처리 5회(관측 테스트 수치이며 실제 청구량이 아님). 해당 읽기 수를 기존 회귀 검사에도 보존했다.
- `capture-import-result.mjs`: 5개 폭, 준비/갱신 실패/재처리, 필터, 101행 페이지, 0/소수 정밀도, 다크, 런타임 오류 0, API 요청 0 검증.
- 기존 실제 합성 XLSX/CSV→검토→메모리 저장→결산 저장/조회/삭제 검사 통과. 새 영수증의 저장 종목/수량/금액/파일명을 실제 응답에 대조한다. 고객 계좌·실제 PDF는 쓰지 않았다.
- 최초 통합 검사 1회에서 검토 화면 대기 시간 초과가 있었다. 같은 시각(06:17:05 UTC) 캡처 임시 HTML 삭제로 Vite page reload가 발생했고, 편집/캡처 없는 재실행은 통과했다. 캡처와 통합 검사를 같은 Vite에서 동시 실행하지 않는다.
- 전체 Node 검사 814개, lint(오류 0, 기존 경고 54개), Vue 타입 검사·프로덕션 빌드 통과. 빌드의 기존 대형 청크 경고는 남는다. 원격 CI와 운영 제공 버전은 별도 확인 전이다.

실제 로그인/권한 변경·실계좌/PDF, 영수증 전용 CSV, 금융 집계 정의/산출, 전체 픽셀 승인은 미검증/미구현이다. 다른 최종 화면을 이 변경으로 완료 처리하지 않는다. 대조표에서는 선택된 최종 ID를 superseded 목록에서 제외해 현재/이전 버전이 동시에 표시되는 중복을 정리했다.
