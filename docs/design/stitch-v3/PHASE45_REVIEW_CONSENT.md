# 검토 동의·저장 카드 연결

#256의 기존 헤더·폭 구현 위에 최종 Tablet `5aa7a573854a46db9b106f89c09c4f23`, Mobile `6bd9777b8bea43b98aea8397a29f809a`의 최종 반영 동의 및 저장 카드를 적용했다. 기존 저장 동작·취소·이전 단계·PDF 명의 확인·전체 행 재검증을 유지한다. 하단의 가로 저장 바를 원본처럼 확인 사이드바 안의 카드로 옮겼다. 1024px 이상에서 7:5 두 열, 그 아래에서는 단일 열이며 Mobile은 기존 원본 최대358px를 유지한다.

필수 원본 대조 동의가 없으면 저장 버튼과 commit 이벤트 모두 차단한다. 행 수정(개별/일괄)·검토 세션·대상 계좌가 바뀌면 동의를 해제한다. 필터·페이지 전환은 같은 전체 검토를 유지한다. 기존 busy/saveDisabled와 명의 확인을 우회하지 않으며 동의 체크 자체는 금융기관 계좌 소유권 검증이 아니다. 추가 API·원장 계산·개인 자료 캐시는 없다. 다크 scoped 선택자의 전역 누출도 제거했다.

[5폭 측정](evidence/phase45/measurements.json), [1280 원본](evidence/phase45/source-1280.png)/[구현](evidence/phase45/implementation-1280.png), [Mobile 원본](evidence/phase45/source-390.png)/[구현](evidence/phase45/implementation-390.png). 캡처는 동의 전 차단·동의 후 commit·행 편집 시 해제·busy/명의 차단·필터 중 전체6행 보존·다크·포커스·API0회를 검증했다. 실제 Memory API의 수기·증권사 열 연결·정정·전체4716행 검토와 Mobile 오류 복구·자산관리의 6종 브라우저가 통과했다. 실제 고객 자료/인증·PDF와 운영 쓰기는 수행하지 않았다.

구형 statement-identity 브라우저 스크립트는 현재 등록/업로드 진입 및 로딩 UI와 맞지 않아 미통과다. 최초 추출 버튼 대기, 현재 진입에 맞춘 시험에서는 이미 없어진 '거래내역서를 읽고 있습니다' 대화상자를 기다렸다. 이 옛 구조를 제품에 재도입하거나 통과로 계산하지 않았다. 본 변경에서는 새 동의를 확인하는 단계만 해당 스크립트에 추가했고, 이 스크립트 전체 현대화는 별도 과제다. 활성 CI의 전체 검토 및 모바일 오류 검사와 신규 동의 캡처 결과를 구분한다.

남은 차이: 일반 CSV Mobile 거래 카드·원문 인스펙터, 통화별 거래 합계 계약, 진행률의 검토 완료 정의, 기존 배당 차트/안내 구성과 글꼴·간격. 세전 실입금·정상100%·가상 합계를 실제 값으로 대신하지 않는다. 동의 카드를 연결한 것은 전체 시각 일치 완료가 아니다. #253 업로드 미리보기와 합칠 때 review 모드는 !inlineReview 조건을 유지해야 하며 새 standard-upload-inline 테스트에도 이 동의 단계를 연결해야 한다.
