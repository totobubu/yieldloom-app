## 실제 계약 보존

유형은 기존 등록 폼의4값만 번역한다. 일반을 데이터에 없는 ‘일반위탁’으로 추정하지 않으며, 모르는/비정상/프로토타입 이름은 유형·권한 미확인이다. 원본 예시의 API 미연결·정상 스냅샷 등을 실제 계약이 없는 계좌에 붙이지 않았다. 실제 별칭·기준일·통화·보유 행/가린 번호·부가 안내는 유지한다.

별칭 수정 조건은 원래와 같은 authorityUid 일치 및 owner/editor이고 busy 잠금도 보존한다. 수정할 수 없는 계좌는 ‘별칭 수정 불가’와 잠금 아이콘을 보여준다. 선택 버튼은 실제 명의자·기관·별칭·번호·권한·유형을 읽는다. 원본 파일은 기존처럼 미지원/비활성이며 가짜 문서 링크나 저장 성공을 만들지 않았다.

실제 컴포넌트를9개 합성 role/type 사례×3폭으로 검증했다. 소유자/편집자/조회전용/다른 권한자/알 수 없음, 잘못된 유형과 프로토타입 이름, disabled native 동작, 조회전용 선택, 올바른 rename ID, 처리 중 잠금, 다크,0/미확인 보존을 확인했다. 이 검증은 API/인증 접근0이다. 기존 전체 앱의 명의자/독립 통화/별칭 포커스·권한·계좌 상태 흐름은 통합 회귀로 별도 확인한다. [27개 UI 상태](evidence/phase79-cards/card-states.txt).

새 명의자 읽기 검사에서 합성 HTML의 UTF-8 선언 누락이 발견됐다. 검증 페이지에 meta charset을 추가해 해결했으며 제품 페이지 인코딩 오류로 분류하지 않았다. 기대값을 낮추지 않았고 같은 검사가 통과했다. [첫 실패](evidence/phase79-cards/harness-encoding-failure.txt), [구분](evidence/phase79-cards/harness-fix.json).

## 미수용 범위

1024px에서는 원본3열/현재1열이다. 원본 콘텐츠976px에 비해 실제 셸 슬롯708px가 남으므로 기존 안전한 한 열을 유지했다. 이 차이를 합격으로 바꾸거나 카드만 억지로 좁히지 않았다. PC1280px도 슬롯 차이로 원본 카드394.66px/현재310.66px이고 실제 보유 행이 줄바꿈돼 현재300px/원본284px 차이가 남는다. 별도 셸/콘텐츠 조립과 전체 프레임의 일반 UI 잔여다.

전체 native PNG/실제 글꼴·모든 데이터 상태의 일치는 미수용이다. 실계좌·고객PDF·서버 DB 쓰기/청구량은 검증하지 않았다. 금융 계산·원장·계좌 권한 API·공개 데이터·의존성을 변경하지 않았으며 시뮬레이터 공개 PR 승인 차단을 유지했다.
