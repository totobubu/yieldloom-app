# 관리자 장부 통합 작업 인계

이 작업의 구현과 검증은 `feat/sheet-evidence-tools`의 draft PR [168](https://github.com/totobubu/yieldloom-app/pull/168)에 보존한다. 기능 커밋은 `bbf9247dc72fd2ee54cebc92eda6a1f7e067d9b7`이며, 이 문서는 후속 문서 커밋으로 추가한다. 최종 인계 SHA와 CI 결과는 아래 비공개 완료 기록 및 PR 최신 head를 기준으로 확인한다.

이 문서는 기존 채팅의 결정과 실행 상태를 인계하는 요약이다. 대화 원문이나 접근 불가능한 첨부를 자동 이동한 것이 아니다. 실제 거래값·계좌 식별자·이미지·인증 정보는 Git에 넣지 않는다. 세부 금융 검토 이력은 아래 비공개 R2 인계 자료에 별도로 보존했다.

## 후속 사용자 결정: 토스 원본을 기준으로 재구성

2026-10-27 통합 관리에서 사용자는 원본이 토스증권이어야 한다고 명확히 정정했다.
과거의 시트 기준 비교·원금 검토는 이행 대조 기록으로 보존한다. 앞으로의 분석은 토스
웹/토스 발행 PDF → 불변 원문 → 검증된 사건·ID → 장부를 기준으로 하며 시트는 1:N/N:1
참고 대조 계층이다. 세부 기준은 [장부 정본 정책](../SHEET_TRIAL_LEDGER.md#정본과-이행-방향)에
유지한다. 시트에 맞춘 원문 수정·주문 병합·추정 확정·관리자 승인값 자동 변경은 하지 않는다.
현재 시험 장부가 이미 토스 사건 기반으로 전환됐다고 표현하지 않는다.
이번 후속 범위는 가격/이력·장부의 읽기 검증과 정책/일반 검증 코드이며 운영 전환은 제외한다.

## 후속 읽기 검증의 관측 범위

현재 Firebase 시험 장부의 버전 고정 스냅샷에서 기존 검토 15행을 출처 workbook 지문과
원본 시트 셀로 고유하게 재확인했다. 해시를 검증한 v4 비교 자료의 수량/금액 대조를
십진수로 다시 계산해 1:1 후보 7행·1:N 정확 일치 0행을 확인했다. 이는 제한된 후보의
결과이며 특정 셀의 집계 의도나 실제 사건 연결을 승인하지 않는다.

토스 원본 파일의 해시를 대조한 별도 주문 7건과 QDTE 거래 상세 3개를 다시 읽었다.
서로 다른 증권사 주문 ID를 보존했고 단일 주문 오매핑 철회는 유지한다. YMAX는 금액/날짜
경계와 실제 열린 패널의 직접 ID 연결을 별도 문제로 남긴다. 전체 보류 항목이 해결됐다고
표시하지 않는다. 다른 항목의 원문 파일까지 모두 재조회한 것은 아니다.

PDF 유래 Firebase 대상 기록은 한도 있는 부분 조회다. 소유 계좌·가족 참여는 확인했지만
해당 PDF와 웹 수집의 남편/아내 구분을 직접 연결하지 못했다. PDF 원본 바이트도 이번
검토에 없으므로 교차 확정하지 않는다. 현재 `toss-pdf` externalId는 앱이 만든 행 지문/
발생 순번이며 증권사 거래번호가 아니다. 누락 비용·시각을 0/자정으로 보충하지 않는다.

인계 envelope와 6개 내부 파일의 전체 바이트 SHA-256을 검증했다. 전송 도구가 잘라 반환한
중간 응답은 근거로 사용하지 않고 완전한 바이트를 재구성해 고정 지문과 대조했다.
상세 값·출처·차이·부족 자료·다음 조치는 비공개 작업 보고서에만 보존하며, 운영 데이터
쓰기·정정·승인·새 공유는 수행하지 않았다. 시장 이력의 별도 결과는
[수집 acceptance](../data-management/COLLECTION_ACCEPTANCE.md#2026-10-27-읽기-검증-체크포인트)를 따른다.

## 승인 범위와 실행 담당

- 사용자는 두 작업의 Git 푸시와 검토용 PR을 승인했고, 이후 통합 작업에서의 main 병합·운영 배포도 승인했다.
- 관리 측의 최신 실행 분담에 따라 **이 작업은 푸시·draft PR·CI 확인·인계 체크포인트까지 마친 뒤 멈춘다**. 여기서 work/main 병합, 운영 배포, 브랜치 삭제를 실행하지 않는다.
- 새 통합 작업의 단일 실행자가 두 PR의 최신 head·검사·충돌을 확인한 뒤 병합·배포를 관리한다. 사용자가 여러 채팅에서 같은 질문을 반복하지 않도록 확인 사항은 관리 측 한 창에서 모은다.
- 원금 대조·장부 화면 준비 요청은 금융 주문 실행, 환전·출금 실행, 자격 증명 생성 또는 권한 확장의 승인이 아니다.

## 화면에서 유지할 사용자 요구

1. 남편·아내 계좌를 구분하고, 원문 확보·비교된 사실·수동 근거·미확인·관리자 채택을 서로 다른 상태로 표시한다.
2. 동일한 날짜가 셀의 주 값과 출처 줄에서 반복될 때 표시 중복만 줄인다. 출처 위치, 다른 값, 연결 경고와 승인 이력은 지우지 않는다.
3. 거래일 옆 거래시간에서 저장된 토스 시각을 볼 수 있어야 한다. 단순히 열만 추가하고 미제공으로 남기는 것은 해결이 아니다.
4. 본문의 필터를 선택하고 확인하면 전체 화면 팝업으로 목록을 연다. 전체 검색·정렬·계좌/유형/상태 필터·처음/마지막 이동·수동 행 추가·수정·기존 승인 저장을 보존한다.
5. 대량 목록은 기존 브라우저 스크롤과 제한된 렌더링 창을 유지한다. 팝업 전환 후 높이와 고정 헤더 좌표를 갱신하는 기존 처리를 제거하지 않는다.
6. 원문 전체 필드와 출처 비교를 확인할 수 있어야 하며, 아직 없는 승인 동작을 구현된 것처럼 표시하지 않는다.
7. 재투자 추정은 최근 같은 계좌 배당금을 계산상 배분하는 기존 휴리스틱이다. 실제 자금 출처가 증명됐거나 거래 자체가 추정이라는 뜻이 아니다. 정확한 계산 기준은 기존 설명과 서비스를 유지한다.
8. 보류 항목을 판단할 비교 자료·필요 필드·검증 방법·최소 사용자 확인 범위를 표로 안내한다. 사용자가 모든 오차를 직접 찾아야 하는 흐름으로 되돌리지 않는다.

## 이번 코드의 실행 경로

`src/pages/SheetTrialLedgerView.vue`는 기존 장부 클라이언트를 그대로 사용한다. 거래 목록 팝업을 열 때 필요한 계좌에 대해서만 기존 보고서 API의 `section=times`를 읽는다. `SheetSourceTimes.vue`는 보관된 R2 후보와 이미 연결 후보인 대조 자료의 시각을 함께 보여준다.

- `transactionAt` 장부값을 `executedAt`·`paidAt`·`settledAt`으로 자동 덮어쓰지 않는다. 각 필드의 역할을 표시한다.
- 주문 목록의 `orderedAt`을 생성·예약·실제 주문 시각으로 일괄 해석하지 않는다. 목록 기록 시각과 상세의 예약·주문·구매/판매·실패·취소 시각을 구분한다.
- 시분초·밀리초·시간대를 임의 추가하거나 UTC/KST를 추정 변환하지 않는다. 날짜만 있는 값은 자정 시각으로 만들지 않는다.
- 회사/HOME 상세 텍스트는 실제 표시된 날짜·종목·시각을 읽는다. 선택한 목록 행의 메타데이터 날짜나 주문 ID를 실제 열린 상세의 식별자로 대입하지 않는다.
- 기본 셀은 시각을 최대 세 개 요약한다. 같은 역할·표시 시각의 중복을 줄여도 별도 원문 후보와 각 수량·출처는 펼친 상세에 그대로 남긴다.
- 날짜·계좌·유형·종목으로 좁힌 결과는 후보일 뿐 직접 ID 일치나 승인 결과가 아니다. 불확실 시도와 고정 기준 밖 기록은 해당 파생 범위에서 제외한다.
- 표의 검색·유형 필터·스크롤에 추가 요청을 만들지 않는다. 진행 중 동일 요청은 합치며, 개인 시각 캐시는 세션 메모리에서 최대 5분, 기존 요약 캐시는 30초다. 로그인/권한 변경·명시적 새로고침·해제 시 폐기한다.

서버는 `lib/sheet-report-handler.js`에서 관리자 인증과 소유 workbook 검증을 유지한다. 원래 요약 index는 보존하고 별도 시각 index를 읽는다. 두 index의 workbook 지문과 runId가 다르면 409로 거절한다. 비공개 R2 객체의 SHA-256과 계좌·형식을 확인하고 `readOnly=true`, `adoptionAvailable=false`로 반환한다. 요약과 시각은 서로 다른 자료이므로 이 둘을 같은 조회의 중복이라고 합쳐 권한 확인을 빼지 않는다.

시각 조회는 계좌별 HTTP 1회, Firestore 소유 검증 2문서와 R2 index/index/report 3객체 읽기다. 이는 코드와 합성 검증 기준이지 실제 청구 측정값이 아니다. API는 시각·수량·출처의 제한된 파생 자료만 읽으며 해당 응답 상한은 4.3MB다. 실제 네트워크와 로그인 화면 성능은 아직 측정하지 않았다.

주요 코드와 테스트:

- `lib/sheet-source-times.js`: 시각 후보 모델·역할·인덱스·응답 검증·기존 관측 시각 표시.
- `lib/sheet-panel-times.js`: 실제 표시 텍스트에서 시각만 추출하며 금액 뒤 날짜를 금액에 붙여 읽지 않는다.
- `lib/sheet-source-time-archive.js`, `scripts/toss/build-source-time-reports.mjs`: 기존 원문 지문을 확인한 로컬 파생 자료 생성. checkout 밖 새 비공개 폴더에만 출력하며 자동 게시하지 않는다.
- `SheetEvidenceRequirements.vue`, `sheetEvidenceGuide.js`: 기존 요약의 보류 항목으로 안내 표를 구성한다. 새 금융 판단이나 원문 조회를 렌더링 중 수행하지 않는다.
- `sheet_source_times`, `sheet_panel_times`, `sheet_source_time_archive`, `sheet_evidence_requirements`, `sheet_reports`, `toss_local_sync` 관련 Node 테스트.

## 금융 대조에서 바뀌면 안 되는 판단

정확한 거래일·금액·수량·원본 식별자와 행별 근거는 비공개 인계 자료의 `financial-decision-context.json` 및 v1–v4 보고서에 있다. 아래 원칙을 먼저 적용하고 원본 수치를 공개 Git 문서나 합성 fixture에 옮기지 않는다.

- 고정 수집 대상 수, 확보한 상세 원문 수, 시트 행 수, 시각 소스 레코드 수, 고유 금융사건 수는 서로 다른 단위다. 최신 증분으로 기존 고정 분모를 덮어쓰지 않는다.
- 사용자는 취소·실패·미체결 주문의 완전 수집과 추가 스크린샷 요구를 중단하고 실제 현금흐름·체결을 우선하라고 했다. 남은 원본 상태를 모두 취소로 바꾸지 않는다. 부분체결 또는 실제 현금 증거가 있으면 상태만으로 제외하지 않는다.
- 원금은 실제 외부 입출금, 환전의 양 통화, 지급 배당, 실제 체결·정산과 시트/PDF를 대조한다. 통화별 표기를 합산하지 않고 환전을 신규 외부 원금으로 중복 계산하지 않는다. 비용 미확인은 0이 아니며, 확인된 부분 합계가 전체 계좌 잔액은 아니다.
- 계좌가 확인되지 않은 PDF를 임의로 남편/아내에게 배정하지 않는다. 원본 PDF 기반 Firebase 자료와 시트 원문은 보존한다. HOME 재확인 건수처럼 보고서 시점별로 다른 숫자를 해결 완료나 임의 감소로 바꾸지 않는다.
- 반복 첨부된 완료 매수 캡처는 기존 거래의 사용자 근거로만 다뤘다. 별도 실패 캡처 보완은 수동 근거이며 금융사 상세 직접 수집 완료나 실제 체결로 바꾸지 않았다. 캡처의 주문번호/URL 부재도 유지한다.
- 특정 실패 주문의 기존 `orderedAt`을 생성시각으로 부른 해석은 철회했다. 주문일·예약일·실패시각은 별도 필드이고 시간대 추정으로 날짜 차이를 없애지 않는다. 관련 값은 체결금액이 아니라 주문 필드다.
- 금액 차이 목록은 자동 해결/승인하지 않았다. 일부 행이 특정 정산 또는 체결항목 금액 기준과 맞더라도 시트 기록 의도와 동일 거래 연결까지 해결됐다는 뜻은 아니다.
- QDTE 사례는 수기 입력이 확인됐으므로 셀 수식 오류 가설을 제외했다. 이후 같은 표시 시각의 별도 주문이 확인돼 기존 유일 후보/강한 연결 및 동일 거래 금액 충돌 가설을 철회했다. 최신 분류는 연결·집계 단위 검토다.
- 사용자는 같은 날짜의 여러 거래를 한 셀에 수기 합산한 경우가 있다고 밝혔다. 모든 행 또는 해당 특정 셀이 합산이라고 확정한 것은 아니다. 계좌·유형·통화·종목을 분리한 1:1과 1:N 후보를 비교하고, 수량과 같은 비용 기준의 금액이 함께 맞는지 확인한다. 단가·평균단가는 합산하지 않는다.
- QDTE 원본 수량 열과 금액 열의 기록 범위, 원래 수기값과 이전 정규화의 관계는 아직 확정되지 않았다. 현재 정규화 결과에 이미 있던 쌍을 이 작업의 수기 오타로 단정하지 않는다. 원본 workbook의 입력값/변경 이력은 없으며 파생 단가도 독립 근거가 아니다.
- YMAX는 선택한 주문과 실제 열린 상세의 연결 상충 및 금액 바로 뒤 출금 날짜가 붙은 파싱 문제다. 다른 날짜 후보의 현금 정산이 맞더라도 원래 선택 ID의 직접 연결을 입증하지 않는다. 금액만으로 바꿔 연결하거나 전체 종목을 해결 처리하지 않는다.
- WPAY/TOPW는 같은 펀드의 공식 심볼 변경 근거에 따른 후보 별칭이다. 원래 표기를 보존하며 분할로 처리하거나 수량을 재계산하지 않는다.
- 새 체결 안내의 첨부는 이 실행자에서 읽어 식별하지 못했다. 종목·계좌·수량·금액·ID를 추정하지 않는다. 일부 prefix 검색은 전체 저장소에 새 증거가 없다는 증명이 아니다.
- 접근이 거부된 이전 Library 이미지를 다른 경로로 재시도하지 않는다. 직접 사용자 첨부, 저장된 텍스트, 원문 JSON, 다른 실행자의 보고와 픽셀 확인을 구분한다. 관리자가 직접 이미지를 봤다고 대신 표시하지 않는다.
- 이전 원문과 정정 이력을 덮어쓰지 않는다. v1 → 수기 확인 v2 → 별도 주문 정정 v3 → 집계 단위 검토 v4의 변경 근거를 읽고 최신 가설을 적용한다. 기존 UI 요약이 최신 비공개 v4 판단과 같다고 가정하지 않는다.

## 실제 브라우저 연결의 남은 범위

사용자는 관리자 화면과 토스 로그인 창을 **같은 컴퓨터**에 열어두기로 했다. 이 선택은 실제 연결 확인이나 새 지속 권한 설정 승인이 아니다. 사용자에게 수집기 파일이나 작업 폴더를 직접 찾아 달라는 기술 질문을 다시 하지 않는다.

저장된 과거 체크포인트에서 수집 도구가 로컬 `ego lite`였고 마지막 CLI 프로세스는 종료됐으며 수집은 멈춘 상태임을 확인했다. 현재 이 실행 환경에는 `ego`/`ego-browser` 실행 파일과 현재 토스 브라우저 연결이 없다. 과거 체크포인트의 로그인/소유 상태를 현재 상태로 재사용하지 않는다.

`SheetTossSyncPanel.vue`와 `createTossLocalSync()`는 연결 상태 검사와 증분 1배치 처리 계약을 구현했다. **실제 브라우저를 읽는 어댑터는 구현·등록되지 않았고 페이지가 전달하는 connector는 없다.** 따라서 토스 창만 열거나 이 PR을 배포해도 최신 데이터 가져오기가 실행되는 것은 아니다.

연결 뒤의 계약은 다음과 같다.

1. 사용자가 계좌와 연결 상태를 확인한다. 신뢰된 로컬 어댑터는 현재 연결·읽기 전용 모드·실제 계좌 확인을 명시적으로 반환해야 한다.
2. 사용자 클릭으로 `nextBatch({accountId, readOnly:true})`에서 기존 수집기의 미승인 배치/증분을 받는다. 한 번에 최대 100건 한 배치이며 백그라운드 폴링이나 전체 재수집은 하지 않는다.
3. 기존 인증된 장부 클라이언트의 `batch-preview`에서 계좌·내용·중복을 검증하고 fingerprint로 `batch-commit`한다. 원문만 보존하고 canonical은 바꾸지 않는다.
4. 클라우드 저장 확인 뒤에만 로컬 `acknowledge()`로 체크포인트를 진행한다. 저장 응답이나 확인이 끊기면 동일 ID/내용/지문을 재전송해 기존 서버 중복 방지를 재사용한다.
5. 사용자/계좌 변경·로그아웃에는 이전 실행 결과를 폐기한다. 수집기에는 Firebase 토큰을 전달하지 않으며 토스 쿠키·세션·비밀번호도 클라우드로 보내지 않는다.

다음 실제 단계는 관리 측이 **기존 사용자 컴퓨터의 연결 도구가 사용 가능한 로컬 실행 환경**을 확인하는 것이다. 이후 그 환경에서 기존 수집기를 재사용하는 어댑터를 구현/등록하고, 현재 계좌·읽기 전용 상태·끊김 후 재개를 시험한다. 설치된 CLI만으로 어댑터 구현까지 끝났다고 하지 않는다. 도구 부재와 사용자 컴퓨터 브라우저 연결 부재를 서로 다른 차단으로 기록한다.

새 영구 host/debugger 권한, 새 확장 프로그램 권한, 원격 CDP 공개, 새 자격 증명을 임의로 설정하지 않는다. 기존 도구가 없다고 유료 외부 브라우저로 바꾸거나 별도 Playwright 브라우저를 띄워 사용자 금융 브라우저를 대체하지 않는다. 저장소 CI의 합성 Playwright 시험은 실제 금융 브라우저 수집과 별개다.

## 비공개 근거와 완료 기록 위치

기존 비공개 버킷은 `yieldloom-data-private`다. 기존 서버 설정 `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`를 재사용하며 값을 문서·로그·공개 번들에 쓰지 않는다. 공개 R2 URL이나 공유 링크로 대체하지 않는다. 현재 권한으로 접근이 안 되면 정확한 실패만 보고하고 인증 검사를 끄지 않는다.

대시보드 index는 `reconciliation/dashboard/v1/current.json`, 시각 index는 `reconciliation/dashboard/v1/source-times/current.json`이다. 시각 index는 계좌별 불변 객체와 SHA-256을 가리킨다. 원래 요약 index와 금융 원문은 변경하지 않았다. source workbook 지문·runId를 비교한 후 읽는다.

고정 수집의 마지막 정상 체크포인트는 `checkpoints/2026-10-26/wife/home-orders-3019-of-3031-083624c26a01286a.json`이다. 잘못 인코딩된 과거 중간 객체를 기준으로 복구하거나 전체 수집을 다시 하지 않는다. 회사 상세 객체 목록은 그 체크포인트의 `sourceCheckpoint`를 따라 읽고, HOME 원문은 `r2SourceObjects`를 따른다.

새 비공개 인계 묶음:

```text
reconciliation/handoffs/2026-10-27/sheet-evidence-tools-20c76b1e-71b2-4040-b510-8071f64551a4/context.json
SHA-256 301ceccdd0e31500bb0a94dd5539eecaaf78302421ee5ae36ba685917e1228e1
```

묶음의 `files[]`는 파일명·바이트 수·SHA-256과 base64 내용을 담는다. 원문 파일을 각각 디코드하고 지문을 확인한다. 압축 파일이 아니라 JSON envelope다. 전체 금융 본문을 도구 출력이나 Git에 덤프하지 말고 필요한 필드만 조회한다.

- `saved-evidence-review.v1.json`: 최초 저장 근거 검토와 보류 항목.
- `qdte-manual-input-addendum.v2.json`: 사용자 수기 입력 확인.
- `qdte-cross-order-correction.v3.json`: 동시각 별도 주문에 따른 연결 가설 철회.
- `sheet-group-review.v4.json`: 1:1/1:N과 열별 집계 의미 검토.
- `financial-decision-context.json`: 정확한 비공개 거래값, 사용자 진술과 native 값의 차이, 날짜 해석 정정, 신규 증분/원금/별칭 원칙.
- `implementation-handoff.json`: 구현·검증 영수증과 시각 객체/지문 위치. 이 파일은 푸시 직후 상태의 스냅샷이므로 이후 최종 SHA와 CI는 아래 완료 기록이 우선한다.

최종 SHA·PR·CI를 기록할 완료 체크포인트 위치:

```text
reconciliation/handoffs/2026-10-27/sheet-evidence-tools-20c76b1e-71b2-4040-b510-8071f64551a4/completion.json
```

현재 작업 폴더의 추가 비공개 자료는 `/workspace/source-times-review.ynNWjc14`, `/workspace/cashflow-evidence-review.ZVTbryDt`, `/workspace/admin-review-prep.krSGTKnD`, `/workspace/sheet-handoff-private.zAfb6fKi`에 있다. 새 작업이 같은 파일시스템을 공유한다고 가정하지 말고 R2 묶음을 우선 사용한다. 원본 시트 정규화 결과를 Google 원본 workbook의 현재 셀·수식·수정 이력이라고 표시하지 않는다.

6. 원금·현금흐름에 영향을 주는 최소 미해결 항목만 기존 근거로 좁힌다. 자동 승인·원문 덮어쓰기·추가 미체결 전체 수집 또는 모든 차이의 사용자 수작업 확인을 재개하지 않는다.
