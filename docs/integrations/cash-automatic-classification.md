# 계좌 내역 자동 분류

`cash-auto-v2`은 계좌 ACL을 확인한 기존 원장 조회 결과에 적용하는 파생 분류다.
과거 내역도 다음 정상 조회부터 같은 규칙을 적용한다. 원장/Firestore 분류 문서를
일괄 저장하거나 거래를 추가하지 않는다. 계좌별 실제 적용 건수는 인증된 원장을
조회해야 확인할 수 있으며, 이 변경의 검증은 합성 fixture로 수행했다.

## 범위와 우선순위

- 같은 계좌의 유효한 토스 PDF 현금 입금 원문 `이벤트입금`(기존 parser 표기
  `이벤트 입금` 포함)은 이벤트 지급, `이자입금`·`외화이자입금`은 이자다.
  취소/반환/유사 문자열과 반대 방향 거래는 자동으로 추측하지 않는다.
- 저장된 사용자 분류와 메모가 항상 우선한다. 명시적으로 되돌린 `unknown`도
  보호한다. 자동 결과는 `자동 분류`와 근거를 표시하며, 되돌리기를 누르면 기존
  revision 검증 API로 수동 `unknown`을 저장한다. 자동 결과 자체에는 revision이 없다.
- 계좌 선택은 예금주 / 증권사 / 기존 마스킹 계좌번호다. 마스킹 형식이 확인되지
  않거나 값이 없으면 `계좌번호 미등록`이며 전체 번호를 읽거나 노출하지 않는다.
- 저장 상태는 검토 제목 오른쪽의 단일 aria-live 영역이다. 저장 중/성공/실패
  상태가 기존 안내를 대체하며, 행별 오류와 재시도·충돌 재조회는 유지한다.

## 환전 안전 기준과 현재 한계

환전원화입금↔환전외화출금, 환전원화출금↔환전외화입금은 아래 조건을 모두
만족할 때만 둘 다 계좌 내 환전으로 파생 분류한다.

1. 같은 계좌, 반대 KRW/USD 통화와 입출금 방향, 정확한 환전 원문 유형.
2. 양쪽 기록 환율이 같고, USD×환율을 원 단위 반올림한 금액이 KRW와 정확히
   일치한다. BigInt 십진 연산을 사용한다. 임의의 몇 원 또는 백분율 허용 오차는 없다.
   이는 기록 금액의 일관성 검사이며 증권사의 실제 수수료·반올림 정책을 확정하지 않는다.
3. 유일한 상호 일대일 쌍이며 수동 분류, 중복, 결제 환전은 보호한다. 같은 날
   불완전한 환전 후보가 있으면 안전하게 보류한다. 날짜만 같다는 이유로 처리하지 않는다.
4. 실제 거래 시각이 양쪽 모두 검증되어 있으면 일치해야 한다. 제공된 시각 근거가
   잘못되거나 충돌하면 날짜 기반으로 우회하지 않는다. 시각 자체가 없으면 위 유형·계좌·
   날짜·기록 환율·금액의 유일성으로 분류하고 화면에 `시각 미확인`을 표시한다.
5. 수수료 근거가 없으면 `수수료 미확인`이며 0으로 채우지 않는다. 알려진 비제로
   수수료 또는 유효하지 않은 근거가 있으면 현재 규칙은 보류한다. 수수료 미상인데
   금액을 맞추려고 차이를 수수료나 스프레드로 추정하지 않는다.

현재 PDF parser/import는 현금 거래 시각·수수료 객체를 생성하지 않는다. v2는
기존에 보존된 유형·금액·환율만으로 유일한 쌍을 분류할 수 있다. 실제 시각이나 수수료,
통화 간 원가 연결 및 환차손익을 복원했다는 의미는 아니다. 해당 기간 원문 PDF는
미확보이며 실제 계좌별 적용 건수는 인증된 조회에서 별도로 검증해야 한다.

공식 [토스 OpenAPI 명세](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)의
`orderedAt`은 주문 시각, `execution.filledAt`은 최종 체결 시각이다. 개별 fill 시각 또는
환전 시각으로 승격하지 않는다. 수집기는 이 문자열을 보존한다. 현재 명세에는 환전·
입출금 이력 경로가 없으며 `/api/v1/exchange-rate`는 계좌와 무관한 참고 환율이다.
따라서 API 주문 ID를 PDF 현금 행과 날짜만으로 결합하지 않는다.

## 집계·복구·조회

이자/이벤트는 소득이며 외부 원금 입금·원금 회수로 집계하지 않는다. 환전은 외부
원금 흐름에서 제외하며, 이 변경이 통화 간 원금 원천을 새로 연결하지는 않는다.
원장 금액·환율·날짜는 불변이다. 소득 자금 추적 결과는 올바른 분류에 따라 바뀔 수 있다.

추가 조회나 자동 POST 없이 기존 공용 조회·캐시를 재사용한다. `v3` 원장 버전과
규칙 버전을 사용해 구 캐시를 무효화하고, annotation만 변경되면 기존 원장을 재사용해
자동 결과를 다시 계산한다. 보관된 수동 분류 배열과 파생 자동 결과를 구분한다.
원장 변경/권한 철회/늦은 응답의 기존 보호를 유지한다.

복구는 규칙을 이전 배포로 되돌리면 된다(일괄 DB 쓰기 0). 개별 사용자는 기존
되돌리기/분류 선택으로 명시적 우선 분류를 저장할 수 있다. 원문/메모는 삭제하지 않는다.
실제 계좌별 적용·제외 건수와 인증된 운영 화면은 이 실행 환경에 기존 로그인 세션이
없어 검증하지 못했다. 인증 없이 개인 API를 우회하거나 원장에 테스트 쓰기를 하지 않는다.
