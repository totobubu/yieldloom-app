# 장부 일별 검토 달력

PR #211의 `c05ac13734acfac912c58fe293070cd01f344b37`에서 분리한 로컬
`feat/fifo-daily-review-calendar` 작업이다. 원래 PR 브랜치와 기존 가족/관측 수량/
legacy PAID 호환/성능 변경을 보존한다. 이번 범위는 구현·합성 검증·로컬 커밋까지다.

## 표시 계약

- 가족/계좌 범위가 먼저 적용된 기존 `portfolioEvents`를 재사용한다. 검색(종목·출처·통화),
  종목, 선택 날짜 조건은 서로 교집합이다. 계좌를 바꿔도 선택한 날짜·검색·종목은 유지한다.
- 월 이동은 달력만 이동한다. 선택한 검토 날짜는 하단 상태에 계속 표시되며, 다른 날짜를
  선택하거나 **전체 날짜 보기**를 눌러 변경한다. 전체 날짜 보기는 검색·종목 조건을 유지한다.
- 날짜는 기존 adapter가 채택한 `event.at`의 기록된 날짜 부분이다. 거래 timestamp가 있으면
  그것을, 없으면 장부 date를 사용하던 계약을 유지한다. UTC 등으로 변환하지 않는다.
  달력 생성/키보드 이동의 UTC 연산은 숫자로 구성한 달력 날짜에만 사용한다.
- 유효하지 않거나 없는 날짜는 **날짜 미상**으로 분리하며 전체 보기에도 남긴다.
  달력만으로 원문 날짜·체결 시각을 보정하거나 새로 추정하지 않는다.
- 일별 건수는 기존 거래 목록 하나에서 계산한다. 배당은 별도 배당 표에도 표시되지만
  한 번만 센다. 기존 세금 환급도 유지하며 건수에 포함됨을 안내한다.
  날짜/종목/금액으로 금융 사건을 합치거나 새 중복 판정을 하지 않는다.
- 빈 날짜·빈 검색 조건에 안내를 표시한다. 월간 날짜 버튼, 이전/다음 달, 날짜 미상,
  전체 복귀를 제공한다. 방향키·Home/End·PageUp/PageDown으로 포커스를 이동하고
  Enter/Space로 선택한다. 모바일/라이트/다크와 페이지 전체 스크롤을 유지한다.

## 계산·조회 경계

`FifoReviewCalendar`가 전달하는 슬롯 목록은 거래·배당 표에서만 소비한다.
`calculateFifoAssets`, `applyFifoCorrections`, 계좌 식별, 관측 수량, 원본/채택 장부,
수기 보정의 입력과 저장에는 연결하지 않는다. 금액·수량의 문자열 정밀도를 유지한다.
달력/월 이동/검색/종목 변경에 API·Firebase·R2 조회나 쓰기를 추가하지 않는다.
현재 보유 미확인과 `/mypage` readiness false 정책도 그대로다.

## 합성 검증과 인계

- `node --test tests/fifo_review_calendar.test.mjs`: 윤년·날짜 경계·시간대·날짜 미상,
  계좌 간 같은 ID, 배당 중복 집계 방지, 필터 교집합, 원본/정밀 금액/FIFO 결과 불변.
- 기존 `tests/fifo-report.browser.mjs`에 통합한 회귀: 가족 범위와 달력/검색/종목 조합,
  빈 날/전체 복귀, 자산 요약·lot 표 불변, 최초 API 1회/DB 3읽기/쓰기 0 이후
  검토 필터로 추가 호출 없음. 기존 CI의 FIFO 브라우저 명령에서 함께 실행된다.
- `tests/support/fifo-calendar-browser.mjs`: 로컬 임시 harness의 합성 매수/매도/배당,
  잘못된 날짜, 월/연도 이동·반복 선택·키보드·390px/라이트/다크·세로 내부 스크롤 없음.
  임시 HTML은 종료 시 삭제한다. 화면 캡처는 `/tmp/yieldloom-review-calendar-*.png`에 둔다.

최종 로컬 검사: 전체 단위 701/701, `npm run type-check`, `npm run build`,
`npm run lint:check`(오류 0, 기존 경고 72), 장부/증분/FIFO 브라우저 3종 통과.
브라우저의 기존 보정 저장/되돌리기는 메모리 DB의 합성 테스트이며 실제 저장이 아니다.
UI 코드와 계약을 자체 검토했으며 별도의 새 독립 리뷰나 원격 CI 실행은 이번 단계에서
하지 않았다. 캡처는 합성 자료로 만든 독립 컴포넌트 화면이다.

공개 게시 승인을 받으면 PR #211 최신 head를 먼저 확인하고, 이 로컬 커밋만 원래
PR 브랜치에 cherry-pick한 뒤 최신 통합 코드 검증을 다시 수행할 수 있다. 강제 덮어쓰기,
원격 push/PR 변경/병합/배포는 이번 작업에서 하지 않는다. 실제 금융 장부/PC/Preview의
새 달력 결과는 검증하지 않았으며, 합성 fixture에는 실제 거래를 넣지 않았다.
