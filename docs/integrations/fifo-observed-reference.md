## 의미와 집계 근거

`recordedTradeQuantity`는 **입력에 기록된 유효 매매의 매수·매도·순매수 수량**이다.
기록 당시 주식 수량의 산술 참고값(`as_recorded_unadjusted`)이며 기업행사·입출고를 조정한 공통 단위 잔고가 아니다.
기간 전체 이력, 초기 보유 0, 현재 잔고 또는 FIFO 원가의 확정이 아니다.
조회 결과 행 수는 계좌·종목·통화별 검토 항목 수이며 현재 보유 종목 수가 아니다.
청산 수량 0과 순매도(음수)도 기록 흐름으로만 해석한다. 기록일 from/to는 전체 기간의
완전성 증명이 아니다. 자료가 없거나 집계 불가능할 때 0으로 대체하지 않는다.

입력 근거는 기존 채택 snapshot의 `orderReferences`다. 최종 투영은 계좌 namespace와
주문 ID별 최신 누적 체결 버전 한 개만 선택하고 동시각 충돌은 거절한다.
이 선택·검증·채택을 재구현하거나 다른 장부·PDF와 다시 비교하지 않는다.
기존 index/hash/receipt/계좌 검증은 바꾸지 않는다.

증분 투영은 기존 baseline Map을 변경하지 않고, 선택한 현재 row의 주문 reference를
새 Map에 유지한다. adapter는 정확히 하나의 주문 reference가 있는 API 매매 행에만
불투명한 계좌별 주문 키를 만든다. 원래 provider 주문번호는 응답에 추가하지 않는다.
이 정보는 `recordedQuantityEvidence`에 따로 전달하고 기존 events·ledgerRevision을
변경하지 않는다. 새 DB·R2·외부 API 요청은 없다.

- 검증된 동일 주문·동일 내용의 재전송은 한 번만 센다.
- 누적 버전의 다른 수량·금액·종목·취소 상태가 섞이면 최신 버전을 임의 선택하거나
  더하지 않고 해당 계좌의 참고 집계를 미상으로 둔다. 최신 선택은 기존 투영의 책임이다.
- 계좌/프로필/통화는 격리한다. 수량은 exact rational로 더하고 뺀다.
- 미체결·void·중복 미확정 제외 행은 더하지 않는다. 부분체결 후 취소는 실제 체결분을 센다.
- 주문 reference·정확 소수 수량·기록일이 확인되지 않으면 그 그룹의 참고 지표도 미상이다.
- 확인된 분할/병합·주식 이전·단주 처분 입력이 있으면 단위/입출고를 임의 보정하지 않고
  관련 계좌·종목·통화의 관측 순매수를 미상으로 둔다. 다른 종목을 함께 제외하지 않는다.
- 수기 기초 lot는 매수로 합산하지 않는다. CASH_COVERAGE는 주식 완전성을 뜻하지 않는다.

## 계산과 상태 표시

기존 `quantity`, `remainingCost`, `realizedPnl` 계산과 모든 보류 가드는 그대로 유지한다.
`currentHoldingQuantity`는 현재 단계에서 항상 null이다. 주식 기간 완전성·기준일 잔고를
확인하는 계약을 새로 만들거나 임의 true로 두지 않는다. 기존 계산값은 입력 범위의 계산이다.

`evidenceStatus`는 코드가 실제로 판단한 근거만 분리한다.

- order: 기존 계산이 표시한 순서·시각 미확정
- coverage: 기초 lot/입고 입력의 존재 여부와 주식 이력 전체 범위·기준일 잔고 미확인
- movement: 입력에 실제 존재하는 기업행사·주식 이전·단주 처분
- cost: 원통화 원가/수수료/세금/정산액의 null
- fx: USD의 실제 원화 금액 또는 환율 근거 부재 (원통화와 분리)
- conflict: 확인된 동일 사건 충돌

자료가 없다는 이유로 실제 기업행사·이체가 있었다고 추정하지 않는다. 불명 원가나 FX를
0/현재가로 채우지 않으며, DRIP·기초 원가를 외부 투입금으로 더하지 않는다.
확인된 가족 현금 이동만 내부이체에서 제외하는 정책도 유지한다.

## 사용자에게 필요한 최소 근거

현재 보유 수량에는 기준일이 있는 증권사 잔고 또는 근거가 있는 기초 수량과 그 이후의
주식 거래·입출고·기업행사 전체 범위가 필요하다. 잔고 수량만으로 취득원가는 확정되지 않는다.
잔여 원가·부분매도 손익에는 기초 lot별 원 취득일/상대 순서·수량·통화·비용 포함 원가와
처분 경계의 체결/정산 근거가 필요하다. 전체 평균단가를 원래 FIFO lot처럼 사용하지 않는다.
원화 손익에는 별도 환전 원가 또는 적용 환율 근거, 배당 회수율에는 별도 현금 입출금
완전성과 재원 분류가 필요하다. 실제 38항목 중 순수매수 수와 남편 연결 여부는 이번 합성
검증으로 추정하지 않는다.

## PR #211로 가져오는 방법

원본 브랜치 소유자가 기존 미커밋 작업을 먼저 보존하고 현재 PR head를 확인한다.
이 문서의 기준 head와 같으면 이 브랜치의 두 후속 커밋을 순서대로 cherry-pick할 수 있다.
원본 head가 앞으로 이동했으면 먼저 diff·충돌 범위를 검토하고 관련 전체 테스트와 화면
검증을 다시 수행한다. 공유 브랜치를 reset/force push하거나 기존 PR 내용을 자동 덮어쓰지 않는다.
커밋 SHA와 최종 검증은 작업 인계에서 전달하며, 이 로컬 결과 자체는 PR/운영 반영이 아니다.

## 화면 검증

화면은 ‘검토 항목’ 수와 ‘장부 순매수 참고 수량’을 ‘현재 보유 미확인’에서 분리한다.
기록 당시 수량·기록일 범위·기업행사/입출고 조정 없음과 기준일 잔고 미확인을 표시한다.
원가·손익은 입력 범위라고 명시하고 기존 FIFO 수량은 계산 근거 안에 보존한다.
순서·주식 범위·움직임·원가·FX 상태는 구분해 보이며 실제 존재하지 않는 기업행사를 추정하지 않는다.
빈 자료에서는 0종목/0원으로 보유를 확정하지 않는다.

합성 브라우저는 정상 참고값, 주문 연결 근거 누락, 빈 자료, 재조회 복구를 검증한다.
자료 상태를 바꾸는 명시적 새로고침 3회는 기존과 동일하게 GET 3회·장부/보정 문서 읽기 9회·
snapshot 호출 3회이며 추가 쓰기는 없다. 테스트 내 보정 쓰기는 전부 메모리 fixture다.

최종 로컬 검증: 전체 Node 단위 696개, 타입 검사 포함 build, final-ledger /
toss-increments / fifo-report 합성 브라우저 3종 통과. 린트 오류 0, 기존 경고 72개.
누적 수량 감소 정정과 부분취소도 기존 최신 버전만 집계함을 검증했다.
AST 비교에서 기존 FIFO if 조건 80개와 증분 check 조건 78개 변경 0을 확인했다.
실제 장부의 관측 수량·현재 보유·원가나 전체 가족 자료는 새로 검증하지 않았다.
