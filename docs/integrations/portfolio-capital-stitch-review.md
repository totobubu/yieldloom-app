# 원금 회수·계좌 검토 화면 적용

2026-11-03 전달된 Stitch PC·모바일 전체 시안과 HTML을 확인하고 기존 Vue 3 / PrimeVue 4 화면에 적용했다. 시안의 A/B/C 분류와 예시 상태·금액은 제품 데이터로 사용하지 않는다. 전역 메뉴나 인증·공유 권한은 바꾸지 않는다.

## 표현과 동작

- PC는 원금 회수율·순투입 원금·외부 입출금의 3개 요약 카드와 검토 표를 사용한다. 모바일은 한 묶음의 통화별 요약과 세로 거래 카드로 전환한다. KRW/USD 비율과 금액은 합치지 않는다.
- 선택 계좌의 검토를 먼저 표시하고, 전체 계좌 회수·자금 계보 상세는 펼칠 때 조회한다. 기존 상세 기능과 계산 서비스는 유지한다.
- 두 DatePicker의 시작·종료일은 해당 날짜를 포함하며, 날짜/검토 상태/통화 필터는 메모리에 있는 검토 행만 거른다. 요약의 전체 저장 내역 집계는 변하지 않고 추가 API 요청도 없다. 기존 페이지당 10건을 유지한다.
- 기존 14개 분류를 모두 유지한다. 거래 후보에 맞는 주요 선택 버튼과 ‘다른 분류’를 제공하며, 후보는 선택 전까지 확정하지 않는다. 일반 분류는 선택 즉시 기존 `classifyCash` API로 저장한다.
- 금액 나눔은 원금·배당·수익·미확인 합계 검증 후 ‘배분 확정’으로 저장한다. 구매 결제 환전은 집계에서 제외하며 수정하지 않는다.
- 기존 분류 메모는 선택 사항이다. 메모만 저장하거나 확정 건을 ‘확인 필요’로 되돌릴 수 있다. 직접 내역 추가의 기존 필수 근거 검증은 유지한다.

## 저장 경계

원본 계좌 거래·금액·계산식·API ACL과 revision 충돌 검증을 변경하지 않는다. 선택은 기존 분류 주석만 저장하며 서버 성공 후 선택 계좌를 재조회한다. 저장/재조회 동안 중복 확정을 막고, 실패하면 선택 UI를 기존 확정값으로 되돌려 실패와 재시도를 표시한다. 권한·revision 오류는 자동 재전송하지 않고 최신 내역 확인을 제공한다. 계좌/사용자 전환 뒤 늦은 응답은 이전 화면에 격리한다. 메모·미확인 복구도 기존 주석 revision을 사용한다.

## 검증

모든 거래·사용자·저장은 합성 fixture 또는 메모리 DB다. 실제 개인 분류·자격증명·금융 원문은 테스트로 변경하지 않는다.

- `node --test tests/*.test.mjs`: 날짜/경계/불변성 및 기존 계산·권한·revision·캐시 계약.
- `tests/cash-review.browser.mjs`: PC 1440 / 모바일 390, 실제 달력 조작, 필터 시 조회 0회, 집계 불변, 즉시 저장·메모·복구·실패 재시도·혼합 금액 검증·충돌·키보드·중복 차단·늦은 계좌 응답·라이트/다크.
- `tests/portfolio-capital.browser.mjs`: 기존/가족 계좌, 통화 분리, 정확한 정산·자금 배분·조회 전용·오류/재시도 회귀. 실제 앱과 같은 테마 및 헤더 Teleport 영역을 합성 화면에 제공한다.
- `tests/account-recovery-reads.browser.mjs`: 선택 계좌 A 저장 뒤 A만 재조회하고 다른 계좌 B는 재조회하지 않는다. 합성 원금 출금에는 같은 계좌의 선행 외부 입금을 제공한다.
- `npm run lint:check`, `npm run build`(타입 포함). 위 브라우저 검사를 원격 Application quality에도 추가했다.

조회 수는 합성 HTTP 요청 수이며 실제 Firestore 읽기/청구량 측정이 아니다. 운영 배포 확인과 인증된 개인 계좌 화면·실제 분류 저장 검증은 구분해 보고한다.
