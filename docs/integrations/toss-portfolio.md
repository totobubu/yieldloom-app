# 토스증권 포트폴리오 연동 검토

## 현재 구현

- 고객별 Firebase 인증을 사용하는 거래내역 PDF 검토·확정 저장을 제공한다.
- `api/_utils/toss-portfolio.js`는 `https://openapi.tossinvest.com`의 `/oauth2/token`, `/api/v1/accounts`, `/api/v1/holdings`를 호출하도록 작성되어 있다.
- 위 주소·grant·응답 스키마는 이 작업에서 공식 문서로 검증되지 않았다. 목 응답 기반 테스트 통과는 실제 API 지원을 보장하지 않는다.
- 서버 키가 있다는 것만으로 고객별 계좌 연결이 완료되지는 않는다. 현재 readiness의 `enabled`는 false다.

## 연결 방안

1. 토스증권에 계좌·잔고·거래내역·배당 내역을 제공하는 외부 서비스용 API와 제휴 신청 가능 여부를 확인한다.
2. 공식 문서에서 고객 동의 방식, 인증 grant, 조회 범위, 호출 제한, 샌드박스와 운영 승인 조건을 확인한다. 현재 client_credentials 구현은 확인된 사양에 맞춰 교체한다.
3. 고객 동의와 계좌 소유 관계를 Firebase UID에 연결하고, 토큰은 서버에서만 보관한다. 서버 공용 키의 계좌를 일반 고객에게 노출하지 않는다.
4. 잔고 스냅샷과 거래 원장을 구분한다. 잔고만으로 과거 배당·매수·매도 원장을 생성하지 않는다. 거래 원장 동기화는 공급자 거래 ID로 중복을 방지한다.
5. 승인된 API가 없다면 현재 PDF 업로드를 유지한다. 대체 중계 서비스도 토스증권 지원 범위와 고객 동의·이용 계약을 확인한 뒤 선정한다.

## 확인 결과와 제한

공식 후보 사이트 `https://openapi.tossinvest.com`, `https://developers.toss.im`를 조회했으나 403 응답으로 문서를 확보하지 못했다. API의 존재 여부나 미지원 여부를 이 응답으로 결론 내릴 수 없다. Toss Payments 결제 API는 증권 계좌 원장 연동의 대체재가 아니다.

## 원장 표시 수정 범위

현재 원장 하위 컬렉션이 비었을 때 자산 문서의 인라인 거래내역을 유지한다. 현재 포트폴리오 전체에 원장이 없으면 소유자의 `adminPortfolios`에서 이전 원장을 조회하고 ID 또는 동일 심볼로 연결한다. 저장 데이터를 변경하지 않는다. 두 저장소 모두 원장이 없다면 PDF를 다시 가져와야 한다. 실제 토스 계좌 API 응답은 검증하지 않았으며, 계좌 동기화 기능은 비활성 상태다.

## 계좌 내역과 투자 원금

`/api/portfolio-capital`은 Firebase 토큰의 UID에 속한 계좌 내역만 읽고 쓴다. 요청 본문의 UID는 사용하지 않는다. 새 컬렉션은 클라이언트 직접 접근을 허용하지 않고 서버에서만 처리한다.

- `portfolios/{uid}/cashEntries`: PDF에서 추출한 입출금·환전 원본 행 또는 사용자 직접 입력. PDF와 비밀번호, 계좌번호는 저장하지 않는다. 계좌번호를 읽은 경우 해시 식별자만 사용한다.
- `cashClassifications`: 원본과 별도로 저장하는 사용자의 분류 확정. PDF의 분류 후보만으로 원금에 반영하지 않는다.
- `fundingAllocations`: 매수 거래별 결제 구성·자금 출처·근거 행·메모. 기존 거래의 수량·금액·손익은 변경하지 않는다. 수정 버전과 정산액을 대조하여 동시에 수정하거나 원장이 바뀐 경우 재확인을 요구한다.

원금 요약은 확정한 외부 입금에서 외부 출금을 차감한다. 배당·매도대금·이자·계좌 내 이동·환전은 새 원금으로 합산하지 않는다. KRW와 USD를 따로 집계하며, 환율이 없는 외화 입출금을 원화로 추정하지 않는다. 저장된 거래일 범위는 계좌 개설 이후의 완전한 내역을 보장하지 않으므로 화면에 범위와 미확정 건수를 표시한다. 과거 PDF 원본을 보관하지 않기 때문에 기존 고객은 해당 PDF를 다시 가져오거나 계좌 내역을 직접 추가해야 한다.

토스 PDF의 ISIN 없는 현금 행은 날짜·유형과 기존 명세서의 9개 금액 열(환율 포함 시 10개)이 맞을 때만 가져온다. 외화 행은 달러 열까지 확인하고, 원화 환산액을 별도 입금으로 중복 저장하지 않는다. 통화나 열이 불명확한 행은 제외한 건수를 검토 화면에 알린다. 이 파서는 모든 증권사·모든 계좌내역서 양식을 지원하지 않는다.

같은 날의 계좌 내역은 매수 자금의 근거 후보로만 제공한다. 원화 환전 금액과 기록 환율을 이용한 분할 입력도 참고값이다. 사용자가 실제 금액과 출처를 확인해야 하며, 하나의 근거가 다른 매수에서도 선택되었다면 중복 사용 확인 문구를 표시한다. 자금 구성이 매수 정산액과 일치해야 저장하며, 결제 구성이나 출처에 ‘확인 필요’가 있으면 일부 미확정으로 남긴다. 매수별 원금 배분은 순입금 원금에 다시 더하지 않는다.
