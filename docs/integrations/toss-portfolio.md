# 토스증권 포트폴리오 연동 검토

## 현재 구현

- 고객별 Firebase 인증을 사용하는 거래내역 PDF 검토·확정 저장을 제공한다.
- `api/_utils/toss-portfolio.js`는 `https://openapi.tossinvest.com`의 `/oauth2/token`, `/api/v1/accounts`, `/api/v1/holdings`를 호출하도록 작성되어 있다.
- 위 주소·grant·응답 스키마는 이 작업에서 공식 문서로 검증되지 않았다. 목 응답 기반 테스트 통과는 실제 API 지원을 보장하지 않는다.
- 서버 키가 있다는 것만으로 고객별 계좌 연결이 완료되지는 않는다. 현재 readiness의 `enabled`는 false다.

## 연결 방안

1. 토스증권에 계좌·잔고·거래내역·배당 내역을 제공하는 외부 서비스용 API와 제휴 신청 가능 여부를 확인한다.
2. 공식 문서에서 고객 동의 방식, 인증 grant, 조회 범위, 호출 제한, 샌드박스와 운영 승인 조건을 확인한다. 현재 client_credentials 구현은 확인된 사양에 맞춰 교체한다.
3. 고객 동의와 계좌 소유 관계를 Firebase UID에 연결하고, 토큰은 서버에서만 보관한다. 서버 공용 키의 계좌를 일반 고객에게 노출하지 않는다.
4. 잔고 스냅샷과 거래 원장을 구분한다. 잔고만으로 과거 배당·매수·매도 원장을 생성하지 않는다. 거래 원장 동기화는 공급자 거래 ID로 중복을 방지한다.
5. 승인된 API가 없다면 현재 PDF 업로드를 유지한다. 대체 중계 서비스도 토스증권 지원 범위와 고객 동의·이용 계약을 확인한 뒤 선정한다.

## 확인 결과와 제한

공식 후보 사이트 `https://openapi.tossinvest.com`, `https://developers.toss.im`를 조회했으나 403 응답으로 문서를 확보하지 못했다. API의 존재 여부나 미지원 여부를 이 응답으로 결론 내릴 수 없다. Toss Payments 결제 API는 증권 계좌 원장 연동의 대체재가 아니다.

## 원장 표시 수정 범위

현재 원장 하위 컬렉션이 비었을 때 자산 문서의 인라인 거래내역을 유지한다. 현재 포트폴리오 전체에 원장이 없으면 소유자의 `adminPortfolios`에서 이전 원장을 조회하고 ID 또는 동일 심볼로 연결한다. 저장 데이터를 변경하지 않는다. 두 저장소 모두 원장이 없다면 PDF를 다시 가져와야 한다. 실제 토스 계좌 API 응답은 검증하지 않았으며, 계좌 동기화 기능은 비활성 상태다.

## 계좌 내역과 투자 원금

`/api/portfolio-capital`은 토큰 취소 여부를 확인하고, 선택한 `investmentAccounts/{accountId}`의 계좌 ACL과 가족 참여를 모두 검사한다. owner/editor는 수정 가능하고 viewer는 조회만 가능하다. 가족 관리자에게 계좌 접근권을 자동 부여하지 않는다. 변경 트랜잭션 안에서도 권한을 다시 확인한다. 계좌 선택 없는 이전 자료에서는 토큰 UID의 `portfolios/{uid}`에 별도 메모만 저장한다. 요청 본문의 UID는 사용하지 않는다. 새 컬렉션은 클라이언트 직접 접근을 허용하지 않고 서버에서만 처리한다.

- `investmentAccounts/{accountId}/entries`: 가족 포트폴리오의 기존 원장. PDF 현금 행은 CASH 종목으로, 실제 원통화 금액과 환전 구분·기록 환율을 보존한다. 매수에는 원문 원화/달러 정산액을 추가 보존한다.
- `.../cashEntries`: 직접 입력한 계좌 내역. 이전 자료에서는 `portfolios/{uid}` 아래에 별도로 저장한다. PDF와 비밀번호, 계좌번호는 저장하지 않는다.
- `cashClassifications`: 원본과 별도로 저장하는 사용자의 분류 확정. PDF의 분류 후보만으로 원금에 반영하지 않는다.
- `fundingAllocations`: 매수 거래별 결제 구성·자금 출처·근거 행·메모. 기존 거래의 수량·금액·손익은 변경하지 않는다. 수정 버전과 정산액을 대조하여 동시에 수정하거나 원장이 바뀐 경우 재확인을 요구한다.

원금 요약은 확정한 외부 입금에서 **원금 회수로 확인한 출금분만** 차감한다. 배당 사용·기타 수익 사용 출금은 원금을 줄이지 않는다. 모든 외부 출금을 차감한 순입금은 별도의 현금 흐름 지표다. 출금 분류는 `external_withdrawal`(출처 미확인), `principal_withdrawal`, `dividend_withdrawal`, `profit_withdrawal`, `mixed_withdrawal`을 지원한다. `cashClassifications.withdrawalParts`의 principal/dividend/profit/unknown 합계가 원본 출금액과 일치해야 저장한다. 기존 일반 출금은 원금 회수로 자동 전환하지 않고 미확인으로 남긴다. 미확인 내역이 있거나 원금 회수액이 저장된 입금액보다 크면 화면에 원금 확정을 보류한다. 누적 수령 배당은 배당 사용으로 줄이지 않으며, 남은 배당의 재투자나 가용 현금도 추정하지 않는다. 배당·매도대금·이자·계좌 내 이동·환전은 새 원금으로 합산하지 않는다. KRW와 USD를 따로 집계하며, 환율이 없는 외화 입출금을 원화로 추정하지 않는다. 저장된 거래일 범위는 계좌 개설 이후의 완전한 내역을 보장하지 않으므로 화면에 범위와 미확정 건수를 표시한다. 과거 PDF 원본을 보관하지 않기 때문에 기존 고객은 가족 포트폴리오에서 명의자·계좌를 확인하여 해당 PDF를 다시 가져오거나 계좌 내역을 직접 추가해야 한다. 이전 단일 계좌 업로드 API는 410을 유지한다.

토스 PDF의 ISIN 없는 현금 행은 날짜·유형과 외화 행의 9개 원화 금액 열 또는 원화 행의 10개 금액 열(환율은 별도)이 맞을 때만 가져온다. 외화 행은 달러 열까지 확인하고, 원화 환산액을 별도 입금으로 중복 저장하지 않는다. 통화나 열이 불명확한 날짜 행은 가족 포트폴리오의 수정 필요 행으로 남겨 확인 전 전체 저장을 막는다. 이 파서는 모든 증권사·모든 계좌내역서 양식을 지원하지 않는다.

같은 날의 계좌 내역은 매수 자금의 근거 후보로만 제공한다. 원화 환전 금액과 기록 환율을 이용한 분할 입력도 참고값이다. 사용자가 실제 금액과 출처를 확인해야 하며, 하나의 근거가 다른 매수에서도 선택되었다면 중복 사용 확인 문구를 표시한다. 자금 구성이 매수 정산액과 일치해야 저장하며, 결제 구성이나 출처에 ‘확인 필요’가 있으면 일부 미확정으로 남긴다. 매수별 원금 배분은 원금이나 순입금에 다시 더하지 않는다.

이전 마이페이지의 기간별 거래내역은 주식 거래와 소유자의 계좌 내역을 합쳐 날짜순으로 표시한다. 종목 필터를 선택하면 계좌 내역은 제외하며, 출금 전체·배당 사용·원금 회수·기타 수익 사용·입금·환전 필터를 제공한다. 분할 출금은 해당 출처가 포함되면 출처 필터에 나타난다. 계좌 행에서 분류 화면으로 이동할 수 있다. 계좌 내역이 없거나 조회에 실패하면 입출금이 빠졌다는 안내를 표시한다. 가족 계좌와 이전 단일 계좌의 내역은 자동 합치지 않는다.


토스 PDF는 2MB·10,000행까지 미리보기하고, 저장은 200행씩 분리한다. 전체 행 검증 후 순서대로 저장하며, 중간 실패 시 같은 미리보기에서 재시도할 수 있다. 각 배치 영수증과 원장 고유번호로 중복을 방지하고, 완료한 배치는 건너뛴다. CSV 한도는 200행이다. 입고·출고와 세금 환급·원천징수는 매수로 바꾸지 않고 원문 유형과 원래 종목 코드를 보존한다.

계좌 소유자는 토스 PDF 기본 비밀번호(생년월일 6자리)를 암호화 저장하거나 삭제할 수 있다. `investmentAccounts/{accountId}/secrets/tossPdfPassword`는 서버에서만 접근하며, API 응답은 설정 여부만 반환한다. 임의 AES-256-GCM 데이터 키로 암호화하고 Firebase 서버 서비스 계정 RSA 키의 OAEP-SHA256으로 데이터 키를 감싼다. 계좌 ID를 인증 데이터와 OAEP label로 묶어 다른 계좌로 암호문을 옮겨 쓸 수 없다. 저장된 기본값은 PDF 입력란을 비울 때 서버에서만 복호화한다. 계좌 편집자는 허가된 PDF 등록에서 기본값을 사용할 수 있지만 변경·삭제는 소유자만 가능하다. 서버 RSA 키를 교체하면 이전 키로 감싼 기본값은 재등록해야 하며 원문 비밀번호·생년월일·PDF 원본을 원장이나 검토 세션, 로그에 저장하지 않는다. 위의 비밀번호 미보관 설명은 직접 입력 비밀번호를 뜻하며, 기본값은 이 명시적 동의 옵션에 한해 암호문으로 보관한다.
