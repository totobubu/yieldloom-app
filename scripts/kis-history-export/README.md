# 한국투자증권 해외주식 거래내역 — 로컬 수집기

목표: **계좌 최초 거래부터 현재까지 전체 이력, 미니스탁 포함**.
이 명령은 앱 원장·Firebase·R2에 연결하거나 기존 승인값을 수정하지 않습니다.
종료일 기본값은 실행일의 한국시간 날짜이며, 2025년으로 잘리지 않습니다.
계좌 최초 거래일과 API가 제공하는 과거 하한은 아직 미확인입니다.
2020년이나 그 밖의 임의 연도를 최초 거래일로 설정하지 않습니다.
빈 응답·최초 반환 거래·마지막 페이지 도달을 전체 이력 확보의 근거로 삼지 않습니다.

이 파일은 본인 PC에서 실행하는 조회 전용 프로그램입니다. 실제 인증·계좌 조회는
로컬 실행 단계이며 코드 검증에는 합성 응답만 사용했습니다. 별도 매매 프로그램이나
Toss 수집기와 폴더를 분리하여 사용하세요. Python 3.10 이상이 필요하며 추가 패키지는 없습니다.

## Windows에서 첫 실행

1. 별도 전달 브랜치의 `scripts/kis-history-export/` 폴더에서 실행합니다. 기존 작업 폴더와
   분리하는 Git 가져오기 방법은 [로컬 전달 안내](GIT_DELIVERY.md)를 참조하세요.
2. `run_windows.cmd`를 실행합니다.
3. 거래했던 일반 해외주식 계좌와 미니스탁 연결 계좌를 입력합니다.
   여러 계좌는 쉼표로 구분합니다. 계좌 형식은 `12345678-01`입니다.
4. 발급받은 **실전용** App Key와 App Secret을 PC 입력창에 입력합니다.
   입력 중 글자가 표시되지 않는 것이 정상입니다. 채팅으로 보내지 않습니다.
5. 시작 경계가 없는 기본 실행은 **2024년 12월, 2025년 5월, 실행일이 속한 현재 월**을 확인합니다.
   앞의 두 달은 확인용 표본 월일 뿐, 최초 거래월이 아닙니다.
   이것은 API 연결 및 거래 포함 범위를 확인하는 실행이며 전체 기간 수집이 아닙니다.
6. `results` 아래 생성된 폴더에서 `해외주식_거래내역.xlsx`의
   `거래내역`, `조회구간`, `표본대조`, `확인사항` 시트를 확인합니다.

동일 앱키가 입력한 모든 계좌에 대해 조회 가능한지는 실제 서비스 연결 상태에
따릅니다. 계좌/인증 오류가 나면 즉시 중지하며, 다른 키를 자동으로 찾지 않습니다.
일반 계좌와 미니스탁 계좌에 다른 키가 발급됐다면 각각 별도 실행해야 합니다.

프로그램이 키/토큰을 새로 저장하지 않습니다. 사용자 요청에 따라 본인 PC에 만든
`.env.kis-orders.local`을 읽을 수 있습니다. 아래 양식을 본인 PC에서만 채우며
실제 값은 Git 또는 채팅에 전달하지 않습니다. 설정 파일은 저장소에 포함하지 않습니다.
파일은 프로그램과 같은 폴더에 두거나 `--env-file "파일경로"`로 지정합니다.
지원 변수는 다음 네 개이며 이름을 그대로 사용합니다.

```dotenv
KIS_APP_KEY=
KIS_APP_SECRET=
KIS_CANO=
KIS_ACNT_PRDT_CD=
```

`KIS_CANO`는 계좌 앞 8자리, `KIS_ACNT_PRDT_CD`는 사용자가 확인한 뒤 2자리입니다.
상품코드는 자동으로 `01` 등으로 채우지 않습니다. 계좌 변수가 모두 비어 있으면
실행 때 계좌를 입력받으며 하나만 채워져 있으면 중지합니다.
UTF-8 및 UTF-8 BOM을 지원하고 실수로 `.txt`가 붙으면 알려줍니다.
한 줄에 하나씩 적고 값 뒤에 주석은 붙이지 않습니다. 따옴표로 감쌀 수 있습니다.
이 파일은 실행 코드가 아닌 단순한 값으로만 읽으며 `$()` 등을 실행하지 않습니다.
기존 OS 환경변수의 비어 있지 않은 값이 파일 값보다 우선합니다.
앱키/시크릿이 비어 있으면 화면에 표시되지 않는 입력으로 받습니다.

로그·파일·터미널에 인증 헤더를 출력하지 않습니다. 인증서 검증을 끄지 않습니다.
접근토큰은 한 번 실행하는 동안 메모리에서만 유지됩니다. 실행을 연속 반복하면
한국투자증권 토큰 발급 제한에 걸릴 수 있습니다.

## 전체 이력 목표와 명시적 기간 수집

기본 목표는 `--goal full-history`입니다. 계좌 개설일/최초 거래를 보여 주는 공식 증빙과
API의 최대 과거 제공 범위를 별도로 확인해야 합니다. API가 최초로 반환한 거래와
과거 빈 응답만으로 최초 거래일을 정하지 않습니다. 과거의 기록이 API 범위 밖이면
그 공백은 공식 거래내역서로 보완해야 합니다. 현재 시작 경계가 없는 `--full`은
실제 인증 전에 중지하며, 임의 연도로 대체하지 않습니다. `--start-basis`를 생략하거나
빈 값·공백·`미확인` 등으로 지정한 `--full`도 설정 파일 읽기와 인증 전에 중지합니다.
이 검사는 근거 설명의 존재를 확인할 뿐 증빙 내용의 진위를 자동 검증하지 않습니다.

근거가 확인된 요청 경계가 있을 때 `--start YYYY-MM-DD --start-basis "근거 설명"`
과 `--full`을 함께 사용합니다. 지정한 경계부터 한국시간 실행일까지 월 단위로
나누고 각 월의 마지막 응답까지 반복 조회합니다. 요청 시작 경계를 정했더라도
그 날짜가 실제 최초 거래일이라고 단정하지 않습니다. 10페이지에서 종료하지 않습니다.
기본 요청 간격은 0.6초이며, API 오류/인증 오류/호출 제한/네트워크 실패 시
나머지 요청도 중단합니다. 제한을 회피하려고 키나 계좌를 바꾸지 않습니다.

기본 조회 시장은 **NASD(미국)**입니다. 미국 외 거래도 있다면 시장별로 실행하세요.
시장 코드: NASD, NYSE, AMEX, SEHK, SHAA, SZAA, TKSE, HASE, VNSE.
시장별 결과는 중복될 수 있으므로 자동으로 병합하거나 거래를 삭제하지 않습니다.
공식 구형 CTOS4001R 예제는 NASD를 미국으로 설명하지만, 최신 상세 명세의
NYSE/AMEX 포함 범위는 미확인입니다. 나스닥 전용 또는 미국 전체 확보로 단정하지 않습니다.
국내주식은 이 도구의 대상이 아니며 미니스탁 과거 이력 포함 여부도 별도 검증해야 합니다.
API별 코드 의미와 최소 확인 경로는 [공식 범위 조사](API_SCOPE.md)를 참조하세요.

macOS/Linux 또는 터미널 실행:

```bash
python3 export_history.py
python3 export_history.py --full --start YYYY-MM-DD --start-basis "증권사 공식 증빙 또는 확인한 제공 하한"
python3 export_history.py --goal period --full --start YYYY-MM-DD --end YYYY-MM-DD --start-basis "확인한 요청 경계의 근거"
```

위의 `YYYY-MM-DD`는 확인한 실제 날짜로 바꿉니다. Windows 터미널에서는
`python3` 대신 `py -3`를 사용하거나 `run_full_windows.cmd --start 실제날짜 --start-basis "근거"`로 실행합니다.
미국 외 시장은 `--market SEHK` 등으로 지정합니다.
`--goal period`는 사용자가 명시한 기간만 수집하는 모드이며 전체 이력 확보를 뜻하지 않습니다.

## 중단 후 재개

`results` 아래 생성된 **기존 실행 폴더 전체**를 유지합니다.
인증값은 다시 PC에 입력하며 이전에 지정했던 계좌들을 그대로 입력합니다.
이미 응답이 종료된 월은 건너뛰고, 미완료 월은 저장한 연속조회 키로 이어받습니다.

```bash
python3 export_history.py --resume "results/기존실행폴더"
```

증권사에서 연속조회 키가 만료/무효라고 응답하면 같은 월을 첫 페이지부터
다시 받습니다. 이 경우에도 이전 원문과 중복/변경된 관측은 삭제하지 않습니다.

```bash
python3 export_history.py --resume "results/기존실행폴더" --restart-window
```

재개 시 기간·시장·전체/확인용 모드는 기존 `state.json` 값을 사용합니다.
종료일도 최초 실행 시점의 날짜로 고정하여 그 실행 계획을 재개합니다.
폴더를 두 터미널에서 동시에 재개하지 마세요. 수집 중 Ctrl+C로 중단하면
수신한 원문 및 부분 결과를 보존합니다. 전원이 꺼진 경우에도 성공적으로
저장된 `page_*.json`과 상태 파일을 사용해 재개할 수 있습니다.

## 파일과 누락 검증

- `page_*.json`: 매 응답의 원문 텍스트, 해석된 본문, 조회 범위, 페이지 번호.
  반복 조회도 새 파일로 보존합니다. 응답 원문에는 계좌 등 금융정보가 있을 수 있습니다.
- `state.json`: 조회 계획과 완료 상태, 재개용 커서. 앱키/시크릿/토큰은 없습니다.
- `records.json`: 거래 행과 원문 관측 연결 ID. 소수값을 반올림하지 않습니다.
- `해외주식_거래내역.xlsx`: 모든 셀을 텍스트로 저장하여 소수 수량과 긴 식별자의
  자릿수를 보존합니다. 합계를 계산하려면 필요한 열만 직접 숫자로 변환하세요.
- CSV: UTF-8 BOM을 포함합니다. CSV는 Excel이 숫자를 자동 변환할 수 있으므로
  정밀도 확인에는 JSON 또는 XLSX를 기준으로 사용하세요.
- `record_fingerprint`: 계좌별 동일 내용 관측 후보를 찾는 지문입니다.
  동일 내용인 별개 거래도 있을 수 있어 자동 중복 제거는 하지 않습니다.
- `observation_id`: 원문 파일명과 응답 내 행 위치입니다. 값이 달라진 반복 관측도
  각각 다른 행으로 남습니다.

`조회구간`의 **응답종료**는 그 요청의 응답이 끝났다는 뜻입니다.
**0건=실제 거래 없음**, **요청 성공=2020년 이후 전체 내역 확보**를 뜻하지 않습니다.
미실행/미완료 구간이 있으면 부분 수집이며 프로그램은 종료 코드 1을 반환합니다.
알 수 없는 응답 구조나 반복 커서도 빈 결과 또는 완료로 처리하지 않습니다.
`report.json`의 `coverage`에는 수집 목표, 요청 경계와 근거, 최초 반환 거래일,
실제 최초 거래일 검증 여부, 미니스탁 및 과거 지원 범위의 미확인 공백을 별도로 기록합니다.

본인 PC의 공식 거래내역에서 준비한 표본은 코드와 별도인
`private/reference_trades.csv`에 두거나 `--reference "표본파일경로"`로 지정합니다.
표본 CSV 열: `account,group,date,name,side,qty`.
계좌는 `****1234-01` 형태, 일자는 `YYYY-MM-DD`, side는 매도 `01`/매수 `02`입니다.
표본 대조는 매매일 또는 결제일, 수량, 매수/매도, 종목명을 확인합니다.
일자·수량만 일치하면 **후보**로 표시합니다. 종목 표기/날짜 기준 차이로
미발견될 수도 있으므로 이 결과만으로 증권사의 자료 누락을 확정하지 않습니다.
표본이 맞아도 수년치 전체 완전성을 증명하지는 못합니다.

API 수량·금액·수수료는 증권사 원장과 같은 통화·날짜 기준으로 대조해야 합니다.
월 경계에서는 매매일과 결제일이 달라질 수 있습니다. 이 도구는 배당·입출금·실제 환전·
타사출고를 대신 수집하지 않습니다. 미니스탁 표본이 없다면 관련 계좌/API 지원을
확인하고 HTS/공식 거래내역서로 보완해야 합니다.
